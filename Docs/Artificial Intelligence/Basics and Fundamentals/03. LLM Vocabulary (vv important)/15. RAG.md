## 1. Learn It (Core Understanding)
- **One-line definition:** RAG is a technique that combines LLM generation with external retrieval from a knowledge base to ground outputs in trusted data.
- **Plain-English explanation (3–4 lines):**  
  Instead of relying only on what the model learned during training, RAG retrieves relevant documents from a vector database or search engine and feeds them into the prompt. The LLM then generates answers based on both its internal knowledge and the retrieved context. This reduces hallucination and makes outputs more accurate and up-to-date.
- **Why it exists / problem it solves:**  
  - Addresses hallucination by grounding outputs in real data  
  - Allows use of private, domain-specific knowledge without retraining  
  - Keeps models current despite knowledge cutoff  
- **Key terms to know:**  
  - **Retriever:** Component that finds relevant documents (via embeddings/vector DB)  
  - **Generator:** The LLM that produces the final answer  
  - **Context injection:** Adding retrieved documents into the prompt  
  - **Knowledge base:** External source of truth (docs, intranet, APIs)  
- **How it works (simple steps):**  
  1. Convert query into embedding.  
  2. Retrieve similar documents from vector DB.  
  3. Inject retrieved context into the LLM prompt.  
  4. LLM generates grounded output.  
- **Where it sits in the AI stack:** Middleware layer between data storage and LLM inference.  
- **Related topics:** [[Embeddings]], [[Vector Databases]], [[LLM]], [[Hallucination]]

## 2. Mental Model
- **Analogy:** Imagine answering an exam question. Instead of relying only on memory, you quickly flip through your textbook to find the relevant section, then write your answer using both memory and the textbook. That’s RAG.  
- **Diagram / flow:**
    - User query → Embedding → Retriever (vector DB) → Relevant docs
Relevant docs + query → LLM → Grounded answer
- **The one thing to remember:** RAG = retrieval + generation → grounded, accurate outputs.  
- **Compare and contrast:**

| | LLM only | RAG |
|---|---|---|
| Knowledge source | Model weights (static) | Model + external documents |
| Accuracy | Risk of hallucination | More grounded, factual |
| Updateability | Fixed at training | Dynamic via updated knowledge base |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Scenario (reduce hallucination) / Compare vs fine-tuning  
- **Must-memorize facts:**  
  - [ ] RAG = retrieval + generation  
  - [ ] Uses embeddings + vector DB for document retrieval  
  - [ ] Reduces hallucination and extends knowledge beyond cutoff  
  - [ ] Cheaper and faster than fine-tuning for factual updates  
- **Keywords:** "RAG," "retrieval," "vector database," "grounding," "hallucination"  
- **Commonly confused with:**  
  - RAG vs fine-tuning (context injection vs weight change)  
  - RAG vs search engine (LLM generates, search retrieves only)  
- **Elimination tips:**  
  - Reject “RAG changes model weights.” It does not.  
  - Reject “RAG is only for training.” It’s used at inference.

## 5. Q&A Bank
- **Q:** What is RAG?  
  **A:** Retrieval-Augmented Generation — combining LLM generation with external document retrieval.  

- **Q:** How does RAG reduce hallucination?  
  **A:** By grounding outputs in retrieved, trusted documents.  

- **Q:** How does RAG differ from fine-tuning?  
  **A:** RAG injects external context at inference; fine-tuning changes model weights.  

- **Q:** What role do embeddings play in RAG?  
  **A:** They enable semantic search in vector databases to find relevant documents.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use RAG for factual grounding | Assume LLM alone is always accurate |
| Keep KB updated and curated | Inject outdated or low-quality docs |
| Combine with human review for critical tasks | Fully automate high-stakes decisions |
| Document retrieval sources | Ignore provenance of retrieved data |

- **Common mistakes:**  
  1. Thinking RAG = fine-tuning  
  2. Assuming RAG changes model weights  
  3. Ignoring KB quality and access controls
