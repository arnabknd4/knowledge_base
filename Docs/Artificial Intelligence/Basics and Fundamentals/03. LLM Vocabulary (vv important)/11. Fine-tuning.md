## 1. Learn It (Core Understanding)
- **One-line definition:** Fine-tuning is the process of adapting a pre-trained model to a specific task or domain by continuing training on smaller, targeted datasets.
- **Plain-English explanation (3–4 lines):**  
  After pre-training on massive general data, the model knows broad language patterns. Fine-tuning teaches it to perform specific tasks (like legal summarisation or customer support) by training further on curated examples. This makes the model more specialised and aligned with the intended use case.
- **Why it exists / problem it solves:**  
  - Adapts general models to domain-specific tasks  
  - Reduces cost compared to training from scratch  
  - Improves accuracy and relevance for specialised applications  
- **Key terms to know:**  
  - **Base model:** The pre-trained foundation model  
  - **Task-specific fine-tuning:** Training for classification, summarisation, translation, etc.  
  - **Instruction tuning:** Fine-tuning to follow human instructions better  
  - **Domain adaptation:** Specialising for legal, medical, or financial text  
  - **Parameter-efficient fine-tuning (PEFT):** Techniques like LoRA that adjust only part of the model  
- **How it works (simple steps):**  
  1. Start with a pre-trained foundation model.  
  2. Collect smaller, domain/task-specific dataset.  
  3. Continue training (adjust weights) on this dataset.  
  4. Validate performance on held-out examples.  
  5. Deploy specialised model.  
- **Where it sits in the AI stack:** Second stage after pre-training, before alignment (RLHF).  
- **Related topics:** [[Pre-training]], [[LLM]], [[RLHF]], [[Generative AI]]

## 2. Mental Model
- **Analogy:** Imagine a student who has read the entire library (pre-training). Fine-tuning is like giving them a short course in law or medicine so they can apply their general knowledge to a specialised field.  
- **Diagram / flow:**

    - Pre-trained model → Fine-tuning dataset → Adjusted weights → Specialised model

- **The one thing to remember:** Fine-tuning adapts a general foundation model to specific tasks or domains.  
- **Compare and contrast:**

| | Pre-training | Fine-tuning |
|---|---|---|
| Data | Massive, general-purpose | Smaller, domain/task-specific |
| Cost | Very high | Lower |
| Output | Foundation model | Specialised model |
| Purpose | Broad language ability | Task/domain adaptation |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Compare vs pre-training / Scenario (domain adaptation)  
- **Must-memorize facts:**  
  - [ ] Fine-tuning = adapting pre-trained model to specific tasks/domains  
  - [ ] Cheaper than training from scratch  
  - [ ] Instruction tuning improves following prompts  
  - [ ] PEFT methods (LoRA, adapters) reduce compute cost  
- **Keywords:** "fine-tuning," "domain adaptation," "instruction tuning," "LoRA," "PEFT"  
- **Commonly confused with:**  
  - Fine-tuning vs pre-training (foundation vs adaptation)  
  - Fine-tuning vs RAG (weight change vs context injection)  
- **Elimination tips:**  
  - Reject “fine-tuning builds the foundation model.” That’s pre-training.  
  - Reject “fine-tuning doesn’t change weights.” It does.

## 5. Q&A Bank
- **Q:** What is fine-tuning?  
  **A:** Adapting a pre-trained model to specific tasks or domains by continuing training on smaller datasets.  

- **Q:** How does fine-tuning differ from pre-training?  
  **A:** Pre-training builds a general foundation; fine-tuning adapts it to specialised tasks.  

- **Q:** What is instruction tuning?  
  **A:** Fine-tuning that teaches the model to follow human instructions better.  

- **Q:** What is PEFT?  
  **A:** Parameter-efficient fine-tuning methods (like LoRA) that adjust only part of the model to save compute.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use fine-tuning for domain adaptation | Confuse it with pre-training |
| Document datasets used for fine-tuning | Ignore data provenance or IP issues |
| Consider PEFT for efficiency | Assume full fine-tuning is always required |
| Validate outputs on domain tasks | Deploy without testing |

- **Common mistakes:**  
  1. Thinking fine-tuning = training from scratch  
  2. Confusing fine-tuning with RAG  
  3. Ignoring dataset quality and licensing
