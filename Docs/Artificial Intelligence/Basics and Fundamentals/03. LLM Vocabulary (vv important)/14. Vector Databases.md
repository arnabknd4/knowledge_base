## 1. Learn It (Core Understanding)
- **One-line definition:** A vector database stores and indexes embeddings (numeric vectors) to enable fast similarity search and retrieval.
- **Plain-English explanation (3–4 lines):**  
  When text, images, or other data are converted into embeddings, they become high-dimensional vectors. A vector database organises these vectors so you can quickly find items that are “close” in meaning. This is essential for semantic search, RAG (retrieval-augmented generation), and recommendation systems.
- **Why it exists / problem it solves:**  
  - Traditional databases handle exact matches; vector DBs handle similarity search  
  - Enables semantic search and context retrieval for LLMs  
  - Scales to millions or billions of embeddings efficiently  
- **Key terms to know:**  
  - **Embedding:** Numeric vector representation of data  
  - **Similarity search:** Finding vectors close to a query vector  
  - **Indexing algorithms:** FAISS, HNSW, Annoy, ScaNN  
  - **Distance metrics:** Cosine similarity, Euclidean distance  
  - **RAG:** Retrieval-Augmented Generation uses vector DBs to ground LLM outputs  
- **How it works (simple steps):**  
  1. Convert data (text, image, etc.) into embeddings.  
  2. Store embeddings in vector database.  
  3. Query converts input into embedding.  
  4. Database finds nearest neighbours (similar vectors).  
  5. Return results for search, recommendation, or grounding.  
- **Where it sits in the AI stack:** Infrastructure layer supporting semantic search and retrieval for LLMs.  
- **Related topics:** [[Embeddings]], [[RAG]], [[LLM]], [[Semantic Search]]

## 2. Mental Model
- **Analogy:** Imagine a giant map where every document is a dot. Similar documents are clustered together. A vector database is like GPS for this map: given a new query, it finds the nearest dots (most similar documents).  
- **Diagram / flow:**
    - Data → Embeddings → Vector DB → Similarity search → Results → LLM / Application
- **The one thing to remember:** Vector DBs make semantic search possible by storing and retrieving embeddings efficiently.  
- **Compare and contrast:**

| | Traditional DB | Vector DB |
|---|---|---|
| Query type | Exact match (SQL, keywords) | Similarity search (nearest neighbours) |
| Data type | Structured rows | High-dimensional vectors |
| Best for | Transactions, records | Semantic search, recommendations |

## 5. Q&A Bank
- **Q:** What is a vector database?  
  **A:** A database that stores embeddings and enables similarity search.  

- **Q:** Why are vector databases important for LLMs?  
  **A:** They enable RAG by retrieving semantically similar documents to ground outputs.  

- **Q:** Name two popular vector database libraries.  
  **A:** FAISS and Annoy.  

- **Q:** How do vector DBs measure similarity?  
  **A:** Using metrics like cosine similarity or Euclidean distance.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use vector DBs for semantic search | Confuse them with relational DBs |
| Document corpus and embedding method | Assume embeddings guarantee factual accuracy |
| Choose indexing algorithm for scale | Ignore performance trade-offs |
| Combine with RAG for grounding | Rely on raw LLM outputs alone |

- **Common mistakes:**  
  1. Thinking vector DBs store raw text instead of embeddings  
  2. Assuming similarity = factual correctness  
  3. Ignoring scalability and indexing method choice
