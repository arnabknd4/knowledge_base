## 1. Learn It (Core Understanding)
- **One-line definition:** Embeddings are numerical vector representations of tokens, words, or documents that capture their meaning and relationships in a continuous space.
- **Plain-English explanation (3–4 lines):**  
  An embedding turns text into numbers that preserve meaning. Words with similar meanings end up close together in this vector space. For example, “king” and “queen” are near each other, while “king” and “banana” are far apart. Models use embeddings to compare, search, and understand text beyond exact word matches.
- **Why it exists / problem it solves:**  
  - Converts discrete text into continuous numeric form for neural networks  
  - Captures semantic similarity (meaning, context)  
  - Enables tasks like search, clustering, and recommendation  
- **Key terms to know:**  
  - **Vector space:** Mathematical space where embeddings live  
  - **Dimensionality:** Number of values in each embedding vector (e.g., 512, 1024)  
  - **Semantic similarity:** Closeness of meaning measured by distance between vectors  
  - **Cosine similarity:** Common metric to compare embeddings  
- **How it works (simple steps):**  
  1. Tokenise text into words or subwords.  
  2. Map each token to a vector using learned weights.  
  3. Use embeddings in downstream tasks (search, clustering, classification).  
- **Where it sits in the AI stack:** Representation layer between raw text and neural network processing.  
- **Related topics:** [[LLM]], [[Transformer]], [[Token]], [[Context Window]], [[Semantic Search]]

## 2. Mental Model
- **Analogy:** Imagine a map of cities. Each city is a word, and their positions show how related they are. Paris and London are close (similar meaning: European capitals), while Paris and Banana are far apart.  
- **Diagram / flow:**
  - Text → Tokenisation → Embedding vectors → Neural network / search

- **The one thing to remember:** Embeddings = numbers that capture meaning; closeness = similarity.  
- **Compare and contrast:**

| | Embeddings | Raw tokens |
|---|---|---|
| Representation | Continuous vectors | Discrete IDs |
| Captures | Meaning, similarity | Exact identity |
| Use cases | Search, clustering, semantic tasks | Direct input/output |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Scenario (semantic search) / Compare embeddings vs raw tokens  
- **Must-memorize facts:**  
  - [ ] Embeddings = numeric vectors capturing meaning  
  - [ ] Similar meanings → vectors close together  
  - [ ] Cosine similarity measures closeness  
  - [ ] Used in search, clustering, recommendations  
- **Keywords:** "embedding," "vector," "semantic similarity," "cosine similarity"  
- **Commonly confused with:**  
  - Embeddings vs parameters (embeddings are outputs, parameters are learned weights)  
  - Embeddings vs context window (context = input length, embeddings = representation)  
- **Elimination tips:**  
  - Reject “embeddings are raw text.” They are numeric vectors.  
  - Reject “embeddings guarantee factual accuracy.” They capture similarity, not truth.

## 5. Q&A Bank
- **Q:** What are embeddings?  
  **A:** Numeric vectors that represent tokens or documents, capturing meaning and similarity.  

- **Q:** Why are embeddings useful?  
  **A:** They allow semantic similarity comparisons, enabling search, clustering, and recommendations.  

- **Q:** How do we measure similarity between embeddings?  
  **A:** Using metrics like cosine similarity.  

- **Q:** Do embeddings guarantee factual accuracy?  
  **A:** No, they capture patterns of meaning, not truth.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use embeddings for semantic tasks | Confuse them with raw tokens |
| Compare embeddings with cosine similarity | Assume closeness = factual correctness |
| Document embedding dimensionality | Ignore training data bias |
| Apply embeddings across languages | Assume perfect translation equivalence |

- **Common mistakes:**  
  1. Thinking embeddings = parameters  
  2. Assuming embeddings guarantee truth  
  3. Ignoring dimensionality and training data quality
