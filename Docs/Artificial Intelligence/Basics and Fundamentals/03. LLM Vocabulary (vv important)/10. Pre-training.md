## 1. Learn It (Core Understanding)
- **One-line definition:** Pre-training is the initial large-scale training of a model on massive, general-purpose datasets to learn language patterns, grammar, facts, and reasoning-like behaviours.
- **Plain-English explanation (3–4 lines):**  
  Before fine-tuning or alignment, LLMs are trained on huge text corpora using self-supervised learning. The model plays the “next-token prediction” game billions of times, absorbing statistical patterns of language. This stage gives the model broad general knowledge and capabilities, which later can be adapted to specific tasks.
- **Why it exists / problem it solves:**  
  - Provides a strong foundation without task-specific labels  
  - Enables transfer learning: one model can be adapted to many tasks  
  - Makes large-scale language understanding possible  
- **Key terms to know:**  
  - **Self-supervised learning:** Training without manual labels, using context prediction  
  - **Next-token prediction:** Core objective of pre-training  
  - **Corpus:** Large dataset of text/code used for training  
  - **Foundation model:** Base model created by pre-training, adaptable to many tasks  
- **How it works (simple steps):**  
  1. Collect massive text corpus (books, articles, code, web data).  
  2. Tokenise text into chunks.  
  3. Train transformer to predict next token.  
  4. Adjust weights via backpropagation and gradient descent.  
  5. Repeat billions of times until model converges.  
- **Where it sits in the AI stack:** First stage of building LLMs and generative models.  
- **Related topics:** [[LLM]], [[Transformer]], [[Fine-tuning]], [[RLHF]], [[Generative AI]]

## 2. Mental Model
- **Analogy:** Like teaching a child language by letting them read an entire library. They don’t learn specific tasks (like answering exam questions) yet, but they absorb grammar, vocabulary, and general knowledge. Later, you can coach them for specific tasks.  
- **Diagram / flow:**

  - Huge corpus → Tokenisation → Next-token prediction → Learned weights

- **The one thing to remember:** Pre-training = broad foundation; fine-tuning = task-specific adaptation.  
- **Compare and contrast:**

| | Pre-training | Fine-tuning |
|---|---|---|
| Data | Massive, general-purpose | Smaller, task/domain-specific |
| Objective | Next-token prediction | Instruction-following or specialised task |
| Output | Foundation model | Adapted model |
| Cost | Very high (compute, energy) | Lower (on top of pre-trained model) |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Compare pre-training vs fine-tuning / Scenario (knowledge cutoff)  
- **Must-memorize facts:**  
  - [ ] Pre-training = massive dataset, next-token prediction  
  - [ ] Produces foundation models adaptable to many tasks  
  - [ ] Knowledge cutoff = last date of training data  
  - [ ] Fine-tuning and RLHF follow pre-training  
- **Keywords:** "pre-training," "foundation model," "next-token prediction," "knowledge cutoff"  
- **Commonly confused with:**  
  - Pre-training vs fine-tuning  
  - Pre-training vs inference (training vs use)  
- **Elimination tips:**  
  - Reject “pre-training uses labelled datasets.” It is self-supervised.  
  - Reject “pre-training happens after fine-tuning.” It comes first.

## 5. Q&A Bank
- **Q:** What is pre-training in LLMs?  
  **A:** The initial large-scale training on massive text corpora using next-token prediction.  

- **Q:** How does pre-training differ from fine-tuning?  
  **A:** Pre-training builds a general foundation; fine-tuning adapts it to specific tasks.  

- **Q:** What is the knowledge cutoff?  
  **A:** The last date of data included in pre-training.  

- **Q:** Why is pre-training expensive?  
  **A:** It requires huge datasets, compute, and energy.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Understand pre-training as the foundation stage | Confuse it with fine-tuning |
| Note knowledge cutoff limitations | Assume model knows current events |
| Recognise self-supervised nature | Assume labelled datasets are required |
| Document corpus sources and risks | Ignore IP, bias, or data provenance |

- **Common mistakes:**  
  1. Thinking pre-training = supervised learning  
  2. Assuming pre-training gives live knowledge access  
  3. Ignoring knowledge cutoff in enterprise use
