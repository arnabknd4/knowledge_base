## 1. Learn It (Core Understanding)
- **One-line definition:** Hallucination is when a generative AI produces fluent but false, misleading, or invented output.
- **Plain-English explanation (3–4 lines):**  
  LLMs generate text by predicting the next token based on patterns, not by verifying facts. Sometimes they produce answers that sound confident but are factually wrong, fabricated, or irrelevant. This is called hallucination. It’s a core risk in using generative AI for factual or high-stakes tasks.
- **Why it exists / problem it solves:**  
  - Models are trained to always produce plausible text, even when unsure  
  - No built-in fact-checking or external grounding  
  - Limited context window and outdated training data  
- **Key terms to know:**  
  - **Confabulation:** Another term for hallucination  
  - **Grounding:** Supplying trusted documents to reduce hallucination  
  - **Prompt injection:** Malicious input that can cause hallucination or unsafe output  
  - **Knowledge cutoff:** Training data limit that increases hallucination risk  
- **How it works (simple steps):**  
  1. Model predicts next token from probabilities.  
  2. If relevant knowledge is missing, it still generates plausible text.  
  3. Output may be fluent but factually wrong.  
- **Where it sits in the AI stack:** Inference-time risk in generative models.

## 2. Mental Model
- **Analogy:** Like a student asked a tough question who doesn’t want to admit “I don’t know.” Instead, they confidently invent an answer that sounds right but is wrong.  
- **Diagram / flow:**

Prompt → Model predicts next token → Fluent output
│
└── May be factually wrong (hallucination)
- **The one thing to remember:** Hallucination = fluent but false output.  
- **Compare and contrast:**

| | Hallucination | Error (classical ML) |
|---|---|---|
| Nature | Invented, fabricated output | Wrong classification or prediction |
| Confidence | Often high, fluent | Varies |
| Cause | Lack of grounding, probabilistic sampling | Model misfit or poor features |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Scenario (wrong but fluent output) / Mitigation strategies  
- **Must-memorize facts:**  
  - [ ] Hallucination = fluent but false output  
  - [ ] Caused by probabilistic prediction, lack of grounding, limited context, outdated data  
  - [ ] Mitigations: RAG, human review, guardrails, evaluation, monitoring  
  - [ ] Bigger models reduce but do not eliminate hallucination  
- **Keywords:** "hallucination," "confabulation," "false but fluent," "grounding"  
- **Commonly confused with:**  
  - Hallucination vs bias (bias = skewed patterns; hallucination = false content)  
  - Hallucination vs creativity (creativity can be useful; hallucination is misleading)  
- **Elimination tips:**  
  - Reject “LLMs always give factual answers.”  
  - Reject “Hallucination means the model is broken.” It’s inherent to probabilistic generation.

## 5. Q&A Bank
- **Q:** What is hallucination in LLMs?  
  **A:** Fluent but false or invented output.  

- **Q:** Why do LLMs hallucinate?  
  **A:** They predict plausible continuations, not verified facts.  

- **Q:** How can hallucination be reduced?  
  **A:** Use RAG (grounding), human review, guardrails, evaluation, monitoring.  

- **Q:** Does a bigger model eliminate hallucination?  
  **A:** No, it reduces but does not eliminate it.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Ground outputs in trusted data | Assume fluent text = factual |
| Keep human review for critical tasks | Fully automate high-stakes decisions |
| Monitor outputs continuously | Ignore hallucination risk |
| Document hallucination mitigation | Treat hallucination as rare or negligible |

- **Common mistakes:**  
  1. Believing hallucination = creativity  
  2. Assuming bigger models solve hallucination  
  3. Ignoring hallucination in enterprise use cases
