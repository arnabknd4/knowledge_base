## 1. Learn It (Core Understanding)
- **One-line definition:** Generative AI is a class of deep learning models that learn the patterns in their training data and use them to create new content (text, images, code, audio, video) rather than only classifying or predicting.
- **Plain-English explanation (3-4 lines):**
  Traditional (discriminative) AI answers "what is this?" or "what will happen?" (spam or not spam, will this customer churn). Generative AI answers "what could come next or what could this look like?" and produces something new. It does this by learning the statistical structure of huge datasets, then sampling from that learned structure in response to a prompt. The output is plausible and new, but it is generated from probabilities, not looked up from a database of facts.
- **Why it exists / problem it solves:**
  - Automates content creation and knowledge work (drafting, summarising, coding, design)
  - Lets people interact with computers in natural language
  - One general model (a foundation model) can be adapted to many tasks, instead of building a separate model for each task
- **Key terms to know:**
  - **Discriminative model:** Predicts a label or value from input (classification, regression)
  - **Generative model:** Produces new data similar to its training data
  - **Foundation model:** Large model pre-trained on broad data, adaptable to many downstream tasks
  - **LLM:** Foundation model for text (and often code); predicts the next token
  - **Diffusion model:** Generates images/video/audio by learning to remove noise step by step
  - **GAN:** Older generative approach where a generator and a discriminator compete
  - **Transformer:** The architecture behind modern LLMs and many multimodal models
  - **Prompt:** The input instruction that steers the output
  - **Multimodal:** Handles more than one data type (text, image, audio, video)
  - **Hallucination:** Fluent but false or fabricated output
  - **Synthetic data:** Artificially generated data (can be produced by GenAI)
- **How it works (simple steps):**
  1. **Pre-train:** Train a large model on massive datasets to learn patterns (e.g., predict the next token in text).
  2. **Adapt:** Fine-tune and/or align it (instruction tuning, RLHF) so it follows instructions and behaves safely.
  3. **Prompt:** A user or application gives an input (prompt, plus optional context or documents).
  4. **Generate (inference):** The model produces output step by step, sampling from probabilities (temperature controls randomness).
  5. **Post-process and govern:** Apply filters, guardrails, human review, and monitoring before the output is used.
- **Where it sits in the AI stack:** Model layer. It is an application area inside deep learning, and it is the foundation for LLM apps, RAG, and agents.

## 2. Mental Model
- **Analogy:** A discriminative model is like a **food critic** who tastes a dish and labels it ("Italian, 4 stars"). A generative model is like a **chef who has studied thousands of recipes** and can now invent a new dish in that style. The chef's dish looks and tastes right, but the chef is working from learned patterns, not from a recipe book that guarantees the dish is correct or safe.
- **Diagram / flow:**
```
  Massive training data
          │
          ▼
  [ Pre-training ] → Foundation model
          │
          ▼
  [ Fine-tuning / Alignment (RLHF) ]
          │
          ▼
  Prompt (+ context) ──► [ Model inference ] ──► New content
                                │                     │
                         Guardrails / filters     Human review
```
- **The one thing to remember:** GenAI creates *plausible* new content from learned patterns. Plausible does not mean true, so it needs verification and governance.
- **Compare and contrast:**

  | | Generative AI | Traditional (Discriminative) AI/ML |
  |---|---|---|
  | Purpose | Create new content | Classify, predict, or detect |
  | Output | Open-ended (text, image, code) | Fixed (label, score, number) |
  | Scope | General-purpose, adaptable | Usually built for one task |
  | Data needed | Massive, broad datasets | Task-specific datasets |
  | Evaluation | Harder (quality is subjective, no single right answer) | Easier (accuracy, precision, recall) |
  | Typical failure | Hallucination, toxic or biased output, leakage | Misclassification, bias, drift |
  | Examples | Claude, ChatGPT, Midjourney, Copilot | Fraud detection, churn prediction, image classifier |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Compare / Scenario / Best-fit / Pick-the-risk
- **Must-memorize facts:**
  - [ ] GenAI = models that create new content; it is a subset of deep learning
  - [ ] Generative vs discriminative (create vs classify/predict)
  - [ ] Foundation model = broad pre-training, adaptable to many tasks
  - [ ] Main model families: Transformers/LLMs (text), Diffusion (images), GANs, VAEs
  - [ ] Output is probabilistic and can be non-deterministic
  - [ ] Key risks: hallucination, bias, data leakage and privacy, IP/copyright, misuse (deepfakes, phishing), prompt injection, over-reliance
  - [ ] Typical mitigations: human-in-the-loop, RAG (grounding), guardrails and filters, red teaming, access controls, usage policies, output labelling
  - [ ] Benefits: productivity, speed, personalisation, accessibility, innovation
  - [ ] Limitations: no true understanding, knowledge cutoff, can be confidently wrong, sensitive to prompt wording, costly to train and run
- **Keywords that signal this topic in a question:** "generates new content," "foundation model," "LLM," "diffusion," "creates text/images/code," "prompt," "synthetic"
- **Commonly confused with:**
  - GenAI vs LLM (LLMs are one type of GenAI; GenAI also covers images, audio, video)
  - GenAI vs traditional ML (create vs predict)
  - Generative vs discriminative models
  - Plausible output vs accurate output
  - RAG vs fine-tuning (grounding with external data at query time vs changing the model's weights)
- **Elimination tips (how to rule out wrong options):**
  - Reject "GenAI outputs are always factual" and "GenAI understands like humans."
  - Reject "GenAI is only about text." It is multimodal.
  - Reject "GenAI retrieves stored answers." It generates from learned patterns.
  - For "reduce hallucination" questions, prefer grounding (RAG), human review, and evaluation over "use a bigger model" or "raise temperature."
  - For "sensitive data" scenarios, prefer data controls, redaction, and approved enterprise tools over "ban everything" or "trust the vendor blindly."
- **Frameworks / standards link:**
  - **NIST AI RMF:** Has a dedicated **Generative AI Profile (NIST AI 600-1)** listing GenAI-specific risks (confabulation, information integrity, data privacy, IP, harmful content, and others) mapped to the Govern / Map / Measure / Manage functions.
  - **EU AI Act:** Introduces obligations for **general-purpose AI (GPAI) models** (documentation, copyright policy, training-data summary, extra duties for systemic-risk models) and **transparency duties** for AI-generated content (e.g., disclose AI interaction, label synthetic media/deepfakes). Check the current application dates, as timelines are phased.
  - **ISO/IEC 42001:** AI management system that covers GenAI use through risk assessment, impact assessment, data governance, and lifecycle controls.
  - **Governance angle:** GenAI raises the need for acceptable-use policy, output review, vendor/third-party risk management, and content provenance.

## 4. 🛠️ Real-World Use Cases
| # | Scenario | Industry | How this topic applies | Outcome / risk |
|---|---|---|---|---|
| 1 | Drafting emails, reports, and summaries | Cross-industry | LLM generates and condenses text | Time saved; hallucinated facts, confidential data pasted into prompts |
| 2 | Code assistance and review | Software / IT | Model suggests, explains, and tests code | Faster delivery; insecure or incorrect code, licence concerns |
| 3 | Customer support chatbot grounded in company knowledge | Retail / Banking / Telecom | LLM + RAG answers from approved documents | Lower cost, 24/7 service; wrong answers, prompt injection, brand risk |
| 4 | Marketing copy and image creation | Media / Marketing | Text and diffusion models create assets | Faster campaigns; copyright/IP questions, bias, deepfake misuse |
| 5 | Document analysis (contracts, policies, audit evidence) | Legal / Consulting / Audit | Model extracts and summarises key clauses or findings | Efficiency; missed or invented details, need for human verification |

- **Consulting / assurance lens:**
  - A client asks, "Where are we using GenAI, and is it governed?"
  - An auditor asks, "Who approved this use case, what data goes in, who reviews the output, and how do you know it works?"
  - Shadow AI (staff using unapproved tools) is a common finding.
- **Evidence or controls you would look for:**
  - GenAI acceptable-use policy and approved-tools list
  - Inventory of GenAI use cases with risk ratings
  - Data classification rules for prompts (what must never be entered)
  - Human-in-the-loop checkpoints for high-impact outputs
  - Evaluation and testing results (accuracy, bias, safety), including red-team reports
  - Vendor due diligence (data retention, training on customer data, security)
  - Logging and monitoring of inputs/outputs; incident process
  - Labelling or disclosure of AI-generated content where required

## 5. Q&A Bank

### Quick recall
- **Q:** What is Generative AI?
  **A:** AI that creates new content (text, images, code, audio, video) by learning patterns from training data.

- **Q:** How is GenAI different from traditional ML?
  **A:** Traditional ML classifies or predicts from input. GenAI generates new, open-ended content.

- **Q:** Name three types of generative models.
  **A:** Transformer-based LLMs, diffusion models, and GANs (also VAEs).

### Conceptual
- **Q:** What is a foundation model, and why does it matter?
  **A:** A large model pre-trained on broad data that can be adapted to many tasks (via prompting, RAG, or fine-tuning). It matters because one model can serve many use cases, but it also concentrates risk: flaws in the base model pass to everything built on it.

- **Q:** Why do GenAI models hallucinate?
  **A:** They generate the most statistically plausible continuation, not verified facts. They have no built-in fact-checking and may lack the relevant knowledge, so they can produce fluent but wrong answers.

- **Q:** Why is evaluating GenAI harder than evaluating a classifier?
  **A:** Outputs are open-ended, with no single correct answer, and quality is partly subjective. It needs a mix of benchmarks, human review, task-specific tests, and red teaming.

### Scenario-based
- **Q:** Employees are pasting confidential client documents into a public chatbot. What should the organisation do?
  **A:** Put an acceptable-use policy in place, define data classification rules for prompts, provide an approved enterprise tool with appropriate data protections, train staff, and monitor for shadow AI. Blocking alone without an alternative usually pushes the behaviour underground.

- **Q:** A customer-facing chatbot is giving incorrect policy information. What is the best fix?
  **A:** Ground it in approved documents (RAG), add guardrails and fallback to a human, test it against known questions, and monitor it. Do not just make the model bigger or increase randomness.

- **Q:** A marketing team wants to publish AI-generated images and text. Key considerations?
  **A:** Copyright/IP and licensing terms, bias and brand safety review, disclosure or labelling of AI-generated content where required, human approval before publishing, and vendor terms on training data.

### Interview-style
- **Q:** "Explain Generative AI to a non-technical executive."
  **A:** "Most AI we've used so far looks at data and gives a label or prediction, like 'this transaction looks fraudulent.' Generative AI creates something new, like a draft report, an image, or working code, based on patterns it learned from enormous amounts of data. It's a big productivity opportunity, but it can sound confident while being wrong, so it needs clear policies, human review, and controls around the data we feed it."

## 6. ✅ Dos and ❌ Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Verify important outputs before acting on them | Trust outputs as factual because they sound confident |
| Define an acceptable-use policy and approved tools | Let shadow AI grow unchecked |
| Ground answers in trusted data (RAG) for factual use cases | Expect the base model to know your company's facts |
| Keep a human in the loop for high-impact decisions | Fully automate decisions affecting people, money, or safety |
| Classify data and restrict sensitive inputs | Paste confidential, personal, or regulated data into unapproved tools |
| Test, red-team, and monitor continuously | Treat a one-time test as proof the system is safe |
| Label or disclose AI-generated content where required | Pass off synthetic content as human-made or authentic |
| Review vendor terms (data use, retention, IP) | Assume vendor defaults protect your data and IP |

- **Common mistakes / misconceptions:**
  1. "GenAI understands like a human." (It predicts patterns; it does not reason or know the way people do.)
  2. "GenAI = ChatGPT = LLM." (GenAI is broader: images, audio, video, code.)
  3. "GenAI looks up answers in a database." (It generates from learned patterns.)
  4. "Bigger model means no hallucination." (Reduces but does not remove it.)
  5. "If it is approved once, it is safe forever." (Models, prompts, and data change, so keep monitoring.)
- **Red flags in practice:**
  - No inventory of where GenAI is used
  - Sensitive data going into public tools
  - No human review on customer-facing or decision-support outputs
  - No testing evidence or monitoring
  - Unclear vendor data-use terms
  - No plan for incidents (harmful output, data leak)

## 7. Revision Snapshot
- **30-second summary:**
  Generative AI is deep learning that creates new content from patterns learned on massive data. It is built on foundation models (LLMs for text, diffusion for images) that are pre-trained, then adapted and aligned. Its outputs are plausible, not guaranteed true, so the core risks are hallucination, bias, data leakage, IP issues, and misuse. Governance relies on policy, grounding (RAG), human-in-the-loop, testing and red teaming, vendor controls, and monitoring, mapped to NIST AI RMF (incl. GenAI Profile), EU AI Act, and ISO 42001.
- **3 bullets to recall on exam day:**
  1. GenAI creates; traditional AI classifies or predicts
  2. Plausible is not true: hallucination is the signature risk
  3. Controls: policy + grounding + human review + testing + monitoring
