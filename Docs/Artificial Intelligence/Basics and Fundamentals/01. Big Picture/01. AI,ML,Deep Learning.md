## 1. Learn It (Core Understanding)
- **One-line definition:** AI is the broad goal of machines performing tasks that need human-like intelligence; ML is the subset of AI that learns patterns from data; Deep Learning is the subset of ML that uses multi-layer neural networks.
- **Plain-English explanation (3-4 lines):**
  AI is the umbrella idea. Some AI is just hand-written rules ("if X then Y"). ML replaces the hand-written rules with a model that learns the rules from examples. Deep Learning is a powerful kind of ML that stacks many layers of artificial neurons, so it can learn very complex patterns such as language, images, and speech.
- **Why it exists / problem it solves:**
  - Rule-based systems break down when the rules are too many or too fuzzy to write by hand (spam detection, image recognition, language).
  - ML lets the system learn the rules from data.
  - Deep Learning removed the need to hand-design input features for unstructured data (text, images, audio).
- **Key terms to know:**
  - **AI:** Any technique that lets machines mimic intelligent behaviour (rules, search, ML, etc.)
  - **Rule-based / expert system:** AI that follows human-written logic; does not learn from data
  - **Machine Learning (ML):** Algorithms that improve at a task by learning from data
  - **Deep Learning (DL):** ML using neural networks with many layers
  - **Neural network:** Layered network of simple units (neurons) with adjustable weights
  - **Feature engineering:** Manually choosing the inputs a model learns from (common in classical ML, largely automated in DL)
  - **Generative AI:** DL-based models that create new content (sits inside DL)
- **How it works (simple steps):**
  1. **AI (rules):** A human writes explicit logic, and the system executes it.
  2. **ML:** A human provides data and picks an algorithm, and the model learns patterns during training.
  3. **DL:** A human provides large amounts of data, and a deep neural network learns both the features and the patterns itself.
- **Where it sits in the AI stack:** Foundation layer of the stack. Every later topic (LLMs, agents, RAG) lives inside the DL/GenAI ring of this picture.

## 2. Mental Model
- **Analogy:** Think of transport. **AI** is "all vehicles." **ML** is "motor vehicles" (they power themselves by learning from data rather than being pushed by hand-coded rules). **Deep Learning** is "high-performance cars": very capable, but they need lots of fuel (data and compute) and are harder to look under the hood of.
- **Diagram / flow (nested circles):**
```
  ┌─────────────────────────────────────────────┐
  │ Artificial Intelligence (broad goal)        │
  │  ┌───────────────────────────────────────┐  │
  │  │ Machine Learning (learns from data)   │  │
  │  │  ┌─────────────────────────────────┐  │  │
  │  │  │ Deep Learning (deep neural nets)│  │  │
  │  │  │  ┌───────────────────────────┐  │  │  │
  │  │  │  │ Generative AI / LLMs      │  │  │  │
  │  │  │  └───────────────────────────┘  │  │  │
  │  │  └─────────────────────────────────┘  │  │
  │  └───────────────────────────────────────┘  │
  │  (Rule-based systems live here, outside ML) │
  └─────────────────────────────────────────────┘
```
- **The one thing to remember:** AI ⊃ ML ⊃ DL. Every DL system is ML, and every ML system is AI, but not the other way around.
- **Compare and contrast:**

  | | AI | Machine Learning | Deep Learning |
  |---|---|---|---|
  | Scope | Broadest field | Subset of AI | Subset of ML |
  | How it gets its "rules" | Human-written or learned | Learned from data | Learned from data, including the features |
  | Data needed | Can be none | Moderate | Very large |
  | Compute needed | Low to high | Low to moderate | High (GPUs/TPUs) |
  | Feature engineering | N/A | Usually manual | Mostly automatic |
  | Explainability | Often high (rules are readable) | Moderate (varies by model) | Low (black-box tendency) |
  | Best for | Well-defined logic | Structured/tabular data | Text, images, audio, video |
  | Examples | Chess rules engine, expert system | Credit scoring, fraud detection, churn prediction | Image recognition, speech-to-text, ChatGPT/Claude |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Compare / Scenario / Best-fit
- **Must-memorize facts:**
  - [ ] AI ⊃ ML ⊃ DL (nested, not parallel)
  - [ ] Not all AI is ML (rule-based systems are AI without learning)
  - [ ] DL = ML with neural networks that have many layers ("deep" = number of layers)
  - [ ] DL learns features automatically; classical ML usually needs manual feature engineering
  - [ ] DL needs more data and compute, and is less explainable
  - [ ] Generative AI and LLMs are built on deep learning
  - [ ] Classical ML examples: linear/logistic regression, decision trees, random forests, SVM, k-means, gradient boosting
  - [ ] DL examples: CNNs (images), RNNs (sequences), Transformers (language)
- **Keywords that signal this topic in a question:** "subset of," "learns from data," "without explicit programming," "neural network," "layers," "feature extraction," "rule-based"
- **Commonly confused with:**
  - AI vs ML (people use them as synonyms; they are not)
  - ML vs DL (DL is a *type* of ML, not a replacement for it)
  - Generative AI vs DL (GenAI is an application area *within* DL)
  - Automation vs AI (fixed scripts are automation, not necessarily AI)
- **Elimination tips (how to rule out wrong options):**
  - Reject any option that says ML is a superset of AI, or DL is separate from ML.
  - Reject "DL is always better." Classical ML often wins on small or tabular datasets.
  - Reject "ML requires explicit rules programmed by humans" (that describes traditional programming or rule-based AI).
  - If the scenario has unstructured data (images, text, audio) plus lots of data, lean DL. If it has structured/tabular data and a small dataset, lean classical ML. If the logic is simple and fixed, a rule-based system is enough.
- **Frameworks / standards link:**
  - **EU AI Act:** Defines an "AI system" around the ability to *infer* outputs from inputs, which covers ML/DL systems. Simple software built only on human-defined rules is intended to be out of scope.
  - **NIST AI RMF:** Uses an OECD-aligned definition of an AI system. It applies across AI generally, but risks such as opacity and bias are most pronounced in ML/DL.
  - **ISO/IEC 42001:** Management system standard that applies to organisations developing or using AI systems, regardless of technique.
  - **Governance angle:** The deeper the model (DL), the harder explainability and audit become, so the control burden rises.

## 4. 🛠️ Real-World Use Cases
| # | Scenario | Industry | How this topic applies | Outcome / risk |
|---|---|---|---|---|
| 1 | Loan approval using fixed eligibility rules | Banking | **AI (rule-based):** transparent, no learning | Easy to audit; cannot adapt to new patterns |
| 2 | Credit risk scoring from tabular customer data | Banking / Insurance | **Classical ML** (e.g., gradient boosting) | Good accuracy, explainable with tools; bias risk from historical data |
| 3 | Medical image analysis (X-rays, scans) | Healthcare | **Deep Learning** (CNNs) | High accuracy; needs large labelled data; explainability and safety concerns |
| 4 | Chat assistant, summarisation, code help | Cross-industry | **DL / Generative AI** (LLMs) | High productivity; hallucination, privacy, and IP risks |

- **Consulting / assurance lens:**
  - A client says "we use AI." The first question is *which kind*: rules, classical ML, or deep learning?
  - The answer drives the risk tier, the validation approach, and the documentation needed.
- **Evidence or controls you would look for:**
  - AI/model inventory that records the technique used
  - Model documentation (purpose, data sources, training approach)
  - Explainability approach matched to model type
  - Validation and monitoring evidence (performance, bias, drift)
  - Justification for choosing a complex model over a simpler one

## 5. Q&A Bank

### Quick recall
- **Q:** What is the relationship between AI, ML, and DL?
  **A:** AI is the broadest field, ML is a subset of AI that learns from data, and DL is a subset of ML that uses deep neural networks.

- **Q:** Is all AI machine learning?
  **A:** No. Rule-based and expert systems are AI but do not learn from data.

- **Q:** What does "deep" mean in Deep Learning?
  **A:** The neural network has many layers between input and output.

### Conceptual
- **Q:** How does Deep Learning differ from classical ML?
  **A:** DL learns features automatically from raw data, needs far more data and compute, and is generally less explainable. Classical ML usually relies on manually engineered features and works well on smaller, structured datasets.

- **Q:** Why is DL dominant for language, image, and audio tasks?
  **A:** These are unstructured data types where hand-crafting features is impractical. Deep networks learn hierarchical features directly from the raw data.

- **Q:** Where does Generative AI fit?
  **A:** It is a category of deep learning models (such as transformers and diffusion models) that generate new content. It sits inside DL, which sits inside ML, which sits inside AI.

### Scenario-based
- **Q:** A bank has 20,000 rows of structured customer data and must explain every loan decision to regulators. Which approach fits best?
  **A:** Classical ML (for example, logistic regression or a tree-based model) with explainability tooling, or even a rule-based system. The dataset is small and structured, and explainability is a hard requirement, so deep learning is a poor fit.

- **Q:** A company wants to classify millions of product photos automatically. Which approach fits best?
  **A:** Deep Learning (a CNN or vision model). Images are unstructured data, and the dataset is large.

- **Q:** A vendor claims their "AI" product is just a set of if-then rules. Is it AI?
  **A:** Technically it is rule-based AI, but it is not machine learning. For governance, it carries different risks (for example, rigidity rather than opaque learned behaviour).

### Interview-style
- **Q:** "Explain AI vs ML vs Deep Learning to a non-technical executive."
  **A:** "AI is the big goal: making machines do smart things. Machine learning is one way to get there: instead of programming every rule, we show the machine lots of examples and it learns the pattern. Deep learning is the most powerful form of machine learning, the technology behind tools like ChatGPT and face recognition. It is very capable but needs lots of data and is harder to explain, which is why governance matters more as systems get more advanced."

## 6. ✅ Dos and ❌ Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Use the nested model: AI ⊃ ML ⊃ DL | Use AI, ML, and DL as interchangeable terms |
| Ask "which technique?" when assessing any AI system | Assume every "AI" system learns from data |
| Match the method to the data type and size (tabular → classical ML; unstructured → DL) | Assume deep learning is always the best choice |
| Consider explainability needs before choosing a model | Ignore that DL is harder to audit and explain |
| Record the technique in the AI/model inventory | Treat all AI systems as carrying the same risk |

- **Common mistakes / misconceptions:**
  1. "ML and AI are the same thing." (ML is a subset of AI.)
  2. "Deep Learning is separate from ML." (DL is a type of ML.)
  3. "More complex models are always more accurate." (Not on small or tabular data.)
  4. "Generative AI is a different field from DL." (It is built on DL.)
- **Red flags in practice:**
  - Vendor says "AI-powered" but cannot say what technique is used
  - Complex DL model used for a simple, high-stakes, explainability-critical decision
  - No documentation of why a model type was chosen

## 7. Revision Snapshot
- **30-second summary:**
  AI is the umbrella goal of intelligent machines. ML is AI that learns from data instead of hand-written rules. DL is ML with deep neural networks that learn features automatically and power modern language, vision, and audio systems. GenAI and LLMs live inside DL. As you go from rules to ML to DL, capability and data/compute needs rise, while explainability falls.
- **3 bullets to recall on exam day:**
  1. AI ⊃ ML ⊃ DL ⊃ GenAI (nested circles)
  2. Not all AI is ML (rule-based systems exist)
  3. DL = automatic features + big data + big compute + low explainability
