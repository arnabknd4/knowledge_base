## 1. Learn It (Core Understanding)
- **One-line definition:** Data is the raw material a model learns from, features are the measurable input variables the model looks at, and labels are the known "right answers" the model is trained to predict.
- **Plain-English explanation (3-4 lines):**
  Think of a spreadsheet. Each row is one example (a customer, an email, a photo). Each column the model reads is a feature (age, word count, pixel values). The column holding the answer we want it to learn to predict (churned: yes/no, spam: yes/no) is the label. The model studies many rows to find the link between features and labels, then uses that link on new rows where the label is unknown.
- **Why it exists / problem it solves:**
  - A model cannot learn without examples; data is the only source of its "knowledge"
  - Features turn messy real-world things into numbers a model can process
  - Labels give supervised models a target, so they can measure how wrong they are and improve
  - The quality of all three sets the ceiling on model quality ("garbage in, garbage out")
- **Key terms to know:**
  - **Dataset:** The full collection of examples used for learning and testing
  - **Sample / instance / record:** One example (one row)
  - **Feature (attribute, variable, input, predictor):** An input measurement used to make predictions
  - **Label (target, output, ground truth):** The correct answer for a sample (used in supervised learning)
  - **Structured data:** Organised in rows and columns (tables, databases)
  - **Unstructured data:** No fixed format (text, images, audio, video)
  - **Labelled vs unlabelled data:** With known answers vs without
  - **Feature engineering:** Creating or transforming features to help the model (e.g., deriving "days since last purchase")
  - **Feature selection:** Choosing which features to keep and dropping irrelevant ones
  - **Data preprocessing / cleaning:** Handling missing values, duplicates, errors, scaling, encoding
  - **Training / validation / test split:** Separate portions of data for learning, tuning, and final unbiased evaluation
  - **Data leakage:** Information from outside the training data (or from the answer itself) sneaking into features, inflating results
  - **Data bias:** Skewed or unrepresentative data that leads to unfair or inaccurate models
  - **Data drift:** Real-world data changing over time so it no longer matches the training data
  - **Ground truth:** The trusted, verified correct answer used as the benchmark
  - **Data provenance / lineage:** Where data came from and how it has changed
- **How it works (simple steps):**
  1. **Collect data** relevant to the problem (with proper consent and legal basis).
  2. **Clean and prepare it:** fix errors, handle missing values, remove duplicates.
  3. **Define features:** select and engineer the inputs the model will use.
  4. **Attach labels** (for supervised learning) through humans, records, or past outcomes.
  5. **Split the data** into training, validation, and test sets.
  6. **Train the model** to map features to labels, then **evaluate** on unseen data.
- **Where it sits in the AI stack:** Bottom layer (data). Everything above it (model, application, governance) depends on it.

## 2. Mental Model
- **Analogy:** Teaching a child to recognise fruit. The **data** is the basket of fruit shown to them. The **features** are the things they look at: colour, shape, size, smell. The **label** is the name you tell them ("apple," "banana"). If you only ever show red apples (biased data), or give the wrong names (bad labels), the child will confidently misidentify fruit later.
- **Diagram / flow:**
```
  Dataset (table)
  ┌──────────┬──────────┬──────────┬────────────┐
  │ Age      │ Income   │ Tenure   │ Churned?   │
  │ (feature)│ (feature)│ (feature)│ (LABEL)    │
  ├──────────┼──────────┼──────────┼────────────┤
  │ 34       │ 50k      │ 2 yrs    │ No         │  ← one sample
  │ 52       │ 80k      │ 6 yrs    │ Yes        │  ← one sample
  └──────────┴──────────┴──────────┴────────────┘
        └──── features (X) ────┘      └─ label (y) ─┘

  Model learns:  features (X)  ──►  label (y)
```
- **The one thing to remember:** Features are the **question**, labels are the **answer**, and data quality decides how good the model can ever be.
- **Compare and contrast:**

  | | Features | Labels |
  |---|---|---|
  | Role | Inputs the model reads | Correct outputs the model learns to predict |
  | Also called | X, attributes, predictors, input variables | y, target, ground truth, output |
  | Present at inference? | Yes (always supplied) | No (that is what the model predicts) |
  | Needed for | All ML | Supervised learning only |
  | Example (spam filter) | Word counts, sender, links | "Spam" / "Not spam" |

  | | Structured data | Unstructured data |
  |---|---|---|
  | Format | Rows and columns | Free-form (text, image, audio) |
  | Typical method | Classical ML | Deep learning |
  | Feature work | Often manual | Mostly learned automatically |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Identify-the-feature-or-label / Scenario / Pick-the-risk
- **Must-memorize facts:**
  - [ ] Features = inputs (X); labels = outputs/targets (y)
  - [ ] Labels are required only for **supervised** learning; unsupervised learning uses unlabelled data
  - [ ] Structured = tables; unstructured = text, images, audio, video
  - [ ] Data quality drives model quality: "garbage in, garbage out"
  - [ ] Standard split: **training** (learn), **validation** (tune), **test** (final unbiased check)
  - [ ] Data leakage = information that would not be available at prediction time gets into training, causing unrealistically good results
  - [ ] Biased or unrepresentative data → biased model outputs
  - [ ] Data quality dimensions: accuracy, completeness, consistency, timeliness, relevance, representativeness
  - [ ] Labels can be wrong, inconsistent, or biased (human annotation error)
  - [ ] Protected or proxy features (e.g., postcode standing in for ethnicity) can cause discrimination
- **Keywords that signal this topic in a question:** "input variables," "target," "ground truth," "annotated," "labelled dataset," "training data," "representative," "missing values," "data quality"
- **Commonly confused with:**
  - Feature vs label (input vs answer)
  - Labelled vs unlabelled data (supervised vs unsupervised)
  - Validation set vs test set (tuning vs final evaluation)
  - Data bias vs model bias vs algorithmic bias
  - Data drift (inputs change) vs concept drift (the relationship between inputs and outputs changes)
- **Elimination tips (how to rule out wrong options):**
  - Reject "more data always fixes the problem." Quantity does not fix poor quality or bias.
  - Reject "labels are needed for all ML." Unsupervised and self-supervised methods do not need manual labels.
  - Reject using the test set for tuning, because that contaminates the final evaluation.
