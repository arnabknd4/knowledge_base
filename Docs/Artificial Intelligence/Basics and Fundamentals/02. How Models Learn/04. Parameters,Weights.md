## 1. Learn It (Core Understanding)
- **One-line definition:** Parameters are the internal numbers a model learns during training; weights are the most common type of parameter, and together they store everything the model has "learned".
- **Plain-English explanation (3-4 lines):**
  A model starts with random numbers. During training, these numbers are nudged again and again until the model's outputs become useful. After training, those final numbers *are* the model: they encode the patterns it found in the data. When people say a model has "70 billion parameters", they mean it has 70 billion of these adjustable numbers. The numbers are fixed during inference.
- **Why it exists / problem it solves:**
  - Gives the model a way to store learned knowledge without storing the raw training data
  - Gives training something to adjust to reduce error
  - Gives a rough measure of model size and capacity, and a way to share or release a trained model (by distributing the weights file)
- **Key terms to know:**
  - **Parameter:** Any value learned from data during training
  - **Weight:** Parameter that sets how strongly one neuron's signal influences the next
  - **Bias (parameter):** Learned offset added to a neuron's output. Not the same as fairness "bias"
  - **Hyperparameter:** Setting chosen by humans *before* training (learning rate, number of layers, batch size); not learned from data
  - **Parameter count / model size:** Total number of learned values (millions, billions, trillions)
  - **Model weights file / checkpoint:** The saved parameters, which is the actual trained model
  - **Open-weight model:** Weights are publicly downloadable (not necessarily open-source: training data and code may be withheld, and licence terms may restrict use)
  - **Closed / proprietary model:** Weights kept private; accessed only via API
  - **Quantization:** Storing weights at lower numeric precision to shrink the model and speed up inference, with some possible loss in quality
  - **Mixture of Experts (MoE):** Architecture where only part of the total parameters is active for each token ("total" vs "active" parameters)
  - **LoRA / parameter-efficient fine-tuning (PEFT):** Fine-tuning by training a small set of extra parameters rather than all of them
  - **Gradient descent / backpropagation:** Methods used to update weights during training
  - **Model inversion / extraction / weight theft:** Attacks or leaks that recover information from, or copy, a model
- **How it works (simple steps):**
  1. **Initialise:** Weights start as random (or pre-trained) values.
  2. **Predict:** The model processes training data and produces an output.
  3. **Measure error:** A loss function compares the output with the correct answer.
  4. **Update:** Backpropagation and gradient descent adjust the weights slightly to reduce the error.
  5. **Repeat** across many passes until performance is acceptable.
  6. **Freeze and save:** The final weights are saved and used unchanged at inference.
- **Where it sits in the AI stack:** Model layer. Weights are the core asset produced by training and the thing that gets deployed, shared, secured, or stolen.

## 2. Mental Model
- **Analogy:** A sound mixing desk with millions of dials. Each dial (weight) controls how much one signal contributes to the final sound. Training is an engineer adjusting every dial, over and over, until the output sounds right. The final dial settings are the model. Hyperparameters are the choices made *before* the session, such as how many channels the desk has and how fast the engineer is allowed to turn the dials.
- **Diagram / flow:**
```
  Input ──► [ Layer 1 ] ──► [ Layer 2 ] ──► ... ──► Output
              weights w1      weights w2
                 ▲                ▲
                 └── adjusted during TRAINING (by gradient descent)
                     frozen during INFERENCE

  Hyperparameters (set by humans before training): learning rate, layers, batch size
  Parameters (learned during training):            weights + biases
```
- **The one thing to remember:** Weights are the model's learned knowledge in numeric form. More parameters means more capacity, not automatically better quality.
- **Compare and contrast:**

  | | Parameters / Weights | Hyperparameters |
  |---|---|---|
  | Who sets them | Learned automatically from data | Chosen by humans (or tuning tools) |
  | When | During training | Before (and between) training runs |
  | Examples | Connection weights, biases | Learning rate, number of layers, epochs, batch size |
  | Change at inference? | No (frozen) | No (not applicable) |
  | Stored in the model file? | Yes | Usually only as configuration |

  | | Open-weight | Closed (API-only) |
  |---|---|---|
  | Weights accessible | Yes, downloadable | No |
  | Control | Run and modify on your own infrastructure | Vendor controls model and updates |
  | Main risk | Misuse, safeguards removable, hard to recall once released | Vendor dependence, data sent to a third party |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Compare (parameter vs hyperparameter) / Scenario / Pick-the-risk
- **Must-memorize facts:**
  - [ ] Parameters are **learned from data** during training; hyperparameters are **set by humans** beforehand
  - [ ] Weights are the main kind of parameter (plus biases)
  - [ ] Weights are **fixed during inference**
  - [ ] Parameter count is a measure of model **size and capacity**, not a guarantee of quality
  - [ ] More parameters means more compute, memory, cost, and energy
  - [ ] Bigger models can **overfit** or memorise training data, and may leak it
  - [ ] Weights **are** the trained model; protecting them protects the IP and prevents misuse
  - [ ] Open-weight is **not** the same as open-source
  - [ ] Fine-tuning updates the weights (all of them, or a small subset with PEFT/LoRA)
  - [ ] In-context learning and prompting do **not** change weights
  - [ ] Quantization reduces the model's size and cost, with possible quality trade-offs
- **Keywords that signal this topic in a question:** "billion parameters," "learned values," "weights file," "model size," "learning rate," "open-weight," "checkpoint," "fine-tune"
- **Commonly confused with:**
  - Parameters vs hyperparameters (learned vs set)
  - Weights vs features (internal learned values vs input data)
  - Bias (the learned offset parameter) vs bias (unfairness)
  - Open-weight vs open-source
  - Model size (parameters) vs training compute (the EU AI Act uses training compute for its systemic-risk presumption, not parameter count)
  - Parameters vs context window (memory of the prompt, not learned values)
- **Elimination tips (how to rule out wrong options):**
  - Reject "hyperparameters are learned during training."
  - Reject "more parameters always means a better model."
  - Reject "the model's weights update every time a user sends a prompt."
  - Reject "open-weight means fully open-source with no restrictions."
  - For "where is the model's learned knowledge stored?", the answer is the weights/parameters, not a database of training data.
  - For fairness questions, do not confuse the bias parameter with discriminatory bias.
- **Frameworks / standards link:**
  - **EU AI Act:** General-purpose AI models are presumed to carry **systemic risk** above a training-compute threshold (10^25 FLOPs), which is about compute, not parameter count. Model providers must keep technical documentation, including information on architecture and training. Open-source GPAI models get some exemptions, but not for systemic-risk models.
  - **NIST AI RMF:** Model security, provenance, and documentation fall under Govern, Map, and Manage. Model theft and tampering are recognised security risks.
  - **ISO/IEC 42001:** Covers AI system documentation, configuration and version control, and security of AI assets, which include model weights.
  - **Security angle:** Weights are a high-value asset. Controls include access management, encryption, integrity checks, and logging of who can download or modify them.
  - **Governance angle:** Releasing open weights is a hard-to-reverse decision: safety guardrails can be removed by downstream users, so risk assessment should come before release.

## 4. 🛠️ Real-World Use Cases
| # | Scenario | Industry | How this topic applies | Outcome / risk |
|---|---|---|---|---|
| 1 | Running an open-weight model on company servers | Banking / Healthcare | Company downloads and hosts the weights so data never leaves its environment | Better data control; company owns security, patching, and safety tuning |
| 2 | Choosing a smaller vs larger model for a task | Cross-industry | Fewer parameters mean lower cost and latency; larger ones may be more capable | Right-sizing saves money; oversizing wastes it, undersizing hurts quality |
| 3 | Fine-tuning a model with LoRA on internal documents | Legal / Consulting | Only a small set of extra parameters is trained | Cheap domain adaptation; risk of memorising confidential data |
| 4 | Proprietary model weights leaked or stolen | Tech / AI vendors | Weights are the crown-jewel IP | Loss of IP, safeguards bypassed, misuse |
| 5 | Quantized model on a phone or laptop | Consumer / Edge | Lower-precision weights fit on small devices | Privacy and speed gains; some accuracy loss |

- **Consulting / assurance lens:**
  - Ask the client: "Are you calling a vendor API or hosting model weights yourselves? Who is responsible for securing, updating, and monitoring the model?"
  - Self-hosted weights shift security, version control, and safety testing onto the client.
- **Evidence or controls you would look for:**
  - Inventory of models including source, version, licence, and whether weights are hosted internally
  - Access controls and logging on weight files and model registries
  - Integrity checks (hashes) and approved-version controls
  - Licence review for open-weight models (permitted use, restrictions)
  - Safety evaluation after any fine-tuning or quantization
  - Documented rationale for model size selection (cost, performance, risk)

## 5. Q&A Bank

### Quick recall
- **Q:** What are model parameters?
  **A:** The internal values a model learns from data during training; they store what the model has learned.

- **Q:** What is the difference between parameters and hyperparameters?
  **A:** Parameters are learned automatically during training. Hyperparameters are chosen by humans before training (e.g., learning rate).

- **Q:** Do weights change when a user chats with a deployed model?
  **A:** No, weights are frozen during inference.

### Conceptual
- **Q:** Does a model with more parameters always perform better?
  **A:** No. More parameters add capacity but also cost, latency, and overfitting risk. Data quality, training method, and fit to the task matter as much as size.

- **Q:** What does "open-weight" mean, and how does it differ from "open-source"?
  **A:** Open-weight means the trained weights can be downloaded. Open-source normally implies code, and often data and permissive licensing, are also available. Open-weight models may still carry use restrictions and may not disclose training data.

- **Q:** Why are model weights a security concern?
  **A:** They are the trained model itself: valuable IP, and if leaked or released, safeguards can be removed and the model misused. Weights need access control, integrity protection, and monitoring.

- **Q:** What is quantization and what is the trade-off?
  **A:** Storing weights at lower numeric precision to reduce size and speed up inference. The trade-off is potential loss of accuracy or quality.

### Scenario-based
- **Q:** A company wants to keep sensitive data in-house and is considering hosting an open-weight model. What are the governance implications?
  **A:** Benefit: data stays within its environment. Responsibilities shift to the company: securing the weights, version control, licence compliance, safety testing, patching, and monitoring, since there is no vendor managing these.

- **Q:** A team says "we'll use the biggest model to be safe." How do you respond?
  **A:** Bigger is not automatically safer or better. Choose the model by task requirements, cost, latency, data sensitivity, and tested performance, and document the rationale.

- **Q:** After fine-tuning, a model starts repeating snippets of confidential training documents. What happened and what should be done?
  **A:** The model memorised training data in its weights. Review the fine-tuning data for sensitive content, apply data minimisation and filtering, test for memorisation and leakage, restrict access, and retrain if needed.

### Interview-style
- **Q:** "Explain parameters and weights to a non-technical executive."
  **A:** "Think of the AI's 'brain' as billions of tiny dials. Training adjusts those dials until the AI gives good answers. Those dial settings, the weights, are what the AI actually knows, and they're the valuable asset. A bigger number of dials gives the AI more capacity, but not automatically better answers, and it costs more to run. From a governance view, we protect those dial settings like a crown jewel, and we're careful about who gets a copy."

## 6. ✅ Dos and ❌ Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Treat model weights as a protected asset (access control, logging, integrity checks) | Store or share weight files without controls |
| Pick model size based on task, cost, and risk | Assume the largest model is always best |
| Review licences for open-weight models | Assume "open-weight" means unrestricted or open-source |
| Re-test safety and quality after fine-tuning or quantization | Assume tuning or compression leaves behaviour unchanged |
| Keep track of model versions and sources | Run unknown or unverified weights from untrusted sources |
| Keep "parameters" and "hyperparameters" distinct in documentation | Use the terms interchangeably |
| Check fine-tuning data for sensitive content | Fine-tune on confidential data without memorisation testing |

- **Common mistakes / misconceptions:**
  1. "More parameters means smarter." (Capacity, not quality, and not always better.)
  2. "Hyperparameters are learned from data." (They are set beforehand.)
  3. "The model stores the training data in a database." (It stores patterns as weights, though some memorisation can occur.)
  4. "Open-weight equals open-source." (Different openness and licensing.)
  5. "The bias parameter is the same as bias in fairness." (Different meanings.)
- **Red flags in practice:**
  - Downloaded model weights from unverified sources
  - No owner for security of self-hosted models
  - No record of model version, source, or licence
  - Fine-tuned model released without safety or leakage testing
