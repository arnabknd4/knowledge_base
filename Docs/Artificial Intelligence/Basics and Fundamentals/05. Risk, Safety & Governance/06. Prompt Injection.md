## 1. Learn It (Core Understanding)
- **One-line definition:** Prompt injection is a security vulnerability where malicious instructions are hidden inside user inputs or external data to manipulate an AI system.
- **Plain-English explanation (3–4 lines):**  
  Just like SQL injection tricks a database, prompt injection tricks an LLM. Attackers embed hidden or misleading instructions in prompts, documents, or websites. The AI may then follow these malicious instructions — leaking secrets, bypassing safety rules, or performing unintended actions.
- **Why it exists / problem it solves:**  
  - LLMs treat text as instructions, so malicious text can hijack behavior  
  - Exploits trust in external inputs (user queries, retrieved documents, APIs)  
  - Can lead to data leaks, unsafe outputs, or unauthorized tool use  
- **Key terms to know:**  
  - **Direct prompt injection:** Malicious instructions in user input  
  - **Indirect prompt injection:** Malicious instructions hidden in external sources (e.g., web pages, PDFs)  
  - **Data poisoning:** Corrupting training or retrieval data to cause unsafe outputs  
  - **Guardrails:** Safety mechanisms to block or filter malicious instructions  
- **How it works (simple steps):**  
  1. Attacker embeds malicious instructions in input or data.  
  2. LLM interprets them as valid commands.  
  3. AI executes unintended actions (e.g., leaking data, ignoring rules).  
  4. System is compromised unless guardrails stop it.  
- **Where it sits in the AI stack:** Security risk at inference and retrieval layers.

## 2. Mental Model
- **Analogy:** Think of prompt injection like a “Trojan horse.” The AI sees a harmless-looking input (gift), but hidden inside are malicious instructions (soldiers) that hijack the system.  
- **Diagram / flow:**
    - User input / external data → Hidden malicious instructions → AI follows them → Unsafe behavior
- **The one thing to remember:** Prompt injection = malicious text hijacking AI instructions.  
- **Compare and contrast:**

| | SQL Injection | Prompt Injection |
|---|---|---|
| Target | Databases | LLMs / AI systems |
| Attack vector | Malicious query | Malicious text prompt |
| Outcome | Unauthorized data access | Unsafe AI behavior |

- **Keywords:** "prompt injection," "direct," "indirect," "Trojan horse," "guardrails"  
- **Commonly confused with:**  
  - Prompt injection vs hallucination (malicious vs accidental errors)  
  - Prompt injection vs jailbreak (malicious vs intentional bypass by user)  
- **Elimination tips:**  
  - Reject “prompt injection = model training issue.” It’s inference-time.  
  - Reject “prompt injection = hallucination.” Different causes.

## 5. Q&A Bank
- **Q:** What is prompt injection?  
  **A:** A vulnerability where malicious instructions are hidden in inputs or data to hijack AI behavior.  

- **Q:** What is the difference between direct and indirect prompt injection?  
  **A:** Direct = malicious user input; indirect = malicious external data (e.g., web pages).  

- **Q:** How does prompt injection differ from hallucination?  
  **A:** Injection is malicious manipulation; hallucination is accidental error.  

- **Q:** Name one mitigation strategy.  
  **A:** Guardrails (filters, validation, HITL oversight).
