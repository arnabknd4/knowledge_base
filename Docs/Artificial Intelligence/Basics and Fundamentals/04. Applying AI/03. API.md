## 1. Learn It (Core Understanding)
- **One-line definition:** An API is a set of rules and endpoints that allow software systems to communicate and exchange data.
- **Plain-English explanation (3–4 lines):**  
  APIs act like contracts between systems. They expose certain functions or data in a controlled way, so other applications can use them without knowing the internal details. For example, a weather API lets you request today’s forecast without needing to know how the weather service calculates it.
- **Why it exists / problem it solves:**  
  - Enables interoperability between different systems  
  - Provides reusable building blocks for developers  
  - Allows secure, controlled access to data and functionality  
- **Key terms to know:**  
  - **Endpoint:** URL where a function or resource can be accessed  
  - **Request/Response:** Client sends request; server returns response  
  - **REST API:** Uses HTTP methods (GET, POST, PUT, DELETE)  
  - **GraphQL API:** Flexible queries for specific data needs  
  - **Authentication:** API keys, OAuth tokens for secure access  
- **How it works (simple steps):**  
  1. Client sends request to API endpoint.  
  2. API processes request.  
  3. Server returns structured response (JSON/XML).  
  4. Application uses response in workflow.  
- **Where it sits in the AI stack:** Integration layer connecting LLMs/agents with external systems.

## 2. Mental Model
- **Analogy:** Think of an API as a restaurant menu. The menu lists dishes (functions) you can order. You don’t see the kitchen’s inner workings — you just place an order (request) and get your meal (response).  
- **Diagram / flow:**
    - Client → Request (API call) → Server → Response (JSON/XML) → Application
- **The one thing to remember:** API = contract for communication between systems.  
- **Compare and contrast:**

| | API | Database |
|---|---|---|
| Purpose | Communication between systems | Storage/retrieval of data |
| Interface | Endpoints, requests/responses | Queries (SQL) |
| Security | Authentication, rate limits | Access control, permissions |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Scenario (API integration) / Compare REST vs GraphQL  
- **Must-memorize facts:**  
  - [ ] API = contract for system communication  
  - [ ] REST uses HTTP verbs; GraphQL allows flexible queries  
  - [ ] Authentication ensures secure access  
  - [ ] APIs enable interoperability and integration  
- **Keywords:** "API," "endpoint," "request/response," "REST," "GraphQL," "authentication"  
- **Commonly confused with:**  
  - API vs SDK (API = interface; SDK = toolkit)  
  - API vs database (API = communication; DB = storage)  
- **Elimination tips:**  
  - Reject “API stores data.” It provides access, not storage.  
  - Reject “API = programming language.” It’s an interface, not a language.

## 5. Q&A Bank
- **Q:** What is an API?  
  **A:** A set of rules and endpoints that allow systems to communicate and exchange data.  

- **Q:** How does REST differ from GraphQL?  
  **A:** REST uses fixed endpoints and HTTP verbs; GraphQL allows flexible queries for specific data.  

- **Q:** Why are APIs important for LLM agents?  
  **A:** They let agents call external tools and integrate with enterprise systems.  

- **Q:** How is API access secured?  
  **A:** Through authentication methods like API keys or OAuth tokens.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use APIs for system integration | Confuse APIs with databases |
| Document endpoints and authentication | Assume APIs are open without security |
| Choose REST or GraphQL based on needs | Mix up API with SDK |
| Apply rate limits and guardrails | Ignore risks of misuse or overload |

- **Common mistakes:**  
  1. Thinking APIs store data themselves  
  2. Confusing APIs with programming languages  
  3. Ignoring authentication and rate limits
