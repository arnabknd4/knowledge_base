## 1. Learn It (Core Understanding)
- **One-line definition:** Agents are LLM-powered systems that can plan, reason, and take multi-step actions using tools, APIs, or external data.
- **Plain-English explanation (3–4 lines):**  
  Instead of just generating text, agents can decide what steps to take to solve a task. They break problems into smaller actions, call tools (like search, databases, or APIs), and combine results into a final answer. This makes them more interactive and capable of completing workflows, not just writing text.
- **Why it exists / problem it solves:**  
  - Extends LLMs beyond text generation into action-taking  
  - Automates multi-step tasks (search, calculation, file handling)  
  - Enables integration with enterprise systems and apps  
- **Key terms to know:**  
  - **Tool use:** Calling external APIs or functions  
  - **Planning:** Breaking tasks into steps  
  - **Reasoning loop:** Iteratively deciding next actions  
  - **Autonomy:** Ability to act without constant human prompts  
  - **Guardrails:** Safety checks to prevent misuse  
- **How it works (simple steps):**  
  1. Receive user prompt.  
  2. Plan steps needed to solve it.  
  3. Call tools or APIs to gather data or perform actions.  
  4. Combine results into final output.  
  5. Return answer or execute workflow.  
- **Where it sits in the AI stack:** Application layer built on top of LLMs.  
- **Related topics:** [[LLM]], [[RAG]], [[Embeddings]], [[Vector Databases]], [[Hallucination]]

## 2. Mental Model
- **Analogy:** Think of an agent as a personal assistant. Instead of just answering questions, it can also make calls, check your calendar, or draft emails. It doesn’t just “talk” — it “acts.”  
- **Diagram / flow:**
    - Prompt → Agent → Plan steps → Call tools/APIs → Collect results → Final answer/action
- **The one thing to remember:** Agents = LLMs + tools + planning → action-taking systems.  
- **Compare and contrast:**

| | LLM | Agent |
|---|---|---|
| Output | Text only | Text + actions |
| Scope | Single-turn answers | Multi-step workflows |
| Risk | Hallucination | Misuse of tools, unintended actions |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Scenario (tool use) / Compare vs plain LLM  
- **Must-memorize facts:**  
  - [ ] Agents = LLMs that plan and act using tools/APIs  
  - [ ] Enable multi-step workflows and automation  
  - [ ] Require guardrails (permissions, oversight)  
  - [ ] Risks: prompt injection, misuse, unintended actions  
- **Keywords:** "agent," "tool use," "planning," "workflow," "autonomy"  
- **Commonly confused with:**  
  - Agent vs chatbot (chatbot = text only; agent = text + actions)  
  - Agent vs RAG (RAG = retrieval; agent = retrieval + action)  
- **Elimination tips:**  
  - Reject “agents are just bigger LLMs.” They add planning + tool use.  
  - Reject “agents don’t need guardrails.” They do.

## 5. Q&A Bank
- **Q:** What is an agent in AI?  
  **A:** An LLM-powered system that plans and takes actions using tools/APIs.  

- **Q:** How do agents differ from plain LLMs?  
  **A:** LLMs generate text; agents generate text + take actions.  

- **Q:** Why do agents need guardrails?  
  **A:** To prevent misuse, unintended actions, or unsafe tool calls.  

- **Q:** Give two real-world uses of agents.  
  **A:** Automated research assistants and DevOps automation.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use agents for multi-step workflows | Confuse them with plain chatbots |
| Apply guardrails and permissions | Assume agents are safe without oversight |
| Document tool integrations | Ignore risks of prompt injection |
| Keep human-in-the-loop for critical tasks | Fully automate safety-critical actions |

- **Common mistakes:**  
  1. Thinking agents = bigger LLMs  
  2. Ignoring guardrails and permissions  
  3. Confusing agents with RAG-only systems
