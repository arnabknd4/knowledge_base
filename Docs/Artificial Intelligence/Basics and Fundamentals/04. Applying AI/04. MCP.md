## 1. Learn It (Core Understanding)
- **One-line definition:** An API is a defined interface that allows software systems to communicate and exchange data or functionality.
- **Plain-English explanation (3–4 lines):**  
  APIs act like contracts between systems. They expose certain functions or data in a standardized way, so other applications can use them without knowing the internal details. For example, a weather API lets you request today’s forecast without needing to understand how the weather service calculates it.
- **Why it exists / problem it solves:**  
  - Enables interoperability between different systems  
  - Provides modularity and reusability  
  - Simplifies integration by hiding internal complexity  
- **Key terms to know:**  
  - **Endpoint:** URL or function where API requests are sent  
  - **Request/Response:** Input and output of API calls  
  - **REST API:** Uses HTTP methods (GET, POST, PUT, DELETE)  
  - **SOAP API:** XML-based, older standard  
  - **GraphQL:** Flexible query-based API standard  
- **How it works (simple steps):**  
  1. Client sends request to API endpoint.  
  2. API processes request using internal logic.  
  3. API returns response in structured format (JSON/XML).  
- **Where it sits in the AI stack:** Integration layer enabling LLMs, agents, and applications to connect with external systems.

## 2. Mental Model
- **Analogy:** Think of an API as a restaurant menu. You don’t see the kitchen or how food is prepared; you just order from the menu (API endpoints) and receive the dish (response).  
- **Diagram / flow:**
    - Client → Request (API call) → API endpoint → Process → Response → Client
- **The one thing to remember:** API = contract for communication between systems.  
- **Compare and contrast:**

| | API | Database |
|---|---|---|
| Purpose | Communication between systems | Storage/retrieval of data |
| Interface | Endpoints, requests/responses | Queries (SQL) |
| Abstraction | Hides internal logic | Exposes schema directly |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Scenario (integration) / Compare REST vs GraphQL  
- **Must-memorize facts:**  
  - [ ] API = contract for communication between systems  
  - [ ] REST uses HTTP verbs; GraphQL allows flexible queries  
  - [ ] APIs hide complexity and expose functionality  
  - [ ] APIs are essential for tool use and agents  
- **Keywords:** "API," "endpoint," "request/response," "REST," "GraphQL"  
- **Commonly confused with:**  
  - API vs SDK (API = interface; SDK = toolkit)  
  - API vs database (API = communication; DB = storage)  
- **Elimination tips:**  
  - Reject “API = database.” It provides access, not storage.  
  - Reject “API = user interface.”

## 5. Q&A Bank
- **Q:** What is an API?  
  **A:** A defined interface that allows systems to communicate and exchange data or functionality.  

- **Q:** How does REST differ from GraphQL?  
  **A:** REST uses fixed endpoints and HTTP verbs; GraphQL allows flexible queries to fetch exactly what’s needed.  

- **Q:** Why are APIs important for LLM agents?  
  **A:** They enable agents to call external tools and integrate with enterprise systems.  

- **Q:** Give two real-world examples of APIs.  
  **A:** Payment gateway APIs and weather forecast APIs.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use APIs for integration | Confuse APIs with databases |
| Document endpoints and contracts | Assume APIs expose internal logic |
| Apply authentication and guardrails | Ignore security/privacy risks |
| Choose API type based on use case | Assume REST fits all scenarios |

- **Common mistakes:**  
  1. Thinking API = database  
  2. Ignoring authentication/security  
  3. Confusing API with SDK
