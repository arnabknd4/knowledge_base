## 1. Learn It (Core Understanding)
- **One-line definition:** Evaluation (Evals) refers to systematic methods for measuring the performance, reliability, and safety of LLMs and generative AI systems.
- **Plain-English explanation (3–4 lines):**  
  Evals are tests that check how well an AI model performs on tasks. They measure accuracy, usefulness, safety, and alignment with human expectations. For example, an eval might test whether a chatbot gives correct medical advice, avoids unsafe outputs, or follows instructions consistently.
- **Why it exists / problem it solves:**  
  - Ensures models meet quality and safety standards  
  - Identifies weaknesses like hallucination or bias  
  - Provides benchmarks for comparing models and improvements  
- **Key terms to know:**  
  - **Benchmark datasets:** Standard test sets (e.g., MMLU, HELM)  
  - **Human evals:** Human reviewers judge outputs for quality/safety  
  - **Automated evals:** Metrics like BLEU, ROUGE, accuracy, perplexity  
  - **Red-teaming:** Stress-testing models for unsafe behavior  
- **How it works (simple steps):**  
  1. Define evaluation criteria (accuracy, safety, relevance).  
  2. Select benchmark datasets or tasks.  
  3. Run model outputs against tasks.  
  4. Score results using metrics or human judgment.  
  5. Analyse weaknesses and improve model.  
- **Where it sits in the AI stack:** Quality assurance and governance layer.  
- **Related topics:** [[Hallucination]], [[RAG]], [[Agents]], [[Alignment]]

## 2. Mental Model
- **Analogy:** Think of evals like exam papers for students. The model is the student, and evals are the tests that check whether it learned correctly, behaves safely, and can apply knowledge.  
- **Diagram / flow:**
    - Model → Task → Output → Evaluation (metrics/human review) → Score → Improvement
- **The one thing to remember:** Evals = systematic testing of LLM performance, safety, and alignment.  
- **Compare and contrast:**

| | Training | Evaluation |
|---|---|---|
| Purpose | Teach the model | Test the model |
| Data | Large corpora | Benchmarks, tasks |
| Output | Learned weights | Scores, metrics |
| Frequency | Continuous | Periodic, iterative |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Scenario (eval design) / Compare automated vs human evals  
- **Must-memorize facts:**  
  - [ ] Evals = systematic testing of LLMs  
  - [ ] Automated metrics (BLEU, ROUGE, accuracy) vs human evals (quality, safety)  
  - [ ] Red-teaming = stress-testing for unsafe behavior  
  - [ ] Benchmarks: MMLU, HELM, BIG-bench  
- **Keywords:** "evals," "benchmark," "human eval," "automated eval," "red-teaming"  
- **Commonly confused with:**  
  - Evaluation vs training (testing vs learning)  
  - Evaluation vs monitoring (pre-deployment vs post-deployment)  
- **Elimination tips:**  
  - Reject “evals = training.” They are separate stages.  
  - Reject “evals only use humans.” Automated metrics exist too.

## 5. Q&A Bank
- **Q:** What are evals in LLMs?  
  **A:** Systematic methods for testing model performance, safety, and alignment.  

- **Q:** What is the difference between automated and human evals?  
  **A:** Automated use metrics (BLEU, ROUGE); human evals judge quality, safety, alignment.  

- **Q:** What is red-teaming in evals?  
  **A:** Stress-testing models to find unsafe or harmful behaviors.  

- **Q:** Name two benchmark datasets used in evals.  
  **A:** MMLU and HELM.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use evals before deployment | Confuse evals with training |
| Combine automated + human evals | Rely only on one method |
| Document eval methodology | Ignore bias in evaluation datasets |
| Apply red-teaming for safety | Assume models are safe without testing |

- **Common mistakes:**  
  1. Thinking evals = training  
  2. Ignoring human judgment in safety-critical tasks  
  3. Using outdated benchmarks only
