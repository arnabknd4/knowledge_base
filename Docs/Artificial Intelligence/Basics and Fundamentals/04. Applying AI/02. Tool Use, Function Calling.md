## 1. Learn It (Core Understanding)
- **One-line definition:** Tool use (function calling) is when an LLM invokes external functions, APIs, or tools to extend its capabilities beyond text generation.
- **Plain-English explanation (3–4 lines):**  
  LLMs can generate text, but they don’t inherently know live facts, perform calculations, or access private data. Function calling lets them trigger external tools — like a calculator, search engine, or database — to fetch or process information. The model decides when to call a tool, passes structured inputs, and integrates the results into its response.
- **Why it exists / problem it solves:**  
  - Extends LLMs with real-world capabilities (search, math, APIs)  
  - Reduces hallucination by grounding answers in external data  
  - Enables automation and integration with enterprise systems  
- **Key terms to know:**  
  - **Function calling:** Structured invocation of external APIs/tools by the LLM  
  - **Tool use:** General term for LLMs using external capabilities  
  - **Agent loop:** LLM plans → calls tools → integrates results → continues reasoning  
  - **Guardrails:** Safety checks on tool permissions and outputs  
- **How it works (simple steps):**  
  1. User prompt received.  
  2. LLM decides tool is needed.  
  3. Generates structured call (e.g., JSON) to tool.  
  4. Tool executes and returns result.  
  5. LLM integrates result into final answer.  
- **Where it sits in the AI stack:** Application layer, extending LLM inference with external systems.  
- **Related topics:** [[Agents]], [[RAG]], [[LLM]], [[Embeddings]]

## 2. Mental Model
- **Analogy:** Imagine a consultant who knows a lot but sometimes needs to check a calculator, a map, or a database. Instead of guessing, they pause, use the right tool, then continue the conversation with accurate information.  
- **Diagram / flow:**
    - Prompt → LLM → Function call (tool) → Tool result → LLM integrates → Final answer
- **The one thing to remember:** Tool use = LLM + external functions → grounded, extended capabilities.  
- **Compare and contrast:**

| | Plain LLM | LLM with Tool Use |
|---|---|---|
| Knowledge | Static (training data) | Dynamic (external sources) |
| Capabilities | Text generation only | Search, math, APIs, workflows |
| Risk | Hallucination | Tool misuse if unguarded |

## 3. 🎯 Exam Focus
- **Likely question types:** Definition / Scenario (when tool use is needed) / Compare vs plain LLM  
- **Must-memorize facts:**  
  - [ ] Tool use = LLM invoking external functions/APIs  
  - [ ] Reduces hallucination by grounding in external data  
  - [ ] Enables automation and integration with systems  
  - [ ] Requires guardrails for safety and permissions  
- **Keywords:** "tool use," "function calling," "API," "agent loop"  
- **Commonly confused with:**  
  - Tool use vs RAG (tools vs retrieval)  
  - Tool use vs fine-tuning (external calls vs weight changes)  
- **Elimination tips:**  
  - Reject “tool use changes model weights.” It does not.  
  - Reject “tool use is part of pre-training.” It’s inference-time behaviour.

## 5. Q&A Bank
- **Q:** What is tool use in LLMs?  
  **A:** The ability of LLMs to call external functions/APIs to extend capabilities.  

- **Q:** How does tool use reduce hallucination?  
  **A:** By grounding answers in external, trusted data sources.  

- **Q:** How does tool use differ from RAG?  
  **A:** RAG retrieves documents; tool use can perform actions or fetch live data.  

- **Q:** Why do agents rely on tool use?  
  **A:** Agents need tools to execute workflows beyond text generation.

## 6. ✅ Dos and ❌ Don’ts
| ✅ Do | ❌ Don’t |
|---|---|
| Use tool use for live data and actions | Confuse with training or fine-tuning |
| Apply guardrails and permissions | Allow unrestricted tool calls |
| Document tool integrations | Ignore provenance or safety risks |
| Combine with human oversight for critical tasks | Fully automate safety-critical actions |

- **Common mistakes:**  
  1. Thinking tool use = retraining the model  
  2. Ignoring guardrails and permissions  
  3. Confusing tool use with RAG
