## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Slash commands are shorthand triggers that execute predefined agent skills with context rules.

- **Plain-English explanation (3–4 lines):**  
  They allow you to define reusable commands (like `/deploy` or `/lint`) that agents can execute consistently.  
  Skills bundle logic, tools, and context together, ensuring predictable workflows.  
  Context options like `fork`, `allowed-tools`, and `argument-hint` control how the command runs.

- **Why it exists / problem it solves:**  
  Provides structured, repeatable workflows without manually re‑prompting agents.

- **Key terms to know:**  
  - **Custom commands:** User-defined slash triggers.  
  - **Context (fork):** Creates isolated execution branches.  
  - **Allowed-tools:** Restricts which tools can be used.  
  - **Argument-hint:** Guides expected inputs.

- **How it works (simple steps):**  
  1. Define slash command in CLAUDE.md.  
  2. Attach skill logic and context rules.  
  3. Invoke with `/command` → agent executes with constraints.

- **Where it sits in the AI stack:**  
  Model execution → workflow orchestration.

- **Related topics:** CLAUDE.md hierarchy, plan mode, CI/CD integration.

## 5. Q&A Bank

### Quick recall
- **Q:** What is a slash command?  
  **A:** A shorthand trigger for predefined agent workflows.

### Conceptual
- **Q:** Why use `fork` in a skill?  
  **A:** To isolate execution branches and prevent state leakage.

### Scenario-based
- **Q:** A team wants `/summarize` to only use `Read` and `Write`. What should be done?  
  **A:** Define skill with `allowed-tools: [Read, Write]`.

### Interview-style
- **Q:** “Explain slash commands to a non-technical executive.”  
  **A:** “They’re shortcuts that trigger consistent workflows, like pressing a button that runs a full process safely.”

## 6. ✅ Dos and ❌ Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Use fork for isolation | Let commands leak state |
| Restrict tools with allowed-tools | Allow unrestricted tool calls |
| Provide argument-hints | Assume inputs are obvious |

- **Common mistakes / misconceptions:**  
  1. Thinking slash commands = ad-hoc prompts.  
  2. Forgetting to restrict tools → security risk.

- **Red flags in practice:**  
  Commands without tool restrictions, missing documentation.
