## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Iterative refinement is the process of progressively improving outputs through repeated cycles of feedback and adjustment.

- **Plain-English explanation (3–4 lines):**  
  Instead of executing once and hoping for perfection, iterative refinement breaks tasks into cycles.  
  Each cycle produces a draft, which is then reviewed, corrected, or expanded.  
  This reduces errors, improves quality, and ensures alignment with user intent.

- **Why it exists / problem it solves:**  
  Prevents brittle one-shot execution, reduces hallucinations, and ensures outputs meet standards.

- **Key terms to know:**  
  - **Drafting:** Initial output.  
  - **Feedback loop:** Review and correction.  
  - **Retry caps:** Limit iterations to avoid infinite loops.  
  - **Multi-pass review:** Multiple refinement cycles.

- **How it works (simple steps):**  
  1. Generate initial draft.  
  2. Review against criteria.  
  3. Apply corrections/refinements.  
  4. Repeat until acceptable quality.

- **Where it sits in the AI stack:**  
  Execution → validation → governance.

- **Related topics:** Plan mode, validation retry, structured output.

## 2. Mental Model
- **Analogy:**  
  “Iterative refinement is like editing a document — you don’t publish the first draft, you polish it step by step.”

- **Text Diagram / flow:**  
  Input → Draft → Review → Refine → Final Output

- **The one thing to remember:**  
  Quality improves through cycles, not one-shot execution.

- **Compare and contrast:**

  | | Iterative Refinement | Direct Execution |
  |---|---|---|
  | Purpose | Improve quality | Immediate results |
  | When to use | Complex/high-stakes tasks | Simple/routine tasks |
  | Key difference | Multi-pass cycles | One-shot run |

  - Retry caps prevent infinite cycles.

- **Keywords that signal this topic in a question:**  
  “multi-pass”, “refinement”, “feedback loop”.

- **Commonly confused with:**  
  Plan mode (preview only, not refinement).

- **Elimination tips:**

## 6. ✅ Dos and ❌ Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Use refinement for complex tasks | Assume first draft is final |
| Set retry caps | Allow infinite loops |
| Document feedback cycles | Skip review checkpoints |

- **Common mistakes / misconceptions:**  
  1. Confusing refinement with plan mode.  
  2. Forgetting to set iteration limits.

- **Red flags in practice:**  
  No logs of refinement cycles, uncontrolled retries.
