#### 1. Learn It (Core Understanding)
*   **One-line definition:** The architectural hierarchy separating project-scoped tool/server declarations (`.mcp.json`) from user-global environment configurations and sensitive credentials (`~/.claude.json`).
*   **Plain-English explanation (3-4 lines):** Model Context Protocol (MCP) integrations require configuration files to tell the host application (like Claude Code or Claude Desktop) which MCP servers to launch and connect to. `.mcp.json` resides in the project root, defining tools and servers specific to that codebase so all team members share the same setup. In contrast, `~/.claude.json` resides in the user's home directory, storing personal API keys, user-level preferences, and global MCP servers accessible across all local projects.
*   **Why it exists / problem it solves:** Solves configuration drift across developer teams while preventing accidental commits of personal API keys, tokens, or environment-specific credentials into source control repositories.
*   **Key terms to know:**
    *  `.mcp.json`: Project-level MCP configuration file committed to version control for shared repository tooling.
    *  `~/.claude.json`: User-level global configuration file storing personal preferences, global MCP servers, and sensitive authentication tokens.
    *  Project-scoped vs. Global-scoped: Project-scoped applies strictly to the active working directory; global-scoped applies across every session on the developer's machine.
    *  Secret Leakage: The risk of committing private API keys or auth header tokens when credentials are placed in `.mcp.json` instead of `~/.claude.json` or environment variables.
*   **How it works (simple steps):**  
    1. **Initialization:** Host client reads global settings from `~/.claude.json` upon startup.
    2. **Project Discovery:** When opened in a specific repository directory, the client inspects and parses local `.mcp.json`.
    3. **Merger & Precedence:** Local `.mcp.json` server definitions merge with or override global settings for that specific session.
    4. **Tool Registration:** Active MCP servers declared in both layers instantiate their tools into the agent's context window.
*   **Where it sits in the AI stack:** Application Layer → Host Client Configuration & Developer Environment

#### 2. Mental Model
*   **Analogy:** "`.mcp.json` is like a project's `package.json` file that everyone on the software team shares, while `~/.claude.json` is like your personal `.bashrc` or `~/.ssh/config` file sitting in your home directory that belongs exclusively to you."
*   **Diagram / flow (ASCII or mermaid):**
Host Client Startup → Read User-Global (`~/.claude.json`) → Read Repository-Local (`.mcp.json`) → Merge & Instantiate MCP Servers
*   **The one thing to remember:** Share team tools in `.mcp.json`, but keep personal credentials and machine-wide servers in `~/.claude.json`.
*   **Compare and contrast:**
|  | `.mcp.json` | `~/.claude.json` |
| ------ | ------ | ------ |
| Scope | Repository / Project-level | User / Machine-global level |
| Version Control | Committed to Git (Shared with team) | Excluded from Git (Lives in `~/$HOME`) |
| Primary Contents | Project-specific MCP servers (e.g., local DB, app APIs) | Global tools, personal API keys, user preferences |
| Secret Handling | Uses env var references (`${ENV_VAR}`) | Stores local user tokens & global configs |

#### 5. Q&A Bank
##### Quick recall
*   **Q:** Which configuration file should be committed to Git to ensure all team members access the same project-specific MCP servers?  
    **A:** `.mcp.json` in the root of the project repository.
##### Conceptual
*   **Q:** Why is storing authentication tokens in `~/.claude.json` safer than putting them directly in `.mcp.json`?  
    **A:** `~/.claude.json` resides in the developer's home directory outside the git tracking tree, whereas `.mcp.json` is committed to version control where hardcoded tokens would be exposed to anyone with repo access.
##### Scenario-based
*   **Q:** A developer wants to use a personal SQLite inspection MCP server across five different clients and projects on their laptop. Where should this MCP server be declared?  
    **A:** In `~/.claude.json` (user-global configuration), so it remains active across all workspace sessions without needing to edit individual project repos.
##### Interview-style
*   **Q:** "How do you manage MCP integration configurations across developer teams while maintaining strict credential security?"  
    **A:** "We enforce a two-tier configuration architecture. Project-specific tool servers are declared in repository-level `.mcp.json` files using environment variable references for dynamic values, allowing the team to share identical tooling via Git. Personal credentials, global utility servers, and machine-specific settings are kept isolated in each developer's local `~/.claude.json` file."

#### 6. ✅ Dos and ❌ Don'ts
| ✅ Do | ❌ Don't |
| ------ | ------ |
| Commit `.mcp.json` to project repositories to standardize team tooling | Hardcode secret keys, passwords, or bearer tokens inside `.mcp.json` |
| Reference environment variables (`${API_KEY}`) in `.mcp.json` for sensitive fields | Put team-wide repository tool definitions exclusively in `~/.claude.json` |
| Use `~/.claude.json` for user-specific developer utilities and global API tokens | Treat `.mcp.json` and `CLAUDE.md` as interchangeable (configs vs prompts) |

*   **Common mistakes / misconceptions:** 
    1. Believing `~/.claude.json` is checked into project source control.
    2. Forgetting that `.mcp.json` server definitions merge with global `~/.claude.json` settings upon host startup.
*   **Red flags in practice:** Public Git commits containing plaintext API keys inside `.mcp.json` or team members manually copying personal config files into shared project roots.
