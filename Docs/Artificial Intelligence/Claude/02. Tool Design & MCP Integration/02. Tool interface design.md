## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Tool interface design defines how agents interact with external tools through schemas, naming conventions, and clear descriptions.

- **Plain-English explanation (3–4 lines):**  
  A schema specifies the structure of inputs and outputs. Naming conventions ensure consistency and readability across tools. Descriptions explain the tool’s purpose and usage so agents can call it correctly. Together, they make tool use predictable, reliable, and safe.

- **Why it exists / problem it solves:**  
  - Prevents mis‑use of tools by agents  
  - Ensures interoperability across systems  
  - Provides clarity for developers and auditors  

- **Key terms to know:**  
  - **Schema:** Defines input/output structure (JSON, parameters)  
  - **Naming conventions:** Standardized labels for tools and fields  
  - **Description writing:** Human‑readable guidance for tool use  

- **How it works (simple steps):**  
  1. Define schema (parameters, types, constraints)  
  2. Apply naming conventions (camelCase, snake_case, clarity)  
  3. Write descriptions (purpose, usage, examples)  
  4. Validate and document for agent use  

- **Where it sits in the AI stack:** Integration layer (tool use + orchestration)  
- **Related topics:** [[API design]], [[Guardrails]], [[SDK hooks]]

## 2. Mental Model
- **Analogy:**  
  Tool interface design is like designing a form: schema = fields, naming conventions = labels, description = instructions.  

- **Diagram / flow:**
    - Schema → Naming conventions → Description → Agent calls tool correctly


- **The one thing to remember:** Schema = structure, Naming = clarity, Description = usability.  

- **Compare and contrast:**

| | Schema | Naming Conventions | Description Writing |
|---|---|---|---|
| Purpose | Define structure | Ensure consistency | Explain usage |
| When to use | Always | Across all tools | For human + agent clarity |
| Key difference | Technical | Stylistic | Explanatory |

## 6. ✅ Dos and ❌ Don’ts

| ✅ Do | ❌ Don’t |
|---|---|
| Define schemas clearly | Leave parameters ambiguous |
| Use consistent naming | Mix styles (camelCase vs snake_case) |
| Write clear descriptions | Assume agents infer usage |

- **Common mistakes / misconceptions:**  
  1. Thinking naming conventions are optional.  
  2. Assuming descriptions are only for humans (agents rely on them too).  

- **Red flags in practice:** No schema validation or inconsistent naming.
