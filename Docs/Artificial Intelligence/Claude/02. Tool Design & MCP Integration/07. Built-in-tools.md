#### 1. Learn It (Core Understanding)
*   **One-line definition:** The foundational set of native local filesystem and shell execution capabilities provided to agentic coding environments for inspectable, precise file operations and system execution.
*   **Plain-English explanation (3-4 lines):** Rather than forcing language models to perform coarse search and destructive file overwrites, agentic coding environments provide structured built-in primitives. File-level inspection and manipulation are split into reading (`Read`), creating (`Write`), targeted string replacing (`Edit`), regex pattern matching (`Grep`), and wildcard file finding (`Glob`). General terminal command execution is isolated inside `Bash` for building, running tests, and git operations.
*   **Why it exists / problem it solves:** Replaces full-file overwrites (which waste tokens and risk truncating long files) and unstructured terminal hacks with deterministic, token-efficient, and easily auditable agent primitives.
*   **Key terms to know:**
    *  `Read`: Tool for viewing file contents with support for line-range offsets to save context tokens.
    *  `Write`: Tool for creating brand new files or completely overwriting existing ones.
    *  `Edit`: Tool for targeted line or string replacements inside existing files using exact pattern matching (`old_string` → `new_string`).
    *  `Bash`: Tool for executing terminal commands, running test suites, git commands, and shell scripts.
    *  `Grep`: Fast content-search tool using regular expressions to search across repository files without loading full file contents into context.
    *  `Glob`: File system search tool matching paths using pattern wildcards (e.g., `src/**/*.ts`) to discover repo structure.
*   **How it works (simple steps):**  
    1. **Discover:** The agent uses `Glob` or `Grep` to locate relevant file paths or symbol definitions across the workspace.
    2. **Inspect:** The agent uses `Read` with targeted line offsets to load specific source files into prompt context.
    3. **Modify / Execute:** The agent applies precise code modifications using `Edit` (or `Write` for new files) and runs `Bash` commands to execute build scripts or unit tests.
*   **Where it sits in the AI stack:** Application Layer → Agentic Coding Environment & Terminal Operations

#### 2. Mental Model
*   **Analogy:** "Built-in tools are like a surgeon's workstation: `Glob` and `Grep` are the imaging scanners to locate the issue, `Read` is the magnifying scope, `Edit` is the precise scalpel, `Write` is the fresh bandage, and `Bash` is the operating room generator running external equipment."
*   **Diagram / flow (ASCII or mermaid):**
Find Files (`Glob` / `Grep`) → Inspect Code (`Read`) → Precise Patch (`Edit`) → Run Tests (`Bash`)
*   **The one thing to remember:** Use `Edit` for surgical line replacements on existing files; reserve `Write` strictly for new file creation or total file rewrites.
*   **Compare and contrast:**
|  | `Edit` | `Write` | `Grep` / `Glob` | `Bash` |
| ------ | ------ | ------ | ------ | ------ |
| Purpose | Targeted string replacement in existing files | Complete creation or full overwrite of a file | Fast repository search & path discovery | General terminal command execution |
| Token Efficiency | High (transmits only replacement diff) | Low for large files (re-transmits entire file) | Very High (returns matching lines or path strings) | Variable (depends on command output) |
| Risk Level | Low (surgical change with exact matching) | High (accidental truncation or file corruption) | Zero risk (read-only search operations) | High (requires shell sandboxing & safety checks) |

#### 3. 🎯 Exam Focus
*   **Likely question types:** Best-fit / Tool selection / Token optimization scenario / Risk mitigation
*   **Must-memorize facts:**
    *  [ ] `Edit` requires unique matching strings (`old_string` must be unambiguous in the target file) to prevent unintended side effects.
    *  [ ] `Glob` finds files by path pattern matching; `Grep` searches inside file contents using regex.
    *  [ ] Using `Write` to update a 1,000-line file to change 2 lines is a context anti-pattern; `Edit` should always be preferred.
*   **Keywords that signal this topic in a question:** `Read`, `Write`, `Edit`, `Bash`, `Grep`, `Glob`, surgical file edit, token efficiency, file discovery, path rules.
*   **Commonly confused with:** `Grep` (content regex search) vs. `Glob` (file path wildcard search); `Edit` (diff string replacement) vs. `Write` (full file output).
*   **Elimination tips (how to rule out wrong options):** Eliminate options that suggest using `Bash` execution (e.g., `cat` or `sed`) when native tools like `Read`, `Grep`, or `Edit` are available. Native tools provide better structured error handling and safety checks.
*   **Frameworks / standards link:** NIST AI RMF (Manage function — strict operational controls on command execution and local filesystem mutation) / ISO 42001 (Access control and auditability of automated developer tools).

#### 5. Q&A Bank
##### Quick recall
*   **Q:** Which built-in tool should be used to search for files matching the pattern `**/*.test.ts` across a workspace?  
    **A:** `Glob`.
##### Conceptual
*   **Q:** Why is `Edit` significantly more token-efficient and safer than `Write` when updating an existing codebase file?  
    **A:** `Edit` only requires sending the specific `old_string` block and its `new_string` replacement, whereas `Write` requires generating and outputting the entire file content, which burns tokens and risks truncating unedited sections.
##### Scenario-based
*   **Q:** An agent needs to replace a deprecated function call across 20 files. How should it orchestrate its built-in tools?  
    **A:** 1. Use `Grep` to find all occurrences of the deprecated function string. 2. Use `Read` on matched line numbers to verify surrounding context. 3. Use `Edit` on each target file to apply the surgical function replacement.
##### Interview-style
*   **Q:** "Explain the core built-in tools of an agentic coding environment and how they guarantee safety and efficiency."  
    **A:** "Agentic coding environments rely on specialized, native primitives rather than monolithic terminal hacks. File navigation is handled safely via `Glob` and `Grep`, inspection via `Read`, and modification via surgical `Edit` operations rather than destructive full-file rewrites. Terminal commands are isolated inside `Bash` with explicit safety controls, ensuring efficient token usage and predictable code manipulation."

#### 6. ✅ Dos and ❌ Don'ts
| ✅ Do | ❌ Don't |
| ------ | ------ |
| Prefer `Edit` over `Write` when making targeted code modifications to existing files | Use `Write` to replace small code blocks in large files, wasting tokens and risking file corruption |
| Use `Glob` and `Grep` for fast workspace discovery before loading files into context | Use `Read` or `Bash cat` blindly on large directories to locate symbols |
| Provide unique, unambiguous context in `old_string` when executing an `Edit` call | Provide vague single-character `old_string` targets that match multiple lines in the file |

*   **Common mistakes / misconceptions:** 1. Confusing `Glob` (searching file names/paths) with `Grep` (searching text inside files). 2. Using shell utilities via `Bash` (like `grep` or `find`) when native `Grep` and `Glob` tools are available.
*   **Red flags in practice:** Agents issuing repeated `Write` commands on large source files leading to context window exhaustion or missing code sections.
