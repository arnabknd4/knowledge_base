## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Validation retry is a mechanism where outputs are re‑evaluated and retried until they meet defined criteria, with safeguards like retry caps and failure handling.

- **Plain-English explanation (3–4 lines):**  
  When a model produces invalid or incomplete outputs, validation retry loops re‑prompt or re‑execute until the output passes checks.  
  Retry caps prevent infinite loops, while failure handling ensures graceful fallback if retries fail.  
  This improves reliability and reduces malformed responses in structured workflows.

- **Why it exists / problem it solves:**  
  Prevents broken outputs, enforces schema compliance, and ensures predictable automation.

- **Key terms to know:**  
  - **Feedback loop:** Re‑prompting based on validation failure.  
  - **Retry cap:** Maximum number of retries allowed.  
  - **Failure handling:** Safe fallback when retries fail.  
  - **Validation check:** Rule or schema enforcement.

- **How it works (simple steps):**  
  1. Generate output.  
  2. Validate against schema/criteria.  
  3. If invalid → retry with feedback.  
  4. Stop at retry cap; apply failure handling if needed.

- **Where it sits in the AI stack:**  
  Prompt engineering → reliability layer.

- **Related topics:** Structured output, anti‑fabrication schemas.

## 2. Mental Model
- **Analogy:**  
  “Validation retry is like proofreading — if the draft fails checks, you revise it until it passes, but you stop after a set number of attempts.”

- **Text Diagram / flow:**  
  Output → [Validation check] → Pass → Accept  
                     ↘ Fail → Retry → Retry cap → Failure handling

- **The one thing to remember:**  
  Validation retry = feedback + retry cap + safe fallback.

- **Compare and contrast:**

  | | Validation Retry | Iterative Refinement |
  |---|---|---|
  | Purpose | Ensure compliance | Improve quality |
  | When to use | Schema/criteria enforcement | Complex drafting |
  | Key difference | Retry until valid | Multi‑pass improvement |

## 6. ✅ Dos and ❌ Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Enforce retry caps | Allow infinite retries |
| Provide clear feedback loops | Retry blindly |
| Implement failure handling | Ignore fallback paths |

- **Common mistakes / misconceptions:**  
  1. Confusing refinement with validation retry.  
  2. Forgetting to set retry caps.

- **Red flags in practice:**  
  Pipelines with uncontrolled retries, no fallback handling.
