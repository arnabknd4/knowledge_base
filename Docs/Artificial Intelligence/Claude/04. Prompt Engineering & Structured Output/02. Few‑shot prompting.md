## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Few‑shot prompting uses a small set of examples (2–4) to guide the model’s output.

- **Plain-English explanation (3–4 lines):**  
  By showing the model a handful of input–output pairs, you set the pattern for how it should respond.  
  The sweet spot is 2–4 pairs: enough to establish context, but not so many that the model gets confused or wastes tokens.  
  After 5+ examples, returns diminish — the model may overfit or lose efficiency.

- **Why it exists / problem it solves:**  
  Provides structure and reduces hallucinations without overwhelming the context window.

- **Key terms to know:**  
  - **Few‑shot:** 2–4 examples.  
  - **Zero‑shot:** No examples, rely on instructions.  
  - **Many‑shot:** 5+ examples, diminishing returns.

- **How it works (simple steps):**  
  1. Select representative examples.  
  2. Format them consistently.  
  3. Provide them in the prompt before the query.  
  4. Model follows the demonstrated pattern.

- **Where it sits in the AI stack:**  
  Prompt engineering → structured output.

- **Related topics:** Chain-of-thought, structured schemas.

## 2. Mental Model
- **Analogy:**  
  “Few‑shot prompting is like teaching by example — show a couple of solved problems, then let the student solve the next one.”

- **Text Diagram / flow:**  
  Examples (2–4 pairs) → [Model learns pattern] → New query → Output

- **The one thing to remember:**  
  2–4 examples = optimal balance.

- **Compare and contrast:**

  | | Few‑Shot Prompting | Zero‑Shot Prompting |
  |---|---|---|
  | Purpose | Guide with examples | Rely on instructions only |
  | When to use | Complex tasks | Simple tasks |
  | Key difference | Needs examples | No examples |

## 3. 🎯 Exam Focus
- **Likely question types:**  
  Definition, scenario (how many examples to use), compare/contrast.

- **Must-memorize facts:**  
  - Sweet spot = 2–4 examples.  
  - Diminishing returns after 5+.  
  - Examples must be consistent.

- **Keywords that signal this topic in a question:**  
  “few‑shot”, “examples”, “pairs”.

- **Commonly confused with:**  
  Many‑shot prompting (inefficient).  
  Zero‑shot prompting (no examples).

- **Elimination tips:**  
  If question mentions 2–4 examples → few‑shot.  
  If it mentions no examples → zero‑shot.

- **Frameworks / standards link:**  
  Maps to **structured prompting practices** in NIST AI RMF.

## 5. Q&A Bank

### Quick recall
- **Q:** What is the sweet spot for few‑shot prompting?  
  **A:** 2–4 examples.

### Conceptual
- **Q:** Why avoid 5+ examples?  
  **A:** Diminishing returns, wasted tokens, possible confusion.

### Scenario-based
- **Q:** A team uses 7 examples in prompts and sees no improvement. What should they do?  
  **A:** Reduce to 2–4 examples.

### Interview-style
- **Q:** “Explain few‑shot prompting to a non-technical executive.”  
  **A:** “It’s like showing a couple of solved examples so the AI learns the pattern, instead of overwhelming it with too many.”

## 6. ✅ Dos and ❌ Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Use 2–4 examples | Use 5+ examples unnecessarily |
| Keep examples consistent | Mix formats or styles |
| Choose representative cases | Use irrelevant examples |

- **Common mistakes / misconceptions:**  
  1. Thinking more examples always improve results.  
  2. Mixing inconsistent formats.

- **Red flags in practice:**  
  Prompts with excessive examples, token waste.
