## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Explicit criteria are rule-based flags (flag, skip, severity) used to reduce false positives in AI outputs.

- **Plain-English explanation (3–4 lines):**  
  They define clear thresholds for when an output should be flagged, skipped, or assigned a severity level.  
  This ensures that only truly relevant or risky outputs are acted upon, reducing noise.  
  By codifying explicit criteria, AI systems avoid over-triggering alerts or misclassifying benign cases.

- **Why it exists / problem it solves:**  
  Prevents false positives, improves trustworthiness, and enforces consistent decision-making.

- **Key terms to know:**  
  - **Flag:** Mark output for review.  
  - **Skip:** Ignore irrelevant or benign cases.  
  - **Severity:** Assign risk level (low, medium, high).

- **How it works (simple steps):**  
  1. Define explicit criteria in prompt or schema.  
  2. Apply flag/skip/severity rules to outputs.  
  3. Route flagged outputs for review, skip benign ones, escalate severe ones.

- **Where it sits in the AI stack:**  
  Governance → risk management → structured output.

- **Related topics:** Validation retry, anti-fabrication schemas.

## 3. 🎯 Exam Focus
- **Likely question types:**  
  Definition, scenario (when to flag vs skip), best-fit.

- **Must-memorize facts:**  
  - Flag = review.  
  - Skip = ignore.  
  - Severity = risk level.

- **Keywords that signal this topic in a question:**  
  “flag”, “skip”, “severity”, “false positives”.

- **Commonly confused with:**  
  Confidence scoring (probability-based, not rule-based).

- **Elimination tips:**  
  If question mentions thresholds → explicit criteria.  
  If it mentions probability → confidence scoring.

- **Frameworks / standards link:**  
  Maps to **risk classification** in NIST AI RMF.

## 5. Q&A Bank

### Quick recall
- **Q:** What are explicit criteria?  
  **A:** Rule-based thresholds (flag, skip, severity) to reduce false positives.

### Conceptual
- **Q:** Why use severity levels?  
  **A:** To prioritize risks and allocate review resources effectively.

### Scenario-based
- **Q:** A system flags too many benign cases. What should be done?  
  **A:** Introduce skip rules and refine severity thresholds.

### Interview-style
- **Q:** “Explain explicit criteria to a non-technical executive.”  
  **A:** “They’re rules that decide which outputs need review, which can be ignored, and how serious each case is.”

## 6. ✅ Dos and ❌ Don'ts

| ✅ Do | ❌ Don't |
|---|---|
| Define clear thresholds | Leave criteria vague |
| Use skip rules to reduce noise | Flag everything |
| Document severity levels | Ignore escalation paths |

- **Common mistakes / misconceptions:**  
  1. Confusing severity with confidence scores.  
  2. Over-flagging benign outputs.

- **Red flags in practice:**  
  No skip rules, excessive false positives.
