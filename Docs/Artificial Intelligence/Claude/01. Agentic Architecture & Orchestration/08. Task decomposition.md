## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Prompt chaining = fixed, pre‑designed sequence of prompts; dynamic decomposition = model adaptively breaks tasks into subtasks at runtime.

- **Plain-English explanation (3–4 lines):**  
  Prompt chaining is like a scripted workflow: you design a series of prompts ahead of time, each feeding into the next. Dynamic decomposition lets the model decide how to split a complex task into subtasks on the fly, based on context. The former is predictable but rigid; the latter is flexible but harder to control.

- **Why it exists / problem it solves:**  
  - Prompt chaining: Ensures consistency and exam‑style reproducibility.  
  - Dynamic decomposition: Handles unpredictable, open‑ended tasks with adaptive reasoning.  

- **Key terms to know:**  
  - **Prompt chaining:** Pre‑defined sequence of prompts.  
  - **Dynamic decomposition:** On‑the‑fly task splitting.  
  - **Subtask:** Smaller unit of work derived from a larger task.  
  - **Orchestration:** Managing how subtasks are executed.  

- **How it works (simple steps):**  
  1. Task identified  
  2. Either follow pre‑set chain (prompt chaining) or let model decide (dynamic decomposition)  
  3. Execute subtasks  
  4. Aggregate results  

- **Where it sits in the AI stack:** Application layer (prompt engineering & orchestration)

## 2. Mental Model
- **Analogy:**  
  - Prompt chaining = assembly line with fixed stations.  
  - Dynamic decomposition = project manager deciding tasks on the fly.  

- **Diagram / flow:**
    - **Prompt chaining:** Prompt 1 → Prompt 2 → Prompt 3 → Final Output
    - **Dynamic decomposition:** Task → Model decides subtasks → Subtask A / Subtask B / Subtask C → Aggregated Output
    - 
- **The one thing to remember:**  
  Prompt chaining = predictable but rigid; dynamic decomposition = adaptive but less controllable.  

- **Compare and contrast:**

| | Prompt Chaining | Dynamic Decomposition |
|---|---|---|
| Purpose | Predictable workflow | Adaptive reasoning |
| When to use | Structured tasks | Open‑ended tasks |
| Key difference | Pre‑scripted | Emergent, runtime decisions |

## 6. ✅ Dos and ❌ Don’ts

| ✅ Do | ❌ Don’t |
|---|---|
| Use chaining for structured workflows | Expect dynamic decomposition to be predictable |
| Use dynamic decomposition for open tasks | Assume chaining adapts to new contexts |
| Document decomposition method | Ignore risks of inconsistency |

- **Common mistakes / misconceptions:**  
  1. Confusing decomposition with execution order.  
  2. Assuming dynamic decomposition always yields better results.  

- **Red flags in practice:** No logging of how tasks were split.
