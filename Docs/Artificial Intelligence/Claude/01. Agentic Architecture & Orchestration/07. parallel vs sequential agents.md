## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Parallel agents run tasks simultaneously; sequential agents run tasks step‑by‑step in order.

- **Plain-English explanation (3–4 lines):**  
  In parallel mode, multiple agents work at the same time on different subtasks, speeding up workflows. In sequential mode, agents execute tasks one after another, where each step depends on the previous output. The choice depends on task dependencies and efficiency needs.

- **Why it exists / problem it solves:**  
  - Parallel: Faster execution, independent subtasks  
  - Sequential: Ensures dependency handling, ordered logic  

- **Key terms to know:**  
  - **Parallel execution:** Agents run concurrently  
  - **Sequential execution:** Agents run in strict order  
  - **Dependency:** Whether one task relies on another’s output  

- **How it works (simple steps):**  
  1. Coordinator receives task  
  2. Decide if subtasks are independent or dependent  
  3. Run agents in parallel (independent) or sequential (dependent)  
  4. Aggregate results  

- **Where it sits in the AI stack:** Application layer (multi‑agent orchestration)  
- **Related topics:** [[Coordinator–Subagent]], [[Hub‑and‑Spoke]], [[Workflow automation]]

## 2. Mental Model
- **Analogy:**  
  - Parallel = multiple chefs cooking different dishes at the same time.  
  - Sequential = one chef cooking a multi‑course meal step by step.  

- **Diagram / flow:**
    - **Parallel:** Task → Agent A → Agent B → Agent C Results → Aggregator
    - **Sequential:** Task → Agent A → Agent B → Agent C → Final Result

- **The one thing to remember:**  
  Parallel = speed; Sequential = dependency handling.  

- **Compare and contrast:**

| | Parallel Agents | Sequential Agents |
|---|---|---|
| Purpose | Speed, concurrency | Order, dependency |
| When to use | Independent subtasks | Dependent subtasks |
| Key difference | Run simultaneously | Run step‑by‑step |

## 6. ✅ Dos and ❌ Don’ts

| ✅ Do | ❌ Don’t |
|---|---|
| Use parallel for independent tasks | Force sequential when not needed |
| Use sequential for dependent tasks | Assume parallel handles dependencies |
| Document execution order | Ignore risks of race conditions |

- **Common mistakes / misconceptions:**  
  1. Thinking parallel can handle dependencies safely.  
  2. Assuming sequential is always slower (sometimes necessary).  

- **Red flags in practice:** No dependency mapping before execution.
