# Multi‑Agent Orchestration Patterns

## 1. What is it?
Design approaches for coordinating multiple Claude agents to work together on complex tasks.

## 2. Why do we need it?
Provides scalability, modularity, and fault tolerance by distributing responsibilities across specialized agents.

## 3. Core Exam Focus
- Centralized orchestration (one master agent controls flow)
- Decentralized orchestration (agents coordinate peer‑to‑peer)
- Hierarchical delegation (parent agent assigns tasks to subagents)
- Event‑driven orchestration (agents triggered by events/messages)
- Common trap: failing to design fallback or escalation paths

## 4. Real‑World Use Case
Enterprise research pipeline:
- Master agent receives research request
- Subagents handle data collection, analysis, and summarization
- Event‑driven triggers launch agents when new data arrives
- Orchestration ensures compliance and timely delivery

## 5. Interview Lens
- Q: When would you prefer centralized vs decentralized orchestration?
- Q: How do you handle agent failure in a hierarchical setup?
- Q: What’s the trade‑off between event‑driven orchestration and scheduled workflows?

## 6. Common Mistakes
- Over‑reliance on a single master agent → single point of failure
- Poor error handling → stalled workflows
- Ignoring context handoff between agents
- Not monitoring agent health/status

## 7. Mental Model
Think of orchestration as **traffic management**:
- Centralized = one traffic light controlling flow
- Decentralized = roundabout where cars self‑coordinate
- Hierarchical = highway system with main roads and feeder lanes
- Event‑driven = sensors triggering lights when cars approach

## 8. Revision Summary
- Orchestration = coordinating multiple agents
- Patterns: centralized, decentralized, hierarchical, event‑driven
- Exam traps: missing fallback, poor error handling
- Real‑world: research pipelines, enterprise workflows
- Mental model: traffic management analogy
