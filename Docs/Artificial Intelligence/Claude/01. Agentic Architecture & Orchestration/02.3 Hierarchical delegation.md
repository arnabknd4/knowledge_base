# Hierarchical Delegation

## 1. What is it?
A pattern where a parent agent delegates tasks to subagents in a structured hierarchy, with control flowing top‑down.

## 2. Why do we need it?
Provides modularity, specialization, and clear responsibility boundaries in complex workflows; simplifies scaling by layering responsibilities.

## 3. Core Exam Focus
- Parent agent assigns tasks to subagents
- Subagents may further delegate to child agents
- Clear escalation paths back to parent
- Monitoring/reporting flows upward
- Common trap: bottlenecks at parent agent if too many dependencies

## 4. Real‑World Use Case
Enterprise IT automation:
- Parent agent manages overall workflow
- Subagent A handles infrastructure provisioning
- Subagent B manages security compliance
- Subagent C handles monitoring/alerts
- Parent agent consolidates results and ensures governance

## 5. Interview Lens
- Q: How do you design escalation paths in hierarchical delegation?
- Q: What happens if a mid‑level subagent fails?
- Q: How do you balance workload between parent and subagents?

## 6. Common Mistakes
- Overloading parent agent with too many responsibilities
- Weak escalation design → failures not reported upward
- Poor dependency mapping → circular delegation loops
- Ignoring redundancy for critical subagents

## 7. Mental Model
Think of hierarchical delegation as a **corporate org chart**:
- CEO (parent agent) delegates to VPs (subagents)
- VPs delegate to managers (child agents)
- Reports flow upward, tasks flow downward

## 8. Revision Summary
- Hierarchical = parent → subagents → child agents
- Benefits: modularity, specialization, clear boundaries
- Risks: bottlenecks, weak escalation, dependency loops
- Exam traps: missing redundancy, poor workload balance
- Mental model: corporate org chart analogy
