## 1. Learn It (Core Understanding)
- **One-line definition:**  
  A hub‑and‑spoke orchestration pattern where a central coordinator manages multiple specialized subagents to complete complex tasks.

- **Plain-English explanation (3–4 lines):**  
  Instead of one agent doing everything, a coordinator delegates subtasks to subagents (spokes). Each subagent specializes in a domain (search, coding, analysis). The coordinator integrates their outputs into a coherent final answer. This reduces complexity and improves reliability.

- **Why it exists / problem it solves:**  
  - Breaks down large tasks into manageable subtasks  
  - Enables specialization (domain‑specific agents)  
  - Provides oversight and integration to avoid fragmented outputs  

- **Key terms to know:**  
  - **Coordinator:** Central hub that plans and delegates  
  - **Subagent:** Specialized agent handling a specific task  
  - **Orchestration:** Managing workflows across agents  
  - **Hub‑and‑Spoke:** Topology with one hub and multiple spokes  

- **How it works (simple steps):**  
  1. User request received by coordinator  
  2. Coordinator decomposes into subtasks  
  3. Subagents execute subtasks independently  
  4. Coordinator aggregates results  
  5. Final integrated output returned  

- **Where it sits in the AI stack:** Application layer (agents orchestration)  
- **Related topics:** [[Agents]], [[Multi-agent collaboration]], [[Workflow automation]]

## 2. Mental Model
- **Analogy:** Like a project manager (hub) assigning tasks to team members (spokes) and compiling their work into a final report.  
- **Diagram / flow:**
    - User → Coordinator (Hub) → Subagent A / Subagent B / Subagent C → Results → Coordinator → Final Output


- **The one thing to remember:** Coordinator ensures coherence; subagents provide specialization.  
- **Compare and contrast:**

| | Hub‑and‑Spoke | Peer‑to‑Peer Agents |
|---|---|---|
| Purpose | Centralized control | Decentralized collaboration |
| When to use | Complex tasks needing oversight | Emergent behavior, distributed tasks |
| Key difference | One hub directs | Agents self‑coordinate |

## 6. ✅ Dos and ❌ Don’ts

| ✅ Do | ❌ Don’t |
|---|---|
| Use coordinator for complex workflows | Assume subagents self‑coordinate |
| Document delegation and aggregation | Ignore risks of hub bottleneck |
| Apply fallback strategies | Rely on single hub without redundancy |

- **Common mistakes / misconceptions:**  
  1. Thinking subagents self‑coordinate (that’s peer‑to‑peer).  
  2. Ignoring single point of failure at hub.  

- **Red flags in practice:** No logging of delegation or aggregation.
