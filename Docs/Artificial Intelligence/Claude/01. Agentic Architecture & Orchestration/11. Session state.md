## 1. Learn It (Core Understanding)
- **One-line definition:**  
  `--resume` continues a prior agent session; `fork_session` creates a new branch from an existing session state.

- **Plain-English explanation (3–4 lines):**  
  `--resume` is used when you want to pick up exactly where the agent left off, preserving context and history. `fork_session` duplicates the current state into a new branch, allowing experimentation or alternate paths without disturbing the original. Together, they provide continuity and flexibility in agent workflows.

- **Why it exists / problem it solves:**  
  - `--resume`: Avoids losing context in long-running tasks.  
  - `fork_session`: Enables branching for “what-if” scenarios or parallel explorations.  

- **Key terms to know:**  
  - **Session state:** Memory of agent’s ongoing context.  
  - **Resume:** Continue from last checkpoint.  
  - **Fork:** Clone state into a new branch.  

- **How it works (simple steps):**  
  1. Agent session created  
  2. User chooses to continue (`--resume`) or branch (`fork_session`)  
  3. Execution continues with preserved or branched state  
  4. Results logged separately  

- **Where it sits in the AI stack:** Agent orchestration layer (session management)

## 2. Mental Model
- **Analogy:**  
  - `--resume` = reopening a saved document to continue editing.  
  - `fork_session` = making a copy of the document to try alternate edits.  

- **Diagram / flow:**
    - Session A → --resume → Continue Session A
Session A → fork_session → Session B (branch)

- **The one thing to remember:**  
  Resume = continuity; Fork = branching.  

- **Compare and contrast:**

| | --resume | fork_session |
|---|---|---|
| Purpose | Continue existing session | Create alternate branch |
| When to use | Ongoing tasks | Experimentation, parallel paths |
| Key difference | Preserves continuity | Duplicates state into new session |

## 6. ✅ Dos and ❌ Don’ts

| ✅ Do | ❌ Don’t |
|---|---|
| Use resume for continuity | Fork when you need strict continuity |
| Use fork for experimentation | Assume resume creates a branch |
| Document session lineage | Ignore risks of divergence |

- **Common mistakes / misconceptions:**  
  1. Thinking resume creates a branch (it doesn’t).  
  2. Assuming fork overwrites the original session.  

- **Red flags in practice:** No tracking of fork lineage.
