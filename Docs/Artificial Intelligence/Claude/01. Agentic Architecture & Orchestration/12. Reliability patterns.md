## 1. Learn It (Core Understanding)
- **One-line definition:**  
  Reliability patterns are design strategies that ensure AI workflows remain safe, recoverable, and trustworthy under failure or uncertainty.

- **Plain-English explanation (3–4 lines):**  
  Retries handle transient failures by re‑attempting tasks. Checkpointing saves progress so systems can resume after interruptions. Reversible actions allow undoing or rolling back unsafe steps. Human‑in‑the‑loop interrupts provide oversight when automation needs intervention. Together, these patterns build resilience into agent workflows.

- **Why it exists / problem it solves:**  
  - Prevents system crashes or data loss  
  - Ensures recoverability and auditability  
  - Provides human oversight for critical decisions  

- **Key terms to know:**  
  - **Retries:** Automatic re‑execution after failure  
  - **Checkpointing:** Saving state for recovery  
  - **Reversible actions:** Rollback capability  
  - **Human‑in‑the‑loop interrupts:** Escalation to human oversight  

- **How it works (simple steps):**  
  1. Detect failure or risk  
  2. Apply retry or rollback if possible  
  3. Resume from checkpoint if needed  
  4. Escalate to human if automation cannot resolve  

- **Where it sits in the AI stack:** Governance + application reliability layer  
- **Related topics:** [[Guardrails]], [[Human handoff]], [[Session state]]

## 2. Mental Model
- **Analogy:**  
  Reliability patterns are like safety nets in a circus: retries = trying again, checkpointing = pausing mid‑performance, reversible actions = rewinding a mistake, human interrupts = calling in a supervisor.  

- **Diagram / flow:**
    - Failure → Retry → Success?
↘ Checkpoint → Resume
↘ Rollback → Safe state
↘ Human interrupt → Oversight

- **The one thing to remember:** Reliability = resilience + recoverability + oversight.  

- **Compare and contrast:**

| | Retries | Checkpointing | Reversible Actions | Human Interrupts |
|---|---|---|---|---|
| Purpose | Handle transient errors | Save progress | Undo unsafe steps | Escalate oversight |
| Timing | Immediate | Periodic | After action | On trigger |
| Human role | None | None | Optional | Required |

## 6. ✅ Dos and ❌ Don’ts

| ✅ Do | ❌ Don’t |
|---|---|
| Use retries for transient errors | Retry indefinitely without limits |
| Save checkpoints periodically | Ignore storage costs |
| Design reversible actions | Assume rollback is automatic |
| Define human interrupt thresholds | Let AI handle critical risk unchecked |

- **Common mistakes / misconceptions:**  
  1. Thinking retries solve all failures (they don’t).  
  2. Assuming rollback is always possible.  

- **Red flags in practice:** No defined thresholds for retries or interrupts.
