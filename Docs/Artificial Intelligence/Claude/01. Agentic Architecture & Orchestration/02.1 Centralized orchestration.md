# Centralized Orchestration

## 1. What is it?
A pattern where one master agent controls and coordinates all other agents, managing workflow execution centrally.

## 2. Why do we need it?
Provides strong governance, predictable control, and simplified monitoring in enterprise systems where reliability and compliance are critical.

## 3. Core Exam Focus
- Master agent as single controller
- Task assignment and sequencing
- Monitoring and logging centralized
- Escalation paths defined at master level
- Common trap: single point of failure if master agent crashes

## 4. Real‑World Use Case
Enterprise support system:
- Master agent receives customer queries
- Delegates billing tasks to finance agent, technical tasks to devops agent
- Collects results centrally and provides unified response
- Ensures compliance and audit logging from one control point

## 5. Interview Lens
- Q: What are the trade‑offs of centralized orchestration vs decentralized?
- Q: How do you mitigate the single point of failure risk?
- Q: How would you scale centralized orchestration across multiple regions?

## 6. Common Mistakes
- Not implementing redundancy for master agent
- Overloading master agent with too many tasks
- Weak monitoring → blind spots in workflow execution
- Ignoring fallback mechanisms when subagents fail

## 7. Mental Model
Think of centralized orchestration as **air traffic control**:
- One control tower (master agent) directs all planes (subagents)
- Ensures safety, compliance, and sequencing
- Risk: if tower fails, entire system halts

## 8. Revision Summary
- Centralized = one master agent controls flow
- Benefits: governance, compliance, monitoring
- Risk: single point of failure
- Exam traps: missing redundancy, poor fallback
- Mental model: air traffic control analogy
