# GitHub Actions Secrets

## 1. What is it?
- **Secrets** are encrypted environment variables stored in GitHub.
- They provide secure access to sensitive data (tokens, passwords, API keys) inside workflows.
- Only exposed at runtime to jobs that need them.

## 2. Why do we need it?
- Prevents hardcoding sensitive values in workflow files.
- Ensures **confidentiality** and **security** in CI/CD pipelines.
- Centralized management of credentials across repositories and organizations.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Use secret
        run: echo "Token: ${{ secrets.MY_TOKEN }}"
```
`secrets.MY_TOKEN` → securely accesses the stored secret.

## 5. Interview Questions and Answers
Q: What are GitHub Actions secrets?
A: Encrypted environment variables used to store sensitive data securely.

Q: How do you access a secret in a workflow?
A: Using `${{ secrets.SECRET_NAME }}`.

Q: Difference between secrets and variables?
A: Secrets are encrypted and hidden; variables are plain values for configuration.

## 6. Common Mistakes
- Forgetting to wrap secrets in `${{ }}` → values not interpolated.
- Printing secrets in logs → exposes sensitive data.
- Misusing repo secrets when org/environment secrets are required.
- Storing non‑sensitive config as secrets → unnecessary complexity.

## 7. Mental Model
- Think of secrets as “locked vault keys”:
- GitHub stores them securely.
- Workflows can unlock them only when needed.
- They vanish after job execution.

## 8. Revision Summary
- Secrets = encrypted environment variables.
- Access via ${{ secrets.NAME }}.
- Scoped at repo, org, or environment level.
- Best practice: never log or expose secrets.
