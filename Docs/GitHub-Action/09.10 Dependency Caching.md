# Dependency Caching in GitHub Actions

## 1. What is it?
- **Dependency caching** stores commonly used files (like `node_modules`, Maven packages, Python wheels) between workflow runs.
- It avoids re-downloading or rebuilding dependencies every time, speeding up workflows.

## 2. Why do we need it?
- Reduces build time significantly.
- Saves bandwidth and resources.
- Improves efficiency in CI/CD pipelines.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Cache Node.js dependencies
        uses: actions/cache@v3
        with:
          path: ~/.npm
          key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-

      - name: Install dependencies
        run: npm install

      - name: Run tests
        run: npm test
```

- path: location of cached files (`~/.npm`).
- key: unique identifier for the cache (based on OS + hash of package-lock.json).
- restore-keys: fallback keys if exact match not found.

## 4. Exam Perspective
- Key focus areas: `actions/cache`, `path`, `key`, `restore-keys`.
- Expect questions on how caching differs from artifacts and how cache keys are generated.

## 5. Interview Questions and Answers
Q: What is dependency caching in GitHub Actions?
A: A mechanism to store and reuse dependencies between workflow runs to reduce build time.

Q: How is a cache identified?
A: By a unique key (often based on OS and dependency lock files).

Q: What is the difference between caching and artifacts?
A: Caching is for speeding up builds by reusing dependencies, while artifacts are for sharing build outputs between jobs.

## 6. Common Mistakes
- Using a static cache key → cache never updates when dependencies change.
- Forgetting restore-keys → no fallback cache available.
- Caching large unnecessary directories → slows down workflows.
- Confusing cache with artifacts → misuse in pipelines.

## 7. Mental Model
- Think of caching as a “warehouse of spare parts”:
- Each workflow run checks the warehouse for parts (dependencies).
- If found, it reuses them instead of rebuilding.
- If not found, it builds new parts and stores them for future runs.

## 8. Revision Summary
- Dependency caching = reuse of dependencies across workflow runs.
- Implemented with actions/cache.
- Key components: path, key, restore-keys.
- Difference: cache = speed optimization, artifacts = file sharing.
