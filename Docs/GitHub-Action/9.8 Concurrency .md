# Concurrency in GitHub Actions

## 1. What is it?
- **Concurrency** in GitHub Actions is a feature that controls how workflows run when multiple executions are triggered simultaneously.
- It ensures that only one workflow (or job) runs at a time for a given concurrency group, canceling or queuing others.

## 2. Why do we need it?
- Prevents duplicate or conflicting workflow runs (e.g., multiple deployments).
- Saves resources by canceling redundant runs.
- Ensures consistency in environments where only one job should execute at a time.

## 3. Real World Example
```yaml
name: Deploy Workflow
on:
  push:
    branches: [ "main" ]

concurrency:
  group: production-deploy
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v3
      - name: Deploy to production
        run: ./deploy.sh
```
- `group`: defines the concurrency group (production-deploy).
- `cancel-in-progress`: cancels any currently running workflow in the same group when a new one is triggered.

## 4. Exam Perspective
- Key focus areas: `concurrency keyword`, `group`, `cancel-in-progress`.
- Expect questions on how concurrency prevents duplicate runs and how groups are defined.

## 5. Interview Questions and Answers
Q: What is concurrency in GitHub Actions?
A: A mechanism to control workflow execution by grouping runs and canceling duplicates.

Q: How do you cancel in-progress workflows?
A: By setting cancel-in-progress: true under the concurrency section.

Q: Why is concurrency important in CI/CD pipelines?
A: It prevents race conditions, duplicate deployments, and wasted resources.

## 6. Common Mistakes
- Forgetting to define a concurrency `group` → `workflows` run in parallel unnecessarily.
- Misusing `cancel-in-progress` → important runs may be canceled unintentionally.
- Using the same group name across unrelated workflows → causes unexpected cancellations.

## 7. Mental Model
- Think of concurrency as a “traffic signal”:
- The group is the lane of traffic.
- The signal (`cancel-in-progress`) decides whether to stop the current car (workflow) and let the new one pass.
- Without signals, cars pile up and cause collisions (duplicate runs).

## 8. Revision Summary
- Concurrency = controls simultaneous workflow runs.
- Defined with group and cancel-in-progress.
- Prevents duplicate runs, saves resources, ensures consistency.
- Acts like a traffic controller for workflows.
