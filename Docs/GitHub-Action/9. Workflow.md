# GitHub Actions Workflow

## 1. What is it?
- A **GitHub Actions workflow** is an automated process defined in a repository that runs jobs based on triggers (events).
- Workflows are written in **YAML files** stored under `.github/workflows/`.

## 2. Why do we need it?
- Automates CI/CD tasks such as building, testing, and deploying code.
- Ensures consistency and reliability across environments.
- Reduces manual effort and speeds up delivery cycles.

## 3. Real World Example
```yaml
name: CI Pipeline
on:
  push:
    branches: [ "main" ]
  pull_request:
    branches: [ "main" ]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v3

      - name: Set up Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '16'

      - name: Install dependencies
        run: npm install

      - name: Run tests
        run: npm test

```

- This workflow runs on every push or pull request to main.
- It checks out code, sets up Node.js, installs dependencies, and runs tests.
## 4. Exam Perspective
- Key focus areas: workflow structure, triggers (on:), jobs, steps, runners, and reusable Actions.
- Expect questions on YAML syntax, event triggers, and differences between GitHub-hosted vs self-hosted runners.
## 5. Interview Questions and Answers
- Q: What is a GitHub Actions workflow? A: A YAML-defined automation process triggered by repository events.
- Q: Where are workflows stored? A: In the .github/workflows/ directory of the repository.
- Q: What are runners? A: Machines (GitHub-hosted or self-hosted) that execute workflow jobs.
## 6. Common Mistakes
- Misplacing workflow files outside .github/workflows/.
- Incorrect indentation in YAML → parsing errors.
- Forgetting to specify triggers (on:).
- Not caching dependencies → slower builds.
## 7. Mental Model
Think of a workflow as a “pipeline factory”:
- Trigger (on:) starts the pipeline.
- Jobs are assembly lines.
- Steps are tasks at each station.
- Runners are the machines executing the tasks.
## 8. Revision Summary
- Workflow = YAML automation file in .github/workflows/.
- Triggered by events (push, PR, schedule, etc.).
- Contains jobs → steps → executed on runners.
- Benefits: automation, consistency, faster feedback.
