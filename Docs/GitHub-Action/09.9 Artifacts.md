# Workflow Artifacts in GitHub Actions

## 1. What is it?
- **Artifacts** are files created during a workflow run that can be saved and shared between jobs or downloaded later.
- They act as **temporary storage** for build outputs, logs, test results, or compiled binaries.

## 2. Why do we need it?
- Allows jobs to share data across different stages of a workflow.
- Provides access to build/test outputs after workflow completion.
- Useful for debugging, auditing, and deployment pipelines.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Build project
        run: mkdir output && echo "Hello World" > output/hello.txt

      - name: Upload artifact
        uses: actions/upload-artifact@v3
        with:
          name: build-output
          path: output/

  test:
    runs-on: ubuntu-latest
    needs: build
    steps:
      - name: Download artifact
        uses: actions/download-artifact@v3
        with:
          name: build-output
      - name: Run tests
        run: cat build-output/hello.txt
```
- `Upload artifact` → saves files from the build job.
- `Download artifact` → retrieves files in the test job.

# 4. Exam Perspective
- Key focus areas: `upload-artifact`, `download-artifact`, artifact naming, path specification.
- Expect questions on how artifacts enable job-to-job communication and debugging.

# 5. Interview Questions and Answers
Q: What are workflow artifacts in GitHub Actions?
A: Files produced during workflow runs that can be stored, shared, and downloaded.

Q: How do you upload artifacts?
A: Using actions/upload-artifact with a name and path.

Q: How do you share artifacts between jobs?
A: Upload in one job, then download in another using actions/download-artifact.

# 6. Common Mistakes
- Forgetting to specify path → no files uploaded.
- Misnaming artifacts → download step fails.
- Uploading large files unnecessarily → slows down workflows.
- Assuming artifacts persist forever → they are temporary (default retention ~90 days).

# 7. Mental Model
- Think of artifacts as “packages on a conveyor belt”:
- Each job can place a package (artifact) on the belt.
- Later jobs can pick up the package and use it.
- After some time, packages expire and are removed.

## 8. Revision Summary
- Artifacts = files saved during workflow runs.
- Use `upload-artifact` and `download-artifact`.
- Enable job-to-job communication and debugging.
- Temporary storage, not permanent archives.
