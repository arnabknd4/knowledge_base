# Actions Runner Controller (ARC) – Core Components & Resources

## 1. What is it?
- ARC is a **Kubernetes controller** that manages GitHub Actions self‑hosted runners.
- It introduces **Custom Resource Definitions (CRDs)** to define and control runner behavior.

## 2. Why do we need it?
- Manual runner provisioning is inefficient.
- ARC provides:
  - **Declarative runner management** via Kubernetes manifests.
  - **Elastic scaling** through autoscaler resources.
  - **Multi‑repo/org support** for enterprise workloads.
  - **Integration with Kubernetes security, networking, and monitoring.**

## 3. Core Components (CRDs)
- **Runner**  
  - Represents a single GitHub Actions runner Pod.  
  - Useful for dedicated or static runners.

- **RunnerDeployment**  
  - Manages a group of runners for a repository or organization.  
  - Similar to Kubernetes Deployment, ensures desired runner count.

- **RunnerSet**  
  - Defines a pool of runners across multiple repositories/orgs.  
  - Useful for scale sets and shared capacity.

- **HorizontalRunnerAutoscaler (HRA)**  
  - Automatically scales runners based on workload demand.  
  - Metrics include queued jobs and in‑progress workflows.

- **Listener**  
  - Watches GitHub events and triggers runner provisioning.  
  - Ensures jobs are matched with available runners.

## 4. Real World Example
```yaml
apiVersion: actions.summerwind.dev/v1alpha1
kind: RunnerDeployment
metadata:
  name: org-runners
spec:
  template:
    spec:
      organization: my-org
---
apiVersion: actions.summerwind.dev/v1alpha1
kind: HorizontalRunnerAutoscaler
metadata:
  name: org-runners-autoscaler
spec:
  scaleTargetRef:
    name: org-runners
  minReplicas: 2
  maxReplicas: 20
  metrics:
    - type: TotalQueuedAndInProgressWorkflowRuns
      organizationNames:
        - my-org
```

## 6. Interview Questions and Answers
Q: What CRDs does ARC introduce?
A: Runner, RunnerDeployment, RunnerSet, HorizontalRunnerAutoscaler, Listener.

Q: How does ARC scale runners?
A: Through HRA, which monitors GitHub job queues and adjusts runner replicas.

Q: Difference between RunnerDeployment and RunnerSet?
A: RunnerDeployment targets a repo/org; RunnerSet manages shared pools across multiple repos/orgs.

## 7. Common Mistakes
- Misconfigured autoscaler metrics → runners don’t scale.
- Forgetting GitHub App authentication → runners fail to register.
- Over‑provisioning → wasted Kubernetes resources.
- Using Runner instead of RunnerDeployment for scalable workloads.

## 8. Mental Model
Think of ARC as a “Kubernetes operator for GitHub runners”:
- CRDs = blueprints for runner behavior.
- Kubernetes = infrastructure layer.
- ARC = orchestrator ensuring jobs always have available runners.

## 9. Revision Summary

- Provides auto‑scaling, lifecycle management, and cost optimization.
- Best for enterprise CI/CD pipelines with variable workloads.
