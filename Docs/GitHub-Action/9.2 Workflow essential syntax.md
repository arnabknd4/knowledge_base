# 1. Workflow Name (appears in GitHub UI)
``` yaml
name: CI/CD Pipeline
```
# 2. Triggers (When does it run?)
``` yaml
on:
  push:
    branches: [ "main", "develop" ]
    paths-ignore: [ '**.md' ]           # Skip docs updates
  pull_request:
    branches: [ "main" ]
  workflow_dispatch:                   # Enables manual trigger button
  schedule:
    - cron: '0 0 * * *'                # Daily at midnight UTC
```
# 3. Environment Variables (Global level)
``` yaml
env:
  NODE_VERSION: '20'
```

# 4. Jobs Execution
``` yaml
jobs:
  build-and-test:
    runs-on: ubuntu-latest             # Runner environment
    
    # Strategy Matrix for testing multiple versions
    strategy:
      matrix:
        node-version: [18.x, 20.x]
        os: [ubuntu-latest, macos-latest]

    steps:
      # Step 1: Check out repository code
      - name: Checkout repository
        uses: actions/checkout@v4

      # Step 2: Set up language runtime
      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: 'npm'                  # Built-in dependency caching

      # Step 3: Run custom scripts
      - name: Install dependencies & Test
        run: |
          npm ci
          npm test
        env:
          API_SECRET: ${{ secrets.MY_API_KEY }}  # Accessing repository secrets
    
    deploy:
        runs-on: ubuntu-latest
        needs: build-and-test               # Dependency: Wait for tests to pass
        if: github.ref == 'refs/heads/main'  # Conditional execution

        environment: production             # Deployment environment control

        steps:
            - name: Deploy step
            run: echo "Deploying application..."

```

# Real-Life Project Syntax Patterns
## 1. Dependency Caching
``` yaml
- name: Cache dependencies
  uses: actions/cache@v4
  with:
    path: ~/.npm
    key: ${{ runner.os }}-node-${{ hashFiles('**/package-lock.json') }}
    restore-keys: |
      ${{ runner.os }}-node-
```

## 2. Artifact Management
``` yaml
# Upload compiled assets from build job
- name: Upload Build Artifacts
  uses: actions/upload-artifact@v4
  with:
    name: dist-files
    path: ./dist

# Download assets in deployment job
- name: Download Build Artifacts
  uses: actions/download-artifact@v4
  with:
    name: dist-files
```

## 3. Workflow Commands & Outputs
``` yaml
- name: Set output variable
  id: step_one
  run: echo "status=success" >> $GITHUB_OUTPUT

- name: Read output variable
  run: echo "Previous step was ${{ steps.step_one.outputs.status }}"
```

## 4. Reusable Workflows
``` yaml
# Calling a reusable workflow inside a job
jobs:
  call-security-scan:
    uses: my-org/shared-workflows/.github/workflows/security.yml@main
    with:
      environment: staging
    secrets: inherit
```
## Cheat Sheet: Exam vs. Real-Life Priority

| Syntax Keyword | Function | Exam Focus | Real-Life Usage |
| :--- | :--- | :--- | :--- |
| `on:` | Defines triggering events (push, pull_request, cron) | High | Fundamental |
| `needs:` | Controls job dependencies/sequential execution | High | Critical for CI/CD gates |
| `matrix:` | Runs jobs across OS/language combinations | High | Cross-platform testing |
| `secrets.` | Secure key retrieval (`${{ secrets.TOKEN }}`) | High | Environment protection |
| `concurrency:` | Cancels redundant in-progress runs | Low | Essential for cost/time optimization |
| `paths/paths-ignore:` | Triggers execution based on modified files | Medium | Essential for Monorepos |
