# Kubernetes Admission Controller

## 1. What is it?
- Admission controllers are **plugins in the Kubernetes API server** that intercept requests before they are persisted in etcd.
- They can **mutate** or **validate** objects to enforce policies, inject defaults, or reject invalid configurations.
- They operate after authentication/authorization but before persistence.

## 2. Why do we need it?
- Enforce **security, compliance, and governance** at the cluster level.
- Prevent unsafe or non‑compliant workloads from being deployed.
- Automate injection of defaults (e.g., sidecars, labels).
- Ensure workloads adhere to organizational policies.

## 3. Real World Example
```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingWebhookConfiguration
metadata:
  name: deny-unapproved-images
webhooks:
  - name: imagepolicy.k8s.io
    rules:
      - apiGroups: [""]
        apiVersions: ["v1"]
        operations: ["CREATE"]
        resources: ["pods"]
    clientConfig:
      service:
        name: image-policy-service
        namespace: kube-system
      caBundle: <CA_BUNDLE>
```
- This webhook denies Pods using unapproved container images.

## 4. Exam Perspective
- Know mutating vs validating admission controllers.
- Understand AdmissionReview object format.
- Be able to explain webhook configurations (MutatingWebhookConfiguration, ValidatingWebhookConfiguration).
- Expect scenario questions on enforcing policies like resource quotas, image registries, or PodSecurity.

## 5. Interview Questions and Answers
Q: What is an admission controller?
A: A plugin in the API server that intercepts requests to enforce policies or mutate objects before persistence.

Q: Difference between mutating and validating admission controllers?
A: Mutating controllers can change objects; validating controllers only approve/reject.

Q: Why are admission controllers important?
A: They enforce compliance, security, and workload governance in Kubernetes clusters.

## 6. Common Mistakes
- Forgetting to enable required admission controllers → features like quotas or PodSecurity won’t work.
- Misconfigured webhook TLS → API server cannot reach webhook.
- Writing overly complex webhook logic → slows down API server.
- Assuming admission controllers apply to read requests (they don’t).

## 7. Mental Model
- Think of admission controllers as “gatekeepers at the API server door”:
- Authentication/authorization = identity check.
- Admission controllers = policy enforcement and mutation.
- Persistence = final storage in etcd.

## 8. Revision Summary
- Admission controllers intercept create/update/delete requests.
- Types: Mutating, Validating, and Policies.
- Configured via webhooks or declarative policies.
- Essential for security, compliance, and workload governance.
