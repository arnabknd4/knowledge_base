# Runner Groups in GitHub Actions

## 1. What is it?
- **Runner groups** are collections of self-hosted runners that can be organized and managed together.
- They allow administrators to control which repositories or organizations can use specific sets of runners.
- Useful for applying policies, isolating workloads, and managing access.

## 2. Why do we need it?
- Provides **segmentation** of runners for different teams, projects, or environments.
- Enhances **security** by restricting runner usage to authorized repositories.
- Improves **resource management** by grouping runners based on hardware, OS, or purpose.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: [self-hosted, linux, x64, my-runner-group]
    steps:
      - uses: actions/checkout@v3
      - run: ./build.sh
```
- `my-runner-group` specifies that the job should run on a runner from that group.
- Runner groups can be defined at the organization or enterprise level.

## 4. Exam Perspective
- Key focus areas: difference between runner groups and labels, how runner groups restrict access, organizational use cases.
- Expect questions on how runner groups improve governance in enterprise CI/CD pipelines.

## 5. Interview Questions and Answers
Q: What are runner groups in GitHub Actions?
A: Collections of self-hosted runners managed together, with controlled access for repositories.

Q: How do runner groups differ from labels?
A: Labels identify runner capabilities (e.g., linux, x64), while runner groups control access and permissions.

Q: Why are runner groups important in enterprises?
A: They enforce security boundaries and ensure only authorized repositories can use certain runners.

## 6. Common Mistakes
- Confusing labels with runner groups → jobs fail to target the right runners.
- Not assigning repositories correctly → workflows cannot access runners.
- Overlapping groups without clear policies → resource conflicts.
- Forgetting to manage group permissions → unauthorized access risks.

## 7. Mental Model
- Think of runner groups as “departments in a company”:
- Each department (group) has its own workers (runners).
- Labels = skills of workers (Linux, Windows, GPU).
- Groups = organizational boundaries deciding which projects can hire which workers.
