# Private Networking in GitHub Actions

## 1. What is it?
- **Private networking** allows self-hosted runners to connect to internal systems, databases, or services that are not accessible over the public internet.
- GitHub-hosted runners **cannot** access private networks directly, but self-hosted runners can because they run inside your own infrastructure.

## 2. Why do we need it?
- Many enterprise workflows require access to:
  - Internal APIs or microservices.
  - Private package registries.
  - On-premise databases or file servers.
- Ensures CI/CD pipelines can integrate with secure, internal environments.

## 3. Real World Example
```yaml
jobs:
  deploy:
    runs-on: self-hosted
    steps:
      - name: Checkout code
        uses: actions/checkout@v3

      - name: Deploy to internal server
        run: ssh user@10.0.0.5 "deploy.sh"
```
- Here, the self-hosted runner connects to a private IP (10.0.0.5) inside the company’s network.

## 4. Exam Perspective
- Key focus areas: difference between GitHub-hosted vs self-hosted runners in networking.
- Expect questions on why private networking is only possible with self-hosted runners.
- Know how to configure runners behind firewalls or VPNs.

## 5. Interview Questions and Answers
Q: Can GitHub-hosted runners access private networks?
A: No, they only have public internet access.

Q: How do self-hosted runners enable private networking?
A: By running inside your own infrastructure, they inherit access to internal systems.

Q: Why is private networking important in CI/CD?
A: It allows workflows to securely interact with internal services and resources.

## 6. Common Mistakes
- Assuming GitHub-hosted runners can access private IPs → jobs fail.
- Not securing self-hosted runners → risk of exposing internal systems.
- Forgetting firewall/VPN configuration → workflows cannot reach internal services.
- Mixing public and private networking without clear separation.

## 7. Mental Model
- Think of private networking as “inside access badges”:
- GitHub-hosted runners = visitors with public access only.
- Self-hosted runners = employees with badges to enter secure areas (internal systems).

## 8. Revision Summary
- Private networking = access to internal systems via self-hosted runners.
- GitHub-hosted runners → public internet only.
- Self-hosted runners → inherit private network access.
- Critical for enterprise CI/CD pipelines.
