# OpenID Connect (OIDC)

## 1. What is it?
- **OpenID Connect (OIDC)** is an identity layer built on top of OAuth 2.0.
- It allows applications (clients) to verify the identity of users or services based on authentication performed by an identity provider (IdP).
- In GitHub Actions, OIDC enables **secure, short‑lived authentication tokens** to cloud providers without storing long‑lived secrets.

## 2. Why do we need it?
- Eliminates the need for static credentials (PATs, long‑lived cloud keys).
- Provides **federated identity** between GitHub and cloud providers (Azure, AWS, GCP).
- Improves security posture by using **temporary tokens** with limited scope.
- Supports **zero‑trust principles** in CI/CD pipelines.

## 3. Real World Example
```yaml
jobs:
  deploy:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      contents: read
    steps:
      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::123456789012:role/GitHubOIDCRole
          aws-region: us-east-1
```
- GitHub generates an OIDC token.
- AWS IAM role trusts GitHub’s OIDC provider → temporary credentials issued.

## 5. Interview Questions and Answers
Q: What is OpenID Connect?
A: An identity layer on OAuth 2.0 that provides authentication and identity verification.

Q: How does GitHub Actions use OIDC?
A: It issues short‑lived tokens to authenticate with cloud providers, replacing static secrets.

Q: Why is OIDC more secure than storing secrets?
A: Tokens are temporary, scoped, and automatically rotated, reducing risk of leakage.

## 6. Common Mistakes
- Forgetting to enable id-token: write permissions in workflow.
- Misconfiguring trust relationship in cloud IAM → authentication fails.
- Assuming OIDC replaces all secrets (it only covers cloud auth, not all sensitive values).
- Logging OIDC tokens → security risk.

## 7. Mental Model
- Think of OIDC as a “passport system”:
- GitHub = passport issuer.
- Cloud provider = border control.
- OIDC token = temporary visa allowing entry for a specific job.

## 8. Revision Summary
- OIDC = identity layer on OAuth 2.0.
- Used in GitHub Actions for secure cloud authentication.
- Provides short‑lived tokens, eliminating static secrets.
- Requires workflow permission id-token: write.
- Best practice: configure least privilege trust in cloud IAM.
