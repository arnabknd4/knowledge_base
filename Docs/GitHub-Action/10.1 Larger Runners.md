# Larger Runners in GitHub Actions

## 1. What is it?
- **Larger runners** are GitHub-hosted runners with **more CPU, memory, and disk resources** than the standard ones.
- They are designed for **resource-intensive workflows** such as building large projects, running heavy tests, or training ML models.

## 2. Why do we need it?
- Standard runners may not have enough resources for complex builds.
- Larger runners reduce build times and prevent failures due to resource limits.
- They provide scalability for enterprise-level CI/CD pipelines.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    # Request a larger runner
    resources:
      cpu: 8
      memory: 32GB
      disk: 200GB
    steps:
      - uses: actions/checkout@v3
      - run: ./build-large-project.sh
```
- resources: specifies the larger runner configuration (CPU, memory, disk).

## 5. Interview Questions and Answers
Q: What are larger runners in GitHub Actions?
A: Enhanced GitHub-hosted runners with more CPU, memory, and disk resources for heavy workflows.

Q: When should you use larger runners?
A: For resource-intensive tasks like compiling large codebases, running integration tests, or ML workloads.

Q: How are larger runners billed?
A: They consume more minutes and are billed at higher rates compared to standard runners.

## 6. Common Mistakes
- Using larger runners unnecessarily → higher costs without real benefit.
- Not optimizing workflows before scaling → wasted resources.
- Forgetting billing impact → unexpected expenses.
- Misconfiguring resource requests → workflow fails to allocate properly.

## 7. Mental Model
- Think of larger runners as “heavy-duty machines”:
- **Standard runners** = small workshop tools.
- **Larger runners** = industrial-grade machines for big jobs.
- Choose based on workload size and complexity.
