# Runners in GitHub Actions

## 1. What is it?
- A **runner** is a server (machine) that executes jobs defined in a GitHub Actions workflow.
- Each runner listens for available jobs, runs them, and reports results back to GitHub.

## 2. Types of Runners
- **GitHub-hosted runners**
  - Managed by GitHub.
  - Preconfigured with popular tools and environments (Ubuntu, Windows, macOS).
  - Automatically scaled and maintained.
- **Self-hosted runners**
  - Managed by you or your organization.
  - Can run on your own infrastructure (VMs, physical servers, cloud).
  - Useful for custom environments, private networks, or specialized hardware.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest   # GitHub-hosted runner
    steps:
      - uses: actions/checkout@v3
      - run: npm install && npm test

  custom-build:
    runs-on: self-hosted     # Self-hosted runner
    steps:
      - run: ./custom-build.sh
```
- runs-on: ubuntu-latest → GitHub-hosted runner.
- runs-on: self-hosted → job runs on your own machine.

## 4. Exam Perspective
- Key focus areas: difference between GitHub-hosted vs self-hosted runners, runs-on keyword, scalability, customization.
- Expect questions on when to use self-hosted runners (e.g., private dependencies, custom hardware).

## 5. Interview Questions and Answers
Q: What is a runner in GitHub Actions?
A: A machine that executes workflow jobs and reports results back to GitHub.

Q: Difference between GitHub-hosted and self-hosted runners?
A: GitHub-hosted are managed by GitHub with preinstalled tools, while self-hosted are managed by the user with full customization.

Q: When should you use self-hosted runners?
A: When workflows require private infrastructure, custom dependencies, or specialized hardware.

## 6. Common Mistakes
- Forgetting to register self-hosted runners → jobs fail.
- Using outdated GitHub-hosted runner images → missing tools.
- Misconfiguring runs-on → workflow doesn’t run as expected.
- Overloading self-hosted runners without scaling.

## 7. Mental Model
- Think of runners as “workers on the factory floor”:
- GitHub-hosted runners = temporary workers hired by GitHub (ready-to-go).
- Self-hosted runners = your own permanent staff (customized for your needs).
- Jobs = tasks assigned to workers.
