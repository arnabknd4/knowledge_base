# Compromised Runners

## 1. What is it?
- A **compromised runner** is a self-hosted or scale-set runner that has been taken over by an attacker.
- Attackers can exploit runners to inject malicious code, steal secrets, or tamper with build artifacts.
- Especially risky in **shared or untrusted environments**.

## 2. Why do we need to understand it?
- Runners execute workflow jobs with access to code, secrets, and artifacts.
- If compromised:
  - Secrets can be exfiltrated.
  - Artifacts can be tampered with.
  - CI/CD pipeline integrity is broken.
- Protecting runners is essential for **DevSecOps** and supply chain security.

## 3. Real World Example
- An attacker gains access to a self-hosted runner VM.
- They modify the runner to log all `${{ secrets.* }}` values.
- These secrets are then leaked to an external server, compromising cloud accounts.

## 4. Exam Perspective
- Understand **risks of self-hosted runners** vs GitHub-hosted runners.
- Know **best practices**:
  - Isolate runners per repo/org.
  - Use ephemeral runners (destroy after job).
  - Limit secret exposure.
- Expect scenario questions on **runner hardening** and **least privilege**.

## 5. Interview Questions and Answers
- **Q:** What is a compromised runner?  
  **A:** A runner that has been taken over by an attacker, allowing malicious actions in workflows.  

- **Q:** How can compromised runners affect CI/CD security?  
  **A:** They can leak secrets, tamper with artifacts, or inject malicious code.  

- **Q:** How do you mitigate runner compromise risks?  
  **A:** Use ephemeral runners, isolate environments, restrict secrets, and monitor runner activity.

## 6. Common Mistakes
- Reusing long-lived runners → attackers persist across jobs.  
- Giving runners access to all secrets unnecessarily.  
- Running untrusted code on shared runners.  
- Not monitoring runner logs for anomalies.

## 7. Mental Model
Think of runners as **“temporary contractors”**:
- If compromised, they can steal company secrets or sabotage work.  
- Best practice: hire them for one job (ephemeral), then revoke access immediately.

## 8. Revision Summary
- Compromised runner = attacker-controlled execution environment.  
- Risks: secret leakage, artifact tampering, malicious code injection.  
- Mitigation: ephemeral runners, isolation, least privilege, monitoring.
