# GitHub Actions Workflow Commands

## 1. What is it?
- Workflow commands are special instructions used inside GitHub Actions workflows to interact with the runner.
- They allow workflows to set environment variables, create outputs, mask secrets, and control logging.

## 2. Why do we need it?
- Provides a way to communicate between workflow steps and the runner.
- Enables dynamic configuration during workflow execution.
- Helps manage secrets, outputs, and debugging information securely.

## 3. Real World Example
```yaml
steps:
  - name: Set environment variable
    run: echo "MY_VAR=hello" >> $GITHUB_ENV

  - name: Mask secret
    run: echo "::add-mask::super-secret-value"

  - name: Set output
    run: echo "result=success" >> $GITHUB_OUTPUT
```
`GITHUB_ENV` → sets environment variables.

`::add-mask::` → hides sensitive values in logs.

`GITHUB_OUTPUT` → defines outputs for later steps.

## 4. Exam Perspective
Key focus areas: `$GITHUB_ENV`, `$GITHUB_OUTPUT`, `$GITHUB_PATH`, masking secrets, logging commands.

Expect questions on how to pass data between steps and secure sensitive information.

## 5. Interview Questions and Answers
**Q:** What are workflow commands in GitHub Actions?
A: Special instructions that allow workflows to interact with the runner (e.g., set env variables, outputs, mask secrets).

Q: How do you set an environment variable in a workflow?
A: By writing to $GITHUB_ENV using echo "VAR=value" >> $GITHUB_ENV.

Q: How do you mask a secret in logs?
A: Using echo "::add-mask::secret-value".

## 6. Common Mistakes
Forgetting to append (>>) instead of overwrite (>), causing loss of previous values.

Misusing `::add-mask::` → secrets still exposed in logs.

Not using `$GITHUB_OUTPUT` → outputs not passed correctly between steps.

Incorrect YAML indentation → workflow fails to parse.

## 7. Mental Model
Think of workflow commands as “control levers” inside the pipeline:

`$GITHUB_ENV` → lever to set environment variables.

`$GITHUB_OUTPUT` → lever to pass results forward.

`$GITHUB_PATH` → lever to modify PATH.

`::add-mask::` → lever to hide sensitive values.
