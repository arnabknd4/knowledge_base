# Artifact Attestations

## 1. What is it?
- **Artifact attestations** are cryptographically signed metadata that describe how a build artifact was produced.
- They provide **verifiable provenance** (who built it, when, with what inputs).
- Part of GitHub’s **supply chain security** features.

## 2. Why do we need it?
- Ensures trust in build outputs by proving authenticity.
- Helps detect tampering or unauthorized modifications.
- Supports compliance with frameworks like **SLSA (Supply-chain Levels for Software Artifacts)**.
- Critical for secure CI/CD pipelines and software distribution.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      id-token: write
      attestations: write
    steps:
      - uses: actions/checkout@v3
      - run: make build
      - name: Generate artifact attestation
        uses: actions/attest-build-provenance@v1
        with:
          subject-path: ./bin/myapp
```
- This workflow generates a signed attestation for myapp binary.

## 4. Exam Perspective
- Understand attestations vs artifacts.
- Know how attestations tie into SLSA compliance.
- Be able to explain permissions required (attestations: write, id-token: write).
- Expect scenario questions on verifying provenance in pipelines.

## 5. Interview Questions and Answers
Q: What is an artifact attestation?
A: Signed metadata proving how and by whom a build artifact was created.

Q: How does GitHub Actions generate attestations?
A: Using actions/attest-build-provenance with OIDC tokens for signing.

Q: Why are attestations important for supply chain security?
A: They ensure artifacts are authentic and traceable, reducing risk of tampering.

## 6. Common Mistakes
- Forgetting to enable attestations: write permission → attestation fails.
- Confusing artifact storage with attestation metadata.
- Not verifying attestations before distribution.
- Assuming attestations replace artifact signing (they complement it).

## 7. Mental Model
- Think of artifact attestations as a “digital birth certificate”:
- Artifact = the software binary.
- Attestation = certificate proving when, how, and by whom it was created.
- Consumers can verify authenticity before trusting the artifact.

## 8. Revision Summary
- Artifact attestations = signed metadata for build provenance.
