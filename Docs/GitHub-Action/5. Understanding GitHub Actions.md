# GitHub Actions

## 1. What is it?
- GitHub Actions is a CI/CD automation platform built into GitHub.
- It allows developers to create workflows that build, test, and deploy code directly from their repositories.
- Workflows are defined in YAML files and triggered by repository events (push, pull request, issue, etc.).

## 2. Why do we need it?
- Automates repetitive tasks like testing, building, and deployment.
- Provides seamless integration with GitHub repositories.
- Reduces manual effort and ensures consistent, reliable pipelines.
- Enables faster feedback loops for developers.

## 3. Real World Example
- A team working on a microservices project uses GitHub Actions to:
  - Run unit tests on every pull request.
  - Build Docker images and push them to Azure Container Registry.
  - Deploy services to Kubernetes automatically after merging to `main`.

## 4. Exam Perspective
- **Key focus areas:** Workflow syntax (YAML), triggers (events), jobs, steps, runners (GitHub-hosted vs self-hosted).
- Expect questions on how Actions differ from other CI/CD tools, how secrets are managed, and how workflows are structured.

## 5. Interview Questions and Answers
- **Q:** What are GitHub Actions?  
  **A:** A CI/CD automation feature in GitHub that runs workflows triggered by repository events.  

- **Q:** What is the difference between GitHub-hosted and self-hosted runners?  
  **A:** GitHub-hosted runners are provided by GitHub with preinstalled tools, while self-hosted runners are managed by the user for custom environments.  

- **Q:** How do you secure workflows in GitHub Actions?  
  **A:** By using encrypted secrets, limiting permissions, and validating inputs before execution.

## 6. Common Mistakes
- Storing secrets directly in workflow files instead of GitHub Secrets.
- Overusing `workflow_dispatch` without proper automation.
- Not caching dependencies, leading to slower builds.
- Ignoring runner limitations (timeouts, resource constraints).

## 7. Mental Model
Think of GitHub Actions as a **“factory assembly line”**:
- Each event (push, PR) starts the line.
- Jobs are stations (build, test, deploy).
- Steps are tasks at each station.
- The assembly line ensures code moves smoothly from commit to deployment.

## 8. Revision Summary
- GitHub Actions = CI/CD automation inside GitHub.
- Workflows defined in YAML, triggered by repository events.
- Jobs run on runners (GitHub-hosted or self-hosted).
- Benefits: automation, integration, faster feedback, secure pipelines.
