# GitHub-hosted vs Self-hosted Runners

## 1. GitHub-hosted Runners
- **Managed by GitHub** → automatically provisioned and maintained.
- **Preconfigured environments** → Ubuntu, Windows, macOS with popular tools installed.
- **Scalable** → GitHub handles scaling and updates.
- **Best for**: general CI/CD tasks, quick setup, open-source projects.

## 2. Self-hosted Runners
- **Managed by you/organization** → installed on your own infrastructure (VMs, servers, cloud).
- **Custom environments** → full control over OS, tools, dependencies, and networking.
- **Private access** → can connect to internal systems or restricted networks.
- **Best for**: enterprise workloads, custom dependencies, specialized hardware (GPU, FPGA).

---

## 3. Comparison Table

| Feature              | GitHub-hosted Runners                  | Self-hosted Runners                     |
|----------------------|----------------------------------------|-----------------------------------------|
| **Management**       | GitHub provisions & maintains           | User/organization provisions & maintains |
| **Environment**      | Preconfigured (Ubuntu, Windows, macOS) | Fully customizable                      |
| **Scaling**          | Automatic                              | Manual (you must add/remove runners)     |
| **Networking**       | Public internet only                   | Can access private/internal networks     |
| **Cost**             | Minutes billed (included free tier)    | Your infra cost + GitHub billing minutes |
| **Use Cases**        | Standard CI/CD, open-source projects   | Enterprise builds, custom hardware, private infra |

---

## 4. Exam Perspective
- **Key focus areas:** `runs-on` keyword, differences in management, customization, and scaling.
- Expect questions on when to use self-hosted vs GitHub-hosted runners.

---

## 5. Interview Q&A
- **Q:** What is the difference between GitHub-hosted and self-hosted runners?  
  **A:** GitHub-hosted are managed by GitHub with preinstalled environments, while self-hosted are managed by the user with full customization.  

- **Q:** When should you use self-hosted runners?  
  **A:** When workflows require private infrastructure, custom dependencies, or specialized hardware.  

- **Q:** What is the advantage of GitHub-hosted runners?  
  **A:** Quick setup, automatic scaling, and preconfigured environments.

---

## 6. Mental Model
Think of runners as **workers in a factory**:
- **GitHub-hosted** → temporary workers hired by GitHub (ready-to-go, standardized).  
- **Self-hosted** → permanent staff you hire (customized for your factory’s needs).  

---

## 7. Revision Summary
- **GitHub-hosted** → managed, preconfigured, scalable, public internet only.  
- **Self-hosted** → user-managed, customizable, private infra access, manual scaling.  
- Defined in workflows using `runs-on`.
