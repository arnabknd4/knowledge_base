# Expressions in GitHub Actions

## 1. What is it?
- **Expressions** are used in GitHub Actions workflows to evaluate values dynamically.
- They allow conditional logic, string manipulation, and access to contexts, variables, and functions.
- Syntax: `${{ <expression> }}`

## 2. Why do we need it?
- Enables workflows to adapt based on runtime information.
- Allows conditional execution of jobs/steps.
- Provides flexibility by combining contexts, variables, and functions.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Conditional step
        if: ${{ github.ref == 'refs/heads/main' }}
        run: echo "This runs only on main branch"

      - name: Use expression with variable
        run: echo "Commit SHA: ${{ github.sha }}"
```
- `if`: uses an expression to run only on the main branch.
- `${{ github.sha }}` prints the commit SHA.

## 4. Exam Perspective
- Key focus areas: syntax `${{ }}`, conditional logic `(if:)`, accessing contexts (`github`, `env`, `secrets`), and built-in functions.
- Expect questions on how expressions are evaluated and where they can be used.

## 5. Interview Questions and Answers
Q: What are expressions in GitHub Actions?
A: Dynamic evaluations written as `${{ }}` that allow workflows to access contexts, variables, and functions.

Q: Where can expressions be used?
A: In workflow files for conditions `(if:)`, environment variables, outputs, and dynamic values.

Q: Give an example of using expressions for conditional execution.
A: `if: ${{ github.event_name == 'push' }}` runs a step only when the workflow is triggered by a push.

## 6. Common Mistakes
- Forgetting to wrap expressions in `${{ }}` → values not interpolated.
- Using single `=` instead of `==` in conditions.
- Misusing contexts (e.g., `github.ref` vs `github.head_ref`).
- Overcomplicating expressions instead of keeping them simple.

## 7. Mental Model
Think of expressions as “formulas” inside workflows:

- `Contexts` = data sources.
- `Variables` = values to manipulate.
- `Functions` = tools to transform data.
- `Expressions` = formulas combining them to drive workflow logic.

## 8. Revision Summary
- Expressions = dynamic evaluations in workflows.
- Syntax: `${{ }}`.
- Used in conditions, variables, outputs, and contexts.
- Key contexts: `github`, `env`, `secrets`.
