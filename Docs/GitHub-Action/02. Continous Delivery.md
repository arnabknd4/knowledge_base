# Continuous Delivery (CD)

## 1. What is it?
- Continuous Delivery (CD) is a software engineering practice where code changes are automatically prepared for release to production.
- It ensures that software can be deployed at any time with minimal manual intervention, though the final release decision may still be manual.

## 2. Why do we need it?
- Reduces risk by deploying smaller, incremental updates.
- Speeds up release cycles and improves customer feedback loops.
- Ensures production-ready builds are always available.

## 3. Real World Example
- An e-commerce company uses Azure DevOps pipelines for CD.
- After CI validates the build, CD automatically deploys the application to a staging environment.
- Once approved, the same pipeline can push the release to production with a single click.

## 4. Exam Perspective
- **Key focus areas:** Difference between CI and CD, deployment pipelines, environments (dev, test, staging, prod), rollback strategies, and automation tools.
- Expect questions on how CD improves reliability, reduces downtime, and integrates with CI.

## 5. Interview Questions and Answers
- **Q:** What is Continuous Delivery?  
  **A:** A practice where software is always in a deployable state, with automated pipelines ensuring production readiness.  

- **Q:** How is Continuous Delivery different from Continuous Deployment?  
  **A:** CD prepares code for release and may require manual approval, while Continuous Deployment automatically pushes every validated change to production.  

- **Q:** What tools support CD?  
  **A:** Jenkins, GitHub Actions, GitLab CI/CD, Azure DevOps, Spinnaker, ArgoCD.

## 6. Common Mistakes
- Confusing Continuous Delivery with Continuous Deployment.
- Lack of automated rollback or recovery strategy.
- Skipping staging/testing environments before production.
- Over-reliance on manual approvals, defeating the purpose of CD.

## 7. Mental Model
Think of CD as a **“ready-to-ship warehouse”**:
- CI builds and tests the product.
- CD ensures the product is packaged, labeled, and ready for delivery.
- The warehouse is always stocked with production-ready items.

## 8. Revision Summary
- CD = automated release pipeline ensuring production-ready builds.
- Benefits: faster releases, reduced risk, improved customer feedback.
- Tools: Jenkins, GitHub Actions, GitLab CI/CD, Azure DevOps.
- CD bridges CI and Continuous Deployment.
