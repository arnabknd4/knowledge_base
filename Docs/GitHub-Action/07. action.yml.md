# action.yml

## 1. What is it?
- `action.yml` is the metadata file that defines a **custom GitHub Action**.
- It describes how the Action behaves, its inputs, outputs, and execution environment.
- Written in **YAML format**, it is placed in the root of the Action’s repository.

## 2. Why do we need it?
- Provides a standardized way to declare what the Action does.
- Ensures portability and reusability across repositories.
- Allows developers to share Actions in the GitHub Marketplace.

## 3. Real World Example
```yaml
name: 'Hello World'
description: 'Greet someone and record the time'
inputs:
  who-to-greet:
    description: 'The person to greet'
    required: true
    default: 'World'
outputs:
  time:
    description: 'The time we greeted you'
runs:
  using: 'node16'
  main: 'index.js'
```
## 4. Exam Perspective
- Key focus areas: structure of action.yml, inputs/outputs, runs section, supported runtimes (Node.js, Docker, Composite).
- Expect questions on how to declare inputs, outputs, and execution type.

## 5. Interview Questions and Answers
**Q:** What is the purpose of action.yml?

**A:** It defines the metadata and execution details of a custom GitHub Action.

**Q:** What are the supported runs.using options?

**A:** node12, node16, docker, and composite.

**Q:** How do you define inputs and outputs in action.yml?

**A:** Using the inputs and outputs sections with descriptions, requirements, and defaults.

## 6. Common Mistakes
- Forgetting to specify runs.using → Action won’t execute.
- Misnaming inputs/outputs → workflows fail to pass values correctly.
- Not providing defaults for optional inputs.
- Mixing tabs and spaces in YAML → parsing errors.

## 7. Mental Model
- Think of action.yml as the “blueprint” of a GitHub Action:
- Inputs = parameters you pass in.
- Outputs = results you get back.
- Runs = how the Action executes.

Without the blueprint, the Action cannot be built or shared.
