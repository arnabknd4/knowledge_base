# Reusing Workflow Configurations in GitHub Actions

## 1. What is it?
- Reusing workflow configurations means creating **modular, shareable workflows** that can be invoked by other workflows.
- GitHub Actions supports **reusable workflows** via the `workflow_call` trigger.
- This allows teams to centralize CI/CD logic and avoid duplication across repositories.

## 2. Why do we need it?
- Promotes **DRY (Don’t Repeat Yourself)** principles in CI/CD pipelines.
- Simplifies maintenance by updating logic in one place.
- Enables consistency across multiple repositories or projects.
- Improves collaboration by sharing common workflows.

## 3. Real World Example
### Reusable Workflow (`.github/workflows/reusable.yml`)
```yaml
name: Reusable Build Workflow
on:
  workflow_call:
    inputs:
      node-version:
        required: true
        type: string

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: ${{ inputs.node-version }}
      - run: npm install && npm test
```
Caller Workflow (`.github/workflows/main.yml`)
The caller workflow invokes the reusable workflow with parameters.

## 4. Exam Perspective
- Key focus areas: `workflow_call trigger`, passing `inputs/outputs`, modular design.
- Expect questions on how reusable workflows differ from composite actions.
- Know how to structure workflows for cross-repo usage.

## 5. Interview Questions and Answers
Q: What is a reusable workflow in GitHub Actions?
A: A workflow defined with workflow_call that can be invoked by other workflows.

Q: How do reusable workflows differ from composite actions?
A: Composite actions reuse steps, while reusable workflows reuse entire workflows with jobs.

Q: Can reusable workflows accept inputs?
A: Yes, inputs can be defined in the workflow_call section and passed by the caller.

## 6. Common Mistakes
- Forgetting to use `workflow_call` → `workflow` cannot be reused.
- Misplacing reusable workflows outside `.github/workflows/`.
- Not defining required inputs → caller workflow fails.
- Confusing composite actions with reusable workflows.

## 7. Mental Model
- Think of reusable workflows as “plug-and-play modules”:
- Composite actions = reusable steps.
- Reusable workflows = reusable pipelines.
- Caller workflows = projects that plug into these modules.
