# Variables in GitHub Actions

## 1. What is it?
- **Variables** in GitHub Actions are values that can be reused across workflows, jobs, and steps.
- They include **environment variables**, **default variables**, and **custom variables** defined by the user.

## 2. Why do we need it?
- Simplifies workflows by avoiding hardcoding values.
- Makes workflows flexible and reusable.
- Allows dynamic configuration based on runtime information.

## 3. Real World Example
```yaml
name: Example Workflow
on: [push]

jobs:
  build:
    runs-on: ubuntu-latest
    env:
      NODE_ENV: production
      APP_NAME: my-app
    steps:
      - name: Print variables
        run: echo "Environment: $NODE_ENV, App: $APP_NAME"
```
`NODE_ENV` and `APP_NAME` are environment variables accessible in steps.

## 4. Exam Perspective
- Key focus areas: difference between `env`, `secrets`, and `contexts`.
- Expect questions on how to define variables at workflow, job, and step levels.

## 5. Interview Questions and Answers
Q: How do you define variables in GitHub Actions?
A: Using the env keyword at workflow, job, or step level.

Q: What is the difference between env and secrets?
A: env stores non-sensitive values, while secrets securely store sensitive values like tokens.

Q: Can variables be overridden?
A: Yes, variables defined at the step level override job-level variables.

## 6. Common Mistakes
- Hardcoding values instead of using variables.
- Storing sensitive data in env instead of secrets.
- Forgetting variable scope (workflow vs job vs step).

Misusing contexts `(github.ref)` as plain strings without `${{ }}`.

## 7. Mental Model
- Think of variables as “labels on containers”:
- Workflow-level variables = global labels.
- Job-level variables = labels for one assembly line.
- Step-level variables = labels for a single task.

## 8. Revision Summary
- Variables = reusable values in workflows.
- Defined using env keyword.
- Scope: workflow → job → step.
- Use secrets for sensitive values.
- Variables make workflows flexible, secure, and reusable.

# Contexts in GitHub Actions

## 1. What is it?
- **Contexts** are special variables in GitHub Actions that provide information about workflow runs, jobs, steps, and environment.
- They allow workflows to access metadata dynamically (e.g., branch name, commit SHA, event type).

## 2. Why do we need it?
- Enables workflows to adapt based on runtime information.
- Provides secure access to secrets and environment variables.
- Helps in conditional logic (`if:` statements) and dynamic configuration.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Print branch name
        run: echo "Branch: ${{ github.ref }}"

      - name: Use secret
        run: echo "Token: ${{ secrets.MY_TOKEN }}"
```
`github.ref` → gives the branch or tag reference.
`secrets.MY_TOKEN` → securely accesses a stored secret.

## 4. Exam Perspective
Key focus areas: common contexts (`github`, `env`, `secrets`, `runner`, `job`, `steps`).

Expect questions on how contexts are used in conditional logic and secure workflows.

## 5. Interview Questions and Answers
Q: What are contexts in GitHub Actions?
A: Special variables that provide metadata and runtime information to workflows.

Q: Name some commonly used contexts.
A: `github`, `env`, `secrets`, `runner`, `job`, `steps`.

Q: How do you access a secret in a workflow?
A: Using `${{ secrets.SECRET_NAME }}`.

## 6. Common Mistakes
Forgetting to wrap contexts in ${{ }} → values not interpolated.

Using secrets directly in logs → exposes sensitive data.

Misusing `github.ref` without parsing → includes full refs/heads/branch.

Confusing env context with secrets.

## 7. Mental Model
Think of contexts as “information dashboards”:

- `github` → repository and event info.
- `env` → environment variables.
- `secrets` → secure values.
- `runner` → machine details.
- `job/steps` → workflow execution details.

## 8. Revision Summary
- Contexts = metadata variables in GitHub Actions.
- Syntax: `${{ context.variable }}`.
- Common contexts: `github`, `env`, `secrets`, `runner`, `job`, `steps`.
- Used for dynamic workflows, conditional logic, and secure automation.
