# GitHub Actions Overview

GitHub Actions is GitHub’s built-in **CI/CD and automation platform** that lets you build, test, and deploy code directly from your repository. It is event-driven, meaning workflows trigger automatically when specific repository events occur—such as code pushes, pull requests, or issue creation.

Workflows are defined using YAML files stored inside the `.github/workflows/` directory. They run either on **GitHub-hosted runners** (Linux, Windows, macOS) or **self-hosted runners** tailored for custom environments.

---

## Core Components

* **Events:** Triggers that start a workflow (e.g., `push`, `pull_request`, `schedule`).
* **Workflows:** Configurable automated processes containing one or more jobs.
* **Jobs:** Sequences of steps executed on the same runner; jobs can execute sequentially or in parallel.
* **Steps:** Individual tasks within a job, executing either shell commands or reusable actions.
* **Actions:** Standalone, reusable automation units sourced from the GitHub Marketplace or custom code.
* **Runners:** Dedicated servers that execute your workflow jobs.

---

## Example Workflow

```yaml
# .github/workflows/ci.yml
name: CI Pipeline

on:
  push:
    branches: ["main"]
  pull_request:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20
      - name: Install dependencies
        run: npm ci
      - name: Run tests
        run: npm test

```
## Execution Breakdown

* **Triggers:** Fires on code pushes or pull requests targeting the `main` branch.
* **Environment:** Allocates an `ubuntu-latest` runner.
* **Tasks:** Checks out repository code, sets up Node.js v20, installs dependencies with `npm ci`, and executes the test suite.

---

## Advanced Features

* **Matrix Builds:** Run job variations across multiple operating systems and language versions in parallel.
* **Secrets Management:** Encrypt and store sensitive values securely via `secrets.YOUR_KEY`.
* **Caching:** Speed up execution times by caching package manager dependencies between runs.
* **Reusable Workflows:** Modularize and share common workflow logic across multiple repositories.
* **Self-Hosted Runners:** Run jobs on your own hardware for private network access or cost management.

---

## Key Use Cases

* Automated CI/CD deployment pipelines for applications and packages.
* Automated code linting, formatting, and PR reviews.
* Scheduled repository maintenance and cron jobs.
* Automated security scanning and dependency updating (e.g., Dependabot).
* Continuous deployment to cloud infrastructure or GitHub Pages.
