# Script Injections

## 1. What is it?
- **Script injection** is a security vulnerability where malicious code is inserted into a trusted application or workflow.
- Common forms include **Cross-Site Scripting (XSS)**, **SQL Injection**, and **Command Injection**.
- In GitHub Actions, script injection can occur if untrusted input is passed directly into shell commands or workflow steps.

## 2. Why do we need to understand it?
- Script injections can lead to:
  - Unauthorized access to systems.
  - Data theft or corruption.
  - Compromise of CI/CD pipelines.
- Preventing injections is essential for **DevSecOps** and secure software delivery.

## 3. Real World Example
```yaml
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - name: Unsafe example
        run: echo "Deploying ${{ github.event.inputs.env }}"
```
- If env input is not validated, an attacker could inject malicious shell commands.

## 4. Exam Perspective
- Know the types of injection attacks (XSS, SQL, Command).
- Understand secure coding practices:
- Input validation.
- Escaping/quoting variables.
- Using parameterized queries.
- Expect scenario questions on how to mitigate injection risks in workflows.

## 5. Interview Questions and Answers
Q: What is script injection?
A: A vulnerability where malicious code is injected into a trusted application or workflow.

Q: How can script injection occur in GitHub Actions?
A: By passing untrusted inputs directly into shell commands without sanitization.

Q: How do you prevent script injection?
A: Validate inputs, escape variables, use safe APIs, and avoid direct command concatenation.

## 6. Common Mistakes
- Directly interpolating user input into shell commands.
- Assuming GitHub Actions inputs are always safe.
- Logging sensitive variables without sanitization.
- Not applying least privilege principles in workflows.

## 7. Mental Model
- Think of script injection as a “Trojan horse”:
- You expect safe input (a gift).
- Hidden inside is malicious code (the attacker’s payload).
- If unchecked, it executes with your system’s trust.

## 8. Revision Summary
- Script injection = malicious code inserted into trusted workflows.
- Types: XSS, SQL Injection, Command Injection.
- Prevent with input validation, escaping, parameterization, and least privilege.
- Critical for secure CI/CD and DevSecOps practices.
