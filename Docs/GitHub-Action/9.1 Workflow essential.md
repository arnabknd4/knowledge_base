

## 1. Top-Level Workflow Essentials
These keys define the entire workflow file (`.github/workflows/*.yml`).

* **`name:`** *(Optional, but essential for real projects)* — Sets the readable display name in the GitHub Actions UI tab.
* **`run-name:`** *(Exam & Real-World)* — Sets the dynamic name of the workflow execution using contexts (e.g., `run-name: Deploy to ${{ inputs.environment }} by @${{ github.actor }}`).
* **`on:`** *(MANDATORY)* — Specifies the triggers for the workflow.
  * **Push/Pull Request:** `on: [push, pull_request]`
  * **Branch Filtering:** `on: push: branches: [main, 'releases/**']`
  * **Schedule (Cron):** `on: schedule: - cron: '0 0 * * *'`
  * **Manual Trigger:** `on: workflow_dispatch: inputs: ...`
  * **Called by another workflow:** `on: workflow_call:`
* **`env:`** — Sets global environment variables accessible by all jobs in the workflow.
* **`permissions:`** *(Exam heavy)* — Sets the scopes granted to the automatically generated `GITHUB_TOKEN` (e.g., `permissions: { contents: read, packages: write }`).
* **`concurrency:`** — Prevents duplicate parallel runs on the same branch or ref (e.g., `concurrency: group-1, cancel-in-progress: true`).

## 2. Job-Level Syntax (`jobs.<job_id>`)
Jobs run in parallel by default on separate runners.

* **`runs-on:`** *(MANDATORY)* — Defines the execution environment/runner type (e.g., `ubuntu-latest`, `windows-latest`, `macos-latest`, or `[self-hosted, linux]`).
* **`needs:`** — Establishes job dependencies to run jobs sequentially instead of in parallel (e.g., `needs: [build, test]`).
* **`if:`** — Conditional expression controlling whether the job runs (e.g., `if: github.ref == 'refs/heads/main'`).
* **`strategy.matrix:`** *(High Exam Focus)* — Spawns multiple job variants across different operating systems or language versions.
  * **Exam keys:** `include`, `exclude`, `fail-fast: false`, `max-parallel`.
* **`environment:`** — Targets a deployment environment (enables protection rules, required reviewers, and environment secrets).
* **`defaults.run:`** — Defines default shell and working directory settings for all run steps inside the job.
* **`services:`** — Spins up docker sidecar containers (e.g., Redis, PostgreSQL) needed during job steps.

---

## 3. Step-Level Syntax (`jobs.<job_id>.steps[*]`)
Steps run sequentially inside the same runner and share the same filesystem.

* **`uses:`** — Executes a pre-packaged Action from the Marketplace or local path.
  * **Marketplace:** `uses: actions/checkout@v4`
  * **Local composite action:** `uses: ./.github/actions/my-action`
  * **Docker hub:** `uses: docker://alpine:3.8`
* **`run:`** — Runs inline command-line shell scripts.
* **`name:`** — Descriptive text displayed in the GitHub UI log console.
* **`with:`** — Map of input parameters required by an action invoked with `uses`.
* **`env:`** — Step-scoped environment variables overriding higher-level ones.
* **`id:`** — Unique step identifier used to capture outputs in subsequent steps (e.g., `${{ steps.my_step.outputs.my_var }}`).
* **`continue-on-error:`** — Forces the job to proceed even if this step fails.
* **`timeout-minutes:`** — Prevents runaway jobs from exhausting your runner quota.

---

## 4. Expressions & Contexts (Must-Know Syntax)
Expressions are written inside `${{ ... }}` to access runtime context.

### Core Contexts
* `${{ github.sha }}`, `${{ github.ref }}`, `${{ github.actor }}` — Repository metadata
* `${{ secrets.MY_SECRET }}` — Encrypted repository/environment secrets
* `${{ vars.MY_VAR }}` — Plaintext variables
* `${{ inputs.my_param }}` — Inputs from manual or reusable workflows
* `${{ env.MY_ENV }}` — Variables set at workflow, job, or step levels

### Status Functions
* `if: success()` — *(Default)*
* `if: failure()` — Triggers on step/job failure
* `if: always()` — Executes no matter what, ideal for cleanup
* `if: cancelled()` — Executes if the workflow run was manually aborted

# 5. Cheat Sheet Syntax Example
``` yaml
name: Production Deployment Pipeline
run-name: Deploying ${{ github.sha }} by @${{ github.actor }}

on:
  push:
    branches: ["main"]
  workflow_dispatch:
    inputs:
      environment:
        type: choice
        description: Choose Target
        options: [staging, production]
        default: staging

permissions:
  contents: read
  id-token: write

env:
  NODE_VERSION: '20'

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, windows-latest]
    steps:
      - uses: actions/checkout@v4
      
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: ${{ env.NODE_VERSION }}

      - name: Run Tests
        run: npm ci && npm test

  deploy:
    needs: [test]
    runs-on: ubuntu-latest
    environment: production
    if: github.ref == 'refs/heads/main' && success()
    steps:
      - name: Deploy Step
        run: echo "Deploying using secret ${{ secrets.DB_PASSWORD }}"

```
