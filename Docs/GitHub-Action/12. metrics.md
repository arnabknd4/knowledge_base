# GitHub Actions Metrics

## 1. What is it?
- Metrics in GitHub Actions provide **insights into workflow usage and performance**.
- Two main categories:
  - **Usage Metrics** → track minutes consumed, runner types, OS usage.
  - **Performance Metrics** → track run times, queue times, and failure rates.

## 2. Why do we need it?
- Helps organizations:
  - **Optimize workflows** for efficiency.
  - **Control costs** by monitoring minutes usage.
  - **Identify bottlenecks** in CI/CD pipelines.
  - **Improve reliability** by analyzing failure rates.

## 3. Real World Example
- **Usage Metrics**:
  - Minutes consumed per workflow/job.
  - Breakdown by runner type (GitHub-hosted vs self-hosted).
  - OS usage statistics.
- **Performance Metrics**:
  - Average job run time.
  - Queue time before job starts.
  - Workflow failure rates.

## 4. Exam Perspective
- Know difference between **usage vs performance metrics**.
- Understand **permissions required** to view metrics:
  - Org level → only owners or users with “View organization Actions metrics” role.
  - Repo level → base repository role users.
- Be able to explain how metrics help optimize CI/CD pipelines.

## 5. Interview Questions and Answers
- **Q:** What are GitHub Actions metrics?  
  **A:** Insights into workflow usage (minutes consumed) and performance (run times, queue times, failure rates).  

- **Q:** Why are they important?  
  **A:** They help organizations optimize workflows, control costs, and improve reliability.  

- **Q:** How do you access them?  
  **A:** Via the Insights tab at org/repo level, with appropriate permissions.

## 6. Common Mistakes
- Confusing usage metrics (cost tracking) with performance metrics (efficiency).  
- Ignoring queue times → underestimating bottlenecks.  
- Not restricting access → sensitive usage data exposed.  
- Assuming metrics include detailed logs (they are aggregated snapshots only).

## 7. Mental Model
Think of GitHub Actions metrics as **“health reports for CI/CD pipelines”**:
- Usage metrics = billing and resource consumption.  
- Performance metrics = efficiency and reliability checks.  
- Together, they ensure workflows are cost‑effective and performant.

## 8. Revision Summary
- Two types: **Usage (minutes, costs)** & **Performance (run times, queue times, failures)**.  
- Access controlled by org/repo permissions.  
- Viewed via **Insights → Actions Metrics** tabs.  
- Purpose: optimize workflows, control costs, improve reliability.
