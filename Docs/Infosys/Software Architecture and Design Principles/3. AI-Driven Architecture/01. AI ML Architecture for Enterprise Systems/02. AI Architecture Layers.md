# AI Architecture Layers
## 1. What is it?
- A multi‑layered design framework organizing all components required to build, deploy, and manage AI/ML solutions in enterprise environments.  
- Core Infosys concept: each layer ensures data flow, model lifecycle, scalability, and governance.

## 2. Why do we need it?
- Provides structure for embedding AI into enterprise systems.  
- Ensures clean data, accurate models, scalable deployment, and trustworthy governance.  
- Enables continuous improvement and compliance in AI adoption.

## 3. Core Exam Focus
- Layers: Data, Model Development, Deployment, Monitoring & Governance.  
- Situational traps: ignoring data quality, skipping monitoring, or treating deployment as one‑time.  
- Keywords: ETL, APIs, microservices, Kubernetes, SHAP/LIME, model drift.

## 4. Real‑World Use Case
- Enterprise retail personalization:  
  - Data Layer → unified customer data from ERP/CRM.  
  - Model Development → ML recommendation engine trained on purchase history.  
  - Deployment → microservices + APIs integrated with e‑commerce.  
  - Monitoring → bias detection + retraining for accuracy.  
  - Outcome → real‑time personalized shopping experience.

## 5. Interview Lens
- Q: Why is the data layer critical in AI architecture?  
  A: Poor data quality leads to inaccurate predictions; clean, governed data ensures reliable models.  
- Q: How do monitoring tools like SHAP/LIME support governance?  
  A: They provide explainability, fairness audits, and compliance transparency.

## 6. Common Mistakes
- Treating AI as only model development without deployment or monitoring.  
- Ignoring data governance, leading to compliance risks.  
- Overlooking scalability in deployment pipelines.  
- Failing to retrain models when drift occurs.

## 7. Mental Model
- Analogy: **“AI Factory”** — Data = raw materials, Model Development = assembly line, Deployment = distribution, Monitoring = quality control.  
- Mnemonic: **“DMDM → Data, Model, Deployment, Monitoring.”**

## 8. Revision Summary
- AI architecture = layered design for enterprise AI/ML.  
- Data Layer → acquisition, storage, pipelines, governance.  
- Model Development → frameworks, training, validation.  
- Deployment → serving, APIs, microservices, CI/CD.  
- Monitoring & Governance → drift detection, explainability, compliance.  
- Exam trap → focusing only on models, ignoring lifecycle.
