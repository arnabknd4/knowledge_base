# 📘 System Design Note – Snapshot Architecture

## 1. Topic Name
Snapshot Architecture

## 2. What is it?
- A **snapshot** is a point-in-time copy of data (e.g., VM disk, database, file system).  
- It captures the state instantly without duplicating the entire dataset.

## 3. Why did it evolve?
- Traditional backups were slow and resource-heavy.  
- Snapshots evolved to provide **fast recovery** and **minimal downtime**.  
- Triggered by the need for **high availability** in modern distributed systems.

## 4. Core Theory
- **Copy-on-Write (CoW)** or **Redirect-on-Write (RoW)** mechanisms.  
- Trade-offs:  
  - ✅ Fast creation vs. ⚠️ Storage overhead.  
  - ✅ Instant restore vs. ⚠️ Performance impact during writes.  
- Often integrated into cloud storage (Azure, AWS, GCP).

## 5. Key Points to Remember
- 🔑 Snapshots are incremental, not full copies.  
- ✅ Best for short-term recovery and rollback.  
- ⚠️ Not a replacement for long-term archival backups.

## 6. Mental Model
Think of a snapshot as a **camera photo**:  
- You freeze the moment (data state).  
- Future changes don’t alter the photo, but you can revert to it.

## 7. Real-World Example
- **AWS EBS Snapshots**: Incremental backups of block storage.  
- **Azure VM Snapshots**: Used for quick restore or migration.  
- **Kubernetes VolumeSnapshots**: Enable stateful app recovery.

## 8. Exam Preparation
- Typical cloud exam question:  
  *“What’s the difference between snapshot and backup in Azure?”*  
- MCQ fact check:  
  - Snapshots = point-in-time, short-term.  
  - Backups = policy-driven, long-term.  
- RFC/Standard: Storage snapshot mechanisms (vendor-specific).

## 9. Interview Perspective
- Common question: *“Explain snapshot vs. backup trade-offs.”*  
- Whiteboard prompt: Draw snapshot layers (base disk + delta changes).  
- Talking point: Snapshots are **fast but temporary**.

## 10. Revision Summary
- Snapshots = point-in-time copies.  
- Fast, incremental, short-term recovery.  
- Not a substitute for archival backups.  
- Used in cloud + container ecosystems.

## 11. Common Mistakes
- ❌ Assuming snapshots = backups.  
- ❌ Keeping snapshots indefinitely (storage bloat).  
- ❌ Ignoring performance impact during heavy writes.

## 12. Related Topics
- Backups → Archival storage.  
- Replication → High availability.  
- Disaster Recovery → Snapshots + backups + geo-redundancy.
