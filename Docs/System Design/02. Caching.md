# 📘 System Design Note – Caching

## 1. Topic Name
Caching

## 2. What is it?
- A **cache** is a temporary storage layer that holds frequently accessed data for faster retrieval.  
- It reduces latency by serving data from memory or a closer location instead of recomputing or fetching from the source.

## 3. Why did it evolve?
- Early systems suffered from slow disk I/O and network calls.  
- Caching evolved to improve **performance and scalability**.  
- Triggered by the need for **low-latency responses** in web apps, APIs, and distributed systems.

## 4. Core Theory
- **Principles:** Temporal locality (recently used data is likely reused), Spatial locality (nearby data is likely accessed).  
- **Trade-offs:**  
  - ✅ Speed vs. ⚠️ Freshness (stale data risk).  
  - ✅ Reduced load vs. ⚠️ Memory overhead.  
- Common strategies: LRU (Least Recently Used), LFU (Least Frequently Used), Write-through, Write-back.

## 5. Key Points to Remember
- 🔑 Cache = speed booster, not a database.  
- ✅ Use eviction policies (LRU, LFU).  
- ⚠️ Beware of stale data and cache stampede.

## 6. Mental Model
Think of a cache as a **fridge**:  
- Frequently used items (milk, eggs) are kept handy.  
- Rarely used items stay in the pantry (database).  
- Saves time but needs restocking (cache invalidation).

## 7. Real-World Example
- **Netflix**: Uses caching for video metadata and recommendations.  
- **Amazon**: Caches product details to handle millions of requests.  
- **Google**: DNS caching reduces repeated lookups.

## 8. Exam Preparation
- Cloud exams often ask: *“Difference between cache and database?”*  
- MCQ fact check:  
  - Cache = temporary, fast, volatile.  
  - Database = persistent, reliable, slower.  
- Standards: HTTP caching headers (ETag, Cache-Control).

## 9. Interview Perspective
- Common question: *“Explain cache invalidation strategies.”*  
- Whiteboard prompt: Draw request flow → Cache → DB fallback.  
- Talking point: Trade-off between **consistency vs. performance**.

## 10. Revision Summary
- Cache = temporary fast storage.  
- Improves latency and throughput.  
- Needs eviction + invalidation strategies.  
- Not a replacement for persistence.

## 11. Common Mistakes
- ❌ Treating cache as the source of truth.  
- ❌ Forgetting invalidation → stale data.  
- ❌ Over-caching → memory bloat.  
- ❌ Ignoring cache stampede (many requests missing cache simultaneously).
