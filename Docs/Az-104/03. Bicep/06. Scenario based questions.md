# Interview Questions on Azure Bicep & ARM Templates

## 1. Conceptual / Design Questions
- **Q:** Why did Microsoft introduce Bicep when ARM templates already existed?  
  *A:* ARM JSON is verbose and hard to maintain. Bicep provides a concise DSL that compiles into ARM JSON, making IaC easier to author and modular.

- **Q:** How does Bicep improve developer productivity compared to ARM templates?  
  *A:* IntelliSense, type safety, modules, and cleaner syntax reduce errors and speed up authoring.

- **Q:** What are the trade‑offs between using Bicep and Terraform?  
  *A:* Bicep is Azure‑native with day‑zero support for new resources. Terraform is multi‑cloud but may lag in Azure resource support.

---

## 2. Practical / Hands‑On Questions
- **Q:** Show me how to deploy a VM using Bicep.  
  *A:* Write a `.bicep` file with parameters for `vmName`, `location`, `vmSize`, then deploy using `az deployment group create --template-file main.bicep`.

- **Q:** How do you convert an ARM template to Bicep?  
  *A:* Use `bicep decompile template.json`.

- **Q:** How do you validate a Bicep file before deployment?  
  *A:* Run `az deployment group validate --template-file main.bicep`.

---

## 3. Governance / Security Questions
- **Q:** How would you secure secrets in a Bicep deployment?  
  *A:* Store secrets in Key Vault, reference them in parameters, and restrict access via RBAC.

- **Q:** How do you enforce compliance across multiple environments using Bicep?  
  *A:* Use Azure Policy definitions and parameterize resource configurations to ensure consistent deployments.

---

## 4. Failure / Scenario Questions
- **Q:** What happens if you deploy a template in **Complete mode**?  
  *A:* Resources not defined in the template are deleted — risky if misused.

- **Q:** How do you handle dependencies between resources in Bicep?  
  *A:* Use `dependsOn` or implicit dependencies when referencing other resources.

- **Q:** What’s the impact of deploying subscription‑level resources at resource group scope?  
  *A:* Deployment fails due to incorrect scope — exam and interview trap.

---

## 5. Cost / Optimization Questions
- **Q:** How do you optimize cost in multi‑region deployments with Bicep?  
  *A:* Parameterize SKU tiers, use conditions to deploy only required resources, and apply tags for cost tracking.

- **Q:** How do you reuse Bicep code across projects?  
  *A:* Use **modules** for reusable patterns (e.g., AKS cluster, VNet, SQL DB).

---

# Scenario‑Based Interview Questions on Bicep & ARM

## 1. Multi‑Tenant Security
- **Q:** How would you secure an AKS cluster in a multi‑tenant setup using Bicep?  
  *A:* Parameterize RBAC roles, integrate Azure AD for identity, and use Key Vault for secret management. Apply Azure Policy modules to enforce compliance across tenants.

---

## 2. Disaster Recovery
- **Q:** How would you design a Bicep template for disaster recovery across regions?  
  *A:* Parameterize `location` and `replication` settings, use modules for geo‑redundant storage, and deploy paired resources in secondary regions. Outputs can expose failover endpoints.

---

## 3. Cost Optimization
- **Q:** How do you optimize cost when deploying databases with Bicep?  
  *A:* Parameterize SKU tiers, enable auto‑pause for serverless SQL, and use conditional logic to deploy only required replicas. Apply tags for cost tracking.

---

## 4. Governance & Compliance
- **Q:** How would you enforce compliance using ARM/Bicep?  
  *A:* Deploy Azure Policy definitions via Bicep modules, restrict resource SKUs, enforce naming conventions with variables, and ensure diagnostic settings are enabled by default.

---

## 5. Failure Scenarios
- **Q:** What happens if you deploy a template in Complete mode?  
  *A:* Resources not defined in the template are deleted — risky if misused. Incremental mode is safer for additive deployments.

- **Q:** How do you handle dependencies between resources?  
  *A:* Use `dependsOn` explicitly or rely on implicit references (e.g., referencing a resource ID automatically creates a dependency).

---

## 6. Hybrid Connectivity
- **Q:** How would you use Bicep to deploy hybrid connectivity resources?  
  *A:* Parameterize VPN Gateway or ExpressRoute settings, define subnets and NSGs, and modularize connectivity patterns for reuse across environments.

---

## 7. Observability
- **Q:** How do you ensure observability in a Bicep deployment?  
  *A:* Include diagnostic settings in resources, send logs to Log Analytics, and parameterize workspace IDs. Use outputs to expose monitoring endpoints.

---

## 8. Migration & Legacy
- **Q:** What happens to existing ARM templates when adopting Bicep?  
  *A:* They remain valid. You can decompile ARM JSON into Bicep (`bicep decompile`) and continue using them alongside new Bicep files.

---

## ✅ Flashcard Recap

- Disaster recovery → multi‑region, replication, failover outputs.  
- Cost optimization → parameterize SKUs, conditional logic, tags.

- Failure scenarios → Complete vs Incremental, dependencies.

# Full Interview Q&A Bank – Azure Admin / Architect / DevOps

## 1. Bicep & ARM
- **Q:** What’s the difference between Incremental and Complete deployment modes?  
  *A:* Incremental adds/updates resources without deleting existing ones. Complete deletes resources not defined in the template — risky if misused.  

- **Q:** How do you reuse Bicep code across projects?  
  *A:* Use modules for reusable patterns (e.g., AKS cluster, VNet, SQL DB).  

---

## 2. Governance & Security
- **Q:** How do you enforce compliance in Azure?  
  *A:* Use Azure Policy definitions, parameterize resource SKUs, enforce naming conventions, and enable diagnostic settings by default.  

- **Q:** Difference between RBAC and Azure Policy?  
  *A:* RBAC controls *who* can perform actions. Policy controls *what* resources can be deployed/configured.  

- **Q:** How do you secure secrets in deployments?  
  *A:* Store secrets in Key Vault, reference them in templates, and restrict access via RBAC and Managed Identities.  

---

## 3. High Availability & Disaster Recovery
- **Q:** How do you design for high availability in Azure?  
  *A:* Use Availability Zones/Sets, multi‑region deployments with Traffic Manager or Front Door, and geo‑redundant storage.  

- **Q:** How would you design a Bicep template for disaster recovery?  
  *A:* Parameterize location and replication, deploy paired resources in secondary regions, and expose failover endpoints via outputs.  

---

## 4. Networking & Hybrid Connectivity
- **Q:** How do you connect on‑premises to Azure?  
  *A:* Use VPN Gateway for secure tunnels or ExpressRoute for private dedicated connections.  

- **Q:** How do you secure VNets?  
  *A:* Use NSGs, Azure Firewall, and parameterize subnet CIDRs for flexibility.  

---

## 5. Cost Optimization
- **Q:** How do you optimize cost in Azure?  
  *A:* Use Reserved Instances, Auto‑Scaling, Advisor recommendations, and apply tags for chargeback.  

- **Q:** How do you optimize cost in multi‑region deployments with Bicep?  
  *A:* Parameterize SKU tiers, use conditions to deploy only required resources, and apply tags for cost tracking.  

---

## 6. Observability & Monitoring
- **Q:** Difference between Azure Monitor and Log Analytics?  
  *A:* Monitor = collects metrics/logs. Log Analytics = query engine for deep analysis.  

- **Q:** How do you ensure observability in a Bicep deployment?  
  *A:* Include diagnostic settings, send logs to Log Analytics, and parameterize workspace IDs.  

---

## 7. DevOps & CI/CD
- **Q:** Difference between Azure DevOps and GitHub Actions?  
  *A:* DevOps = enterprise CI/CD with boards, repos, pipelines. GitHub Actions = lightweight CI/CD integrated with GitHub repos.  

- **Q:** How do you integrate Bicep into CI/CD?  
  *A:* Use Azure CLI tasks in pipelines (`az deployment group create`), validate templates, and modularize deployments.  

---

## 8. Failure & Scenario Questions
- **Q:** What happens if you deploy subscription‑level resources at RG scope?  
  *A:* Deployment fails due to incorrect scope.  

- **Q:** How do you handle dependencies between resources in Bicep?  
  *A:* Use `dependsOn` or implicit references (resource IDs).  

---

## 9. Migration & Legacy
- **Q:** What happens to existing ARM templates when adopting Bicep?  
  *A:* They remain valid. You can decompile ARM JSON into Bicep (`bicep decompile`).  

- **Q:** How do you migrate legacy deployments to modern IaC?  
  *A:* Export ARM templates, decompile to Bicep, modularize, and integrate into CI/CD pipelines.
