# Azure Bicep

## 1. What is it?
Bicep is a declarative language for deploying Azure resources.  
It compiles into ARM templates but is far easier to read, write, and maintain.

## 2. Why do we need it?
- Ensures consistent deployments across environments (governance & security).  
- Supports modularization and reusability for enterprise‑scale IaC.  
- Future‑proof: instantly supports all new Azure resource types and API versions.

## 3. Core Exam Focus
- Key features: parameters, variables, loops, conditions, modules, deployment scopes.  
- CLI/PowerShell: `az deployment group create --template-file main.bicep`  
- Common traps: wrong scope (RG vs subscription), misuse of parameter files, JSON vs Bicep confusion.

## 4. Real‑World Use Case
Multi‑region deployment of AKS clusters with Key Vault integration:  
- Use Bicep modules to define reusable AKS + Key Vault patterns.  
- Deploy across multiple regions with parameterized location values.  
- Enforce compliance by embedding RBAC and policy definitions.

## 5. Interview Lens
- **Q1:** How would you secure secrets in a Bicep deployment?  
  *Use Key Vault references in parameters and restrict access via RBAC.*  
- **Q2:** What’s the trade‑off between JSON ARM templates and Bicep?  
  *JSON is verbose but universally supported; Bicep is concise, modular, but requires compilation.*  
- **Q3:** How do you optimize cost in multi‑region deployments with Bicep?  
  *Parameterize SKU tiers and use conditional logic to deploy only required resources.*

## 6. Common Mistakes
- Misconfiguring deployment scope (e.g., subscription‑level resources at RG scope).  
- Overlooking dependencies between resources.  
- Wrong defaults (e.g., storage account replication set incorrectly).

## 7. Mental Model
Think of Bicep as **“Lego blocks for Azure infrastructure.”**  
Each resource is a block; modules are sets of blocks; parameters are connectors that let you reuse and rearrange them consistently.

## 8. Revision Summary
- Declarative IaC language → compiles to ARM JSON.  
- Concise syntax, type safety, IntelliSense in VS Code.  
- Supports all Azure resource types instantly.  
- Exam focus: parameters, loops, modules, scopes.  
- Real‑world: multi‑region, compliance, automation.  
- Common trap: wrong scope or overlooked dependencies.
