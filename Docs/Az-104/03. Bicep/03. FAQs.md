# Azure Bicep – Common Questions

## 1. Why create a new language instead of using an existing one?
- ARM JSON templates are verbose and hard to maintain.  
- Bicep was designed as a **domain‑specific language (DSL)** to simplify Azure IaC, with concise syntax, type safety, and IntelliSense support.  
- Existing languages (like JSON or YAML) lacked deep integration with Azure’s resource model.

---

## 2. Why not focus energy on Terraform or other third‑party IaC offerings?
- Terraform is excellent for **multi‑cloud** scenarios, but Microsoft needed a **first‑party tool** tightly integrated with Azure Resource Manager.  
- Bicep ensures **day‑zero support** for new Azure resources and features, something third‑party tools often lag behind on.  
- It complements, not replaces, Terraform — architects can choose based on scope (single‑cloud vs multi‑cloud).

---

## 3. Is this ready for production use?
- Yes. Bicep is **production‑ready** and fully supported by Microsoft.  
- It compiles into ARM JSON, so deployments are as reliable as ARM templates.  
- Enterprises already use Bicep for large‑scale deployments with modules and CI/CD pipelines.

---

## 4. Is Bicep only for Azure?
- Correct. Bicep is **Azure‑specific** because it compiles into ARM JSON, which is consumed by Azure Resource Manager.  
- For multi‑cloud, tools like Terraform or Pulumi are better suited.

---

## 5. Can I use Bicep to deploy to Azure Stack Hub?
- Yes, but with limitations.  
- Bicep supports Azure Stack Hub **only for resources available in ARM API profiles**.  
- If a resource type isn’t supported in Azure Stack Hub’s API version, Bicep cannot deploy it.

---

## 6. What happens to my existing ARM templates?
- They remain fully valid and supported.  
- You can **decompile ARM JSON into Bicep** using `bicep decompile`.  
- Existing ARM templates can continue to run, but new authoring is easier in Bicep.  
- Microsoft’s long‑term direction is to encourage Bicep for authoring, while ARM remains the execution engine.

---

## ✅ Quick Flashcard Recap
- Bicep = concise DSL, ARM = verbose JSON engine.  
- Terraform = multi‑cloud; Bicep = Azure‑native.  
- Production‑ready, fully supported.  
- Azure‑only, limited Azure Stack Hub support.  
- ARM templates remain valid; can be converted to Bicep.
