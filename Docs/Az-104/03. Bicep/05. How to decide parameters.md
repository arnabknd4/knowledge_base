# How to Decide Parameters in Bicep

## 🔑 Core Principle
You **don’t need to memorize every parameter for every resource**. Instead, follow a **pattern‑based approach**:
- **Parameters** → Values that change between environments (dev, test, prod).  
- **Hardcoded values** → Defaults that rarely change (e.g., SKU for a small lab).  
- **Variables** → Derived values (e.g., naming conventions, concatenations).  

---

## 🧩 General Pattern Across Resource Types

### 1. Compute (VMs, Scale Sets)
- **Parameters**: `vmName`, `location`, `vmSize`, `adminUsername`, `adminPassword`, `imageReference`.  
- **Variables**: Naming conventions, tags.  
- **Defaults**: OS type, disk type (unless you want flexibility).

### 2. Networking (VNet, Subnet, NSG)
- **Parameters**: `vnetName`, `addressSpace`, `subnetNames`, `nsgRules`.  
- **Variables**: Derived subnet CIDRs.  
- **Defaults**: Standard NSG rules (allow RDP/SSH if needed).

### 3. Storage
- **Parameters**: `storageAccountName`, `location`, `sku`, `replication`.  
- **Variables**: Resource naming.  
- **Defaults**: Access tier (Hot/Cool) depending on workload.

### 4. Databases (SQL, Cosmos DB)
- **Parameters**: `dbName`, `location`, `skuTier`, `adminLogin`, `adminPassword`.  
- **Variables**: Connection strings.  
- **Defaults**: Backup retention, redundancy (unless compliance requires change).

### 5. AKS (Kubernetes Service)
- **Parameters**: `clusterName`, `location`, `nodeCount`, `nodeVMSize`, `dnsPrefix`.  
- **Variables**: Tags, naming.  
- **Defaults**: Network plugin (Azure CNI vs Kubenet) unless you need flexibility.

---

## 📘 Practical Rule of Thumb
- **Parameterize anything that changes between environments.**  
- **Keep defaults for stable values.**  
- **Use variables for derived values.**  
- **Modules**: Break down large deployments (e.g., AKS cluster module, VNet module).

---

## 🛠️ How to Discover Parameters
- Use **VS Code Bicep extension** → IntelliSense shows required/optional properties.  
- Run `az bicep build` → compiles to ARM JSON, where you can see schema.  
- Use `az resource list` → check existing resources and export templates.  
- **Documentation**: Still essential for advanced features, but IntelliSense reduces reliance.

---

## ✅ Quick Flashcard Recap
- Don’t memorize → follow **pattern**.  
- Parameterize environment‑specific values.  
- Variables for derived values.  
- Defaults for stable values.  
- IntelliSense + docs = discovery, not memorization.
