# Accessing Your Own Scripts and Files in Azure Cloud Shell

## 1. What is it?
Cloud Shell provides a mounted Azure Files share (`clouddrive`) where you can store and access your own scripts, files, and configuration.

## 2. How It Works
- On first use, Cloud Shell prompts you to create a **storage account + Azure Files share**.  
- This share is mounted automatically as `/home/<user>/clouddrive` (Linux) or `clouddrive:\` (PowerShell).  
- Any files saved here persist across sessions.  
- You can upload/download files directly from the Cloud Shell interface.  

## 3. Access Methods
- **Upload/Download** → Use the Cloud Shell toolbar (upload/download buttons).  
- **Persistent Drive** → Store scripts in `clouddrive` for reuse.  
- **Git Integration** → Clone repos directly into Cloud Shell.  
- **VS Code Integration** → Use the Azure Account extension to sync files.  

### 🔧 Code Snippets
**Upload a script to clouddrive (Bash):**
```bash
cp myscript.sh ~/clouddrive/
```

- Run a script stored in clouddrive (PowerShell):

``` ps1
cd clouddrive:\scripts
.\deploy.ps1

```

- Clone a GitHub repo into Cloud Shell:
``` sh
git clone https://github.com/your-org/infra-scripts.git ~/clouddrive/infra

```

4. Real‑World Use Case
Architects keep reusable Terraform scripts, ARM templates, and PowerShell modules in clouddrive to quickly deploy infrastructure across subscriptions.

6. Common Mistakes
Forgetting to configure persistent storage → scripts lost after session ends.

Storing secrets in plain text files inside clouddrive.

Assuming Cloud Shell storage is unlimited (only 5 GB).

7. Mental Model
Think of clouddrive as your “personal USB stick in Azure” — always mounted when you open Cloud Shell.
