# Accessing Azure Cloud Shell

## 1. What is it?
A browser-based shell environment (Bash or PowerShell) hosted in Azure, accessible directly from the portal or web.

## 2. How to Access
- **Azure Portal** → Click the Cloud Shell icon (top-right toolbar).  
- **Direct URL** → Go to [https://shell.azure.com](https://shell.azure.com).  
- **Azure Mobile App** → Cloud Shell available inside the app.  
- **VS Code Extension** → Use the Azure Account extension to launch Cloud Shell.  

## 3. Authentication
- Uses your **Azure AD identity**.  
- Permissions flow from **RBAC** assignments.  
- First-time use prompts creation of a **storage account + Azure Files share** (5 GB persistent storage).  

## 4. Environment Details
- Runs in an **ephemeral container** managed by Microsoft.  
- Supports **Bash** and **PowerShell** modes.  
- Preinstalled tools: `az CLI`, Terraform, Git, `kubectl`, PowerShell modules.  
- Persistent files stored in `clouddrive` (mounted Azure Files share).  

## 5. Real‑World Use Case
Architects and admins use Cloud Shell for quick troubleshooting, running Terraform scripts, or managing multi‑subscription resources without local setup.

## 6. Common Mistakes
- Forgetting to set up persistent storage → session data lost.  
- Assuming Cloud Shell replaces CI/CD pipelines (it doesn’t).  
- Confusing RBAC (access control) with Policy (governance).  

## 7. Mental Model
Think of Cloud Shell as a **“portable toolbox in the cloud”** — always available, preloaded, tied to your Azure identity.

## 8. Revision Summary
- Access via Portal, shell.azure.com, VS Code, or mobile app.  
- Auth via Azure AD + RBAC.  
- Ephemeral container + persistent 5 GB Azure Files.  
- Bash/PowerShell modes with preinstalled tools.  
- Exam trap: Cloud Shell ≠ full automation platform.
