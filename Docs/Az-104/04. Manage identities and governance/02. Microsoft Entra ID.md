# Microsoft Entra ID (formerly Azure Active Directory)

## 1. What is it?
Microsoft Entra ID is Microsoft’s **cloud‑based identity and access management (IAM)** service.  
It provides authentication, authorization, and governance for users, devices, applications, and resources.  
It is the backbone of **Zero Trust security** in Azure and Microsoft 365.

---

## 2. Key Capabilities
- **Authentication**: MFA, passwordless sign‑in, conditional access.  
- **Authorization**: Role‑based access control (RBAC), least privilege enforcement.  
- **Identity Governance**: Privileged Identity Management (PIM), lifecycle automation.  
- **Hybrid Identity**: Azure AD Connect for syncing on‑prem AD with Entra ID.  
- **Device & App Management**: Register devices, manage SaaS apps, use managed identities.  
- **Security Intelligence**: Risk‑based conditional access, anomaly detection, identity protection.

---

## 3. Exam/Interview Lens
- **AZ‑104 Exam**: Focus on user/group management, RBAC, conditional access, hybrid identity, MFA.  
- **Architect Role**: Governance, compliance, SaaS integration, Zero Trust design.  
- **DevOps Role**: Managed identities, app registration, CI/CD integration with Entra ID.  

---

## 4. Real‑World Scenarios
- **Contractor Access**: Use Conditional Access to enforce MFA and limit access to specific apps.  
- **Privileged Accounts**: Secure with PIM, enforce just‑in‑time access, and require approval workflows.  
- **Hybrid Enterprise**: Sync on‑prem AD with Entra ID, enable seamless SSO, and enforce passwordless sign‑in.  

---

## 5. Common Mistakes
- Confusing Entra ID with traditional AD DS (on‑prem).  
- Over‑permissioning users with broad RBAC roles.  
- Not enabling MFA → major security risk.  
- Ignoring Conditional Access → compliance gaps.  

---

## 6. Quick Flashcard Recap
- **Entra ID = Azure AD renamed** → cloud IAM backbone.  
- **Core functions**: Authentication, RBAC, Conditional Access, MFA, Hybrid Identity.  
- **Security**: AI‑driven risk detection, PIM, passwordless sign‑in.  
- **Best practice**: Enforce least privilege, enable MFA, monitor with logs/reports.
