# Microsoft Entra – Architect/Exam/Interview Lens

## 1. What is it?
Microsoft Entra is the **identity and access management family** in Azure.  
It includes **Entra ID (Azure AD)**, **Entra Permissions Management**, and **Entra Verified ID**.  

---

## 2. Why do we need it?
- Provides **centralized identity governance**.  
- Enables **secure access** with MFA, Conditional Access, and Zero Trust.  
- Supports **hybrid identity** (on‑prem AD + cloud).  
- Critical for compliance and multi‑tenant security.

---

## 3. Core Exam Focus (AZ‑104 / Architect)
- **User & Group Management**.  
- **Role Assignments (RBAC)**.  
- **Conditional Access Policies**.  
- **Hybrid Identity (Azure AD Connect)**.  
- **Identity Protection** (MFA, passwordless).  

---

## 4. Real‑World Use Case
An enterprise integrates **on‑prem Active Directory** with **Entra ID** using Azure AD Connect.  
- Employees authenticate with a single identity across Office 365, Azure, and SaaS apps.  
- Conditional Access enforces MFA when logging in outside the corporate network.  
- RBAC ensures least privilege access to Azure resources.

---

## 5. Interview Lens
- **Q1:** How does Entra ID differ from traditional Active Directory?  
  *Entra ID is cloud‑based, supports modern authentication (OAuth2, OpenID Connect), and integrates with SaaS apps. Traditional AD is on‑prem, Kerberos/NTLM based.*  

- **Q2:** How would you secure multi‑tenant access in Azure?  
  *Use Conditional Access, MFA, Privileged Identity Management (PIM), and enforce Just‑In‑Time role assignments.*  

- **Q3:** How do you integrate on‑prem AD with Entra ID?  
  *Use Azure AD Connect for synchronization, configure hybrid identities, and enable seamless SSO.*  

---

## 6. Common Mistakes
- Confusing **Entra ID** with traditional AD DS.  
- Not enabling MFA → major security risk.  
- Misconfigured RBAC → excessive permissions.  
- Ignoring Conditional Access → compliance gaps.  

---

## 7. Mental Model
Think of **Entra ID as a “gatekeeper”**:  
- **Users** = guests.  
- **Policies** = rules for entry.  
- **RBAC** = keys to specific rooms.  

---

## 8. Revision Summary
- Entra = identity family (ID, Permissions, Verified ID).  
- Exam focus: users, groups, RBAC, Conditional Access, hybrid identity.  
- Real‑world: secure SaaS + Azure access, MFA, compliance.  
- Mistakes: confusing AD vs Entra, ignoring MFA/Conditional Access.  
- Mental model: gatekeeper with rules + keys.
