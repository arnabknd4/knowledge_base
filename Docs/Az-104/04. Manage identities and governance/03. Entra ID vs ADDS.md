# Microsoft Entra ID vs Active Directory Domain Services (AD DS)

## 1. Deployment Model
- **Entra ID**: Cloud‑based identity and access management (IAM) service.  
- **AD DS**: On‑premises directory service running on Windows Server.  

---

## 2. Authentication Protocols
- **Entra ID**: Modern protocols (OAuth2, OpenID Connect, SAML, WS‑Federation).  
- **AD DS**: Traditional protocols (Kerberos, NTLM, LDAP).  

---

## 3. Scope of Use
- **Entra ID**: Provides SSO across Microsoft 365, Azure, and thousands of SaaS apps.  
- **AD DS**: Manages on‑premises resources (servers, printers, file shares).  

---

## 4. Identity Management
- **Entra ID**: Cloud identities, hybrid identities (via Azure AD Connect), passwordless sign‑in, MFA, Conditional Access.  
- **AD DS**: Domain‑joined devices, Group Policy Objects (GPOs), organizational units (OUs).  

---

## 5. Governance & Security
- **Entra ID**: Role‑based access control (RBAC), Privileged Identity Management (PIM), risk‑based conditional access.  
- **AD DS**: Group policies, OU‑based delegation, traditional admin roles.  

---

## 6. Device & Application Integration
- **Entra ID**: Registers devices for conditional access, integrates with SaaS apps, supports managed identities for Azure resources.  
- **AD DS**: Joins Windows devices to a domain, applies GPOs, integrates with legacy apps.  

---

## 7. Maintenance & Infrastructure
- **Entra ID**: Fully managed by Microsoft in the cloud, no servers to patch.  
- **AD DS**: Requires domain controllers, replication, backups, patching, and disaster recovery planning.  

---

## 8. Typical Use Cases
- **Entra ID**: Cloud‑first organizations, hybrid identity, SaaS integration, Zero Trust security.  
- **AD DS**: Legacy applications, on‑premises infrastructure, environments needing GPOs.  

---

## ✅ Quick Flashcard Recap
- **Entra ID** = Cloud IAM, modern protocols, SaaS integration, MFA, Conditional Access.  
- **AD DS** = On‑prem directory, Kerberos/NTLM, GPOs, device/domain management.  
- **Architect Lens**: Entra ID for cloud/hybrid, AD DS for legacy/on‑prem.  
- **Best Practice**: Use **hybrid identity** (Azure AD Connect) to bridge both worlds.
