# ARM Template – File Structure Elements

## 1. Schema
- **Required** section.  
- Defines the location of the JSON schema file that describes the structure of the template.  
- Version depends on deployment scope and JSON editor.  

```json
"$schema": "https://schema.management.azure.com/schemas/2019-04-01/deploymentTemplate.json#"
```
## 2. ContentVersion
- **Required section**.
- Defines the version of your template (e.g., `"1.0.0.0"`).
- Used for documenting significant changes and ensuring correct template deployment.
```json
"contentVersion": "1.0.0.0"
```
## 3. ApiProfile
- **Optional section**.
- Defines a collection of API versions for resource types.
- Helps avoid specifying API versions for each resource individually.
```json
"apiProfile": "2020-09-01-hybrid"
```
## 4. Parameters
- **Optional** section.
- Defines values provided during deployment (via parameter file, CLI, or portal).
- Enables flexibility and reusability.
```json
"parameters": {
  "storageName": {
    "type": "string",
    "defaultValue": "mystorageacct"
  }
}
```
## 5. Variables
- **Optional** section.
- Stores values used to simplify template expressions.
- Often derived from parameters.
```json
"variables": {
  "location": "[resourceGroup().location]"
}
```
## 6. Functions
- **Optional** section.
- User-defined functions to simplify repeated complex expressions.
```json
"functions": [
  {
    "namespace": "utilities",
    "members": {
      "concatName": {
        "parameters": [ "prefix", "suffix" ],
        "output": "[concat(parameters('prefix'), parameters('suffix'))]"
      }
    }
  }
]
```
## 7. Resources
- **Required** section.
- Defines the actual Azure resources to deploy or update.
```json
"resources": [
  {
    "type": "Microsoft.Storage/storageAccounts",
    "apiVersion": "2022-09-01",
    "name": "[parameters('storageName')]",
    "location": "[variables('location')]",
    "sku": { "name": "Standard_LRS" },
    "kind": "StorageV2",
    "properties": {}
  }
]
```
## 8. Outputs
- **Optional** section.
- Returns values after deployment (e.g., connection strings, resource IDs).
```json
"outputs": {
  "storageEndpoint": {
    "type": "string",
    "value": "[reference(parameters('storageName')).primaryEndpoints.blob]"
  }
}
```
## 9. Mental Model
- Think of an ARM template as a blueprint:
- Schema = rules of the language.
- ContentVersion = version of the blueprint.
- Parameters = inputs from the architect.
- Variables = shortcuts/derived values.
- Functions = reusable formulas.
- Resources = actual building blocks.
- Outputs = final handover report.

## 10. Revision Summary
- Required: schema, contentVersion, resources.
- Optional: apiProfile, parameters, variables, functions, outputs.
- Parameters = flexibility, Variables = reuse.
- Functions = simplify repeated logic.
- Exam trap: forgetting dependsOn → failed deployments.
