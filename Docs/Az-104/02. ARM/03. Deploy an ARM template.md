# Deploy an ARM Template to Azure

## 1. What is it?
ARM templates are JSON files that define Azure resources declaratively. Deployment applies the template to a resource group, subscription, management group, or tenant.

## 2. Deployment Scopes
- **Resource Group** → Most common; deploy resources into a single RG.  
- **Subscription** → Deploy resources across multiple RGs.  
- **Management Group** → Apply governance templates at scale.  
- **Tenant** → Deploy resources at the highest scope (rare, governance-heavy).  

## 3. Deployment Methods
- **Azure Portal** → Upload template file or link to GitHub/Storage.  
- **Azure CLI** → `az deployment group create` for RG scope.  
- **PowerShell** → `New-AzResourceGroupDeployment`.  
- **REST API** → Programmatic deployments.  
- **Azure DevOps/GitHub Actions** → CI/CD integration.  

## 4. Supporting Code Snippets

**Deploy to Resource Group (CLI):**
```bash
az deployment group create \
  --resource-group MyRG \
  --template-file azuredeploy.json \
  --parameters @azuredeploy.parameters.json
```
Deploy to Subscription (CLI):
```sh
az deployment sub create \
  --location eastus \
  --template-file azuredeploy.json \
  --parameters @azuredeploy.parameters.json
```
Deploy via PowerShell:
```ps1
New-AzResourceGroupDeployment `
  -ResourceGroupName MyRG `
  -TemplateFile azuredeploy.json `
  -TemplateParameterFile azuredeploy.parameters.json
```
- Portal Deployment Steps:
- Go to Azure Portal → Resource Group → Deployments → Add.
- Upload azuredeploy.json and parameter file.
- Validate → Review → Create.

## 5. Real‑World Use Case
- Architects deploy multi‑region VNets, AKS clusters, and monitoring agents using ARM templates integrated into DevOps pipelines for repeatable, compliant infrastructure.

## 6. Interview Lens
- How do you enforce dependencies (dependsOn) in ARM templates?
- What’s the difference between deploying at RG vs Subscription scope?
- How do you integrate ARM templates into CI/CD pipelines?

## 7. Common Mistakes
- Forgetting to validate template before deployment.
- Hardcoding values instead of using parameters.
- Ignoring scope differences → deployment fails.
- Missing dependsOn → race conditions in resource creation.

## 8. Mental Model
Think of ARM deployment as “applying a blueprint to a construction site”, the scope (RG, subscription, etc.) is the site, and the template ensures the building matches the blueprint.

## 9. Revision Summary
- Deployment scopes: RG, Subscription, MG, Tenant.
- Methods: Portal, CLI, PowerShell, REST, CI/CD.
- Parameters = flexibility, Variables = reuse.
- Always validate before deployment.
- Exam trap: wrong scope or missing dependsOn.
