# 🔄 Azure Backup vs Azure Site Recovery (ASR)

| Aspect | Azure Backup | Azure Site Recovery (ASR) |
| --- | --- | --- |
| **Purpose** | Data protection → creates restore points for workloads | Disaster recovery → orchestrates failover to secondary site |
| **Scope** | VMs, files, folders, SQL Server, SAP HANA, on‑prem workloads | Azure VMs, Hyper‑V, VMware, physical servers |
| **Recovery Type** | Granular restore (files, disks, DBs, workloads) | Full workload failover (planned/unplanned) |
| **Time Objective** | Focuses on **RPO** (how much data can be lost) | Focuses on **RTO** (how fast workloads can be restored) |
| **Compliance Fit** | Long‑term retention via **Archive tier** | Not designed for compliance storage |
| **Cost Driver** | Storage (more frequent backups = more cost) | Infrastructure (replication + secondary region resources) |
| **Use Case** | Accidental deletion, corruption, rollback, compliance retention | Regional outage, datacenter failure, business continuity |
| **Management** | Recovery Services vault + Backup Center | Recovery Plans + ASR orchestration policies |

---

# 🧠 Mental Model
- **Azure Backup** = *“time machine vault”* → rewind workloads to restore points.  
- **ASR** = *“mirror city”* → switch operations to a secondary site during disasters.  

---

# 📌 Summary
- Use **Azure Backup** when:  
  - You need restore points for workloads.  
  - Compliance requires long‑term retention.  
  - Operational recoveries (files, disks, DBs) are frequent.  

- Use **ASR** when:  
  - You need disaster recovery with failover orchestration.  
  - Business continuity is critical during regional outages.  
  - RTO/RPO targets demand replication across regions.
