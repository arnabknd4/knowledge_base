# 📌 Decision Matrix – Replication Types vs HA Services vs Use Cases

| Option | Scope | Cost | Use Case | HA Service Alignment |
| --- | --- | --- | --- | --- |
| **LRS (Locally Redundant Storage)** | 3 copies in a single datacenter | Lowest | Protect against local hardware failure | Works with **Availability Sets** (fault domain resilience only) |
| **ZRS (Zone Redundant Storage)** | Replication across availability zones in a region | Medium | Zone‑level resilience, synchronous replication | Aligns with **Availability Zones** (independent datacenter resilience) |
| **GRS (Geo‑Redundant Storage)** | Asynchronous replication to paired region | Higher | Regional disaster recovery, compliance | Complements **Azure Site Recovery** for cross‑region failover |
| **RA‑GRS (Read‑Access GRS)** | Same as GRS + read access in secondary region | Higher | DR + compliance + secondary region read access | Useful for **BCDR testing** and compliance scenarios |
| **Availability Sets** | VM distribution across fault/update domains | No extra cost (infra only) | Protect against rack/power unit failures | Best with **LRS** storage |
| **Availability Zones** | VM distribution across zones (separate datacenters) | Medium | Zone‑level compute resilience | Best with **ZRS** storage |
| **Azure Site Recovery (ASR)** | Replication + failover orchestration to secondary region | Higher (infra + replication) | Regional outage, business continuity | Complements **GRS/RA‑GRS** storage |

---

# 🧠 Mental Model
- **LRS** = local safety net (cheap, limited).  
- **ZRS** = zone‑level shield (balanced).  
- **GRS** = regional parachute (DR focus).  
- **RA‑GRS** = regional parachute + binoculars (read access).  
- **Availability Sets/Zones** = compute resilience.  
- **ASR** = orchestrated failover for business continuity.  

---

# 📌 Exam‑Style Takeaway
- **Operational recovery** → Azure Backup + LRS/ZRS.  
- **Compliance retention** → Azure Backup + Archive tier + GRS/RA‑GRS.  
- **Disaster recovery** → ASR + GRS/RA‑GRS.
