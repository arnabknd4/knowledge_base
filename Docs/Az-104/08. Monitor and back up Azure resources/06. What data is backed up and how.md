# 📦 What Data is Backed Up and How (Azure Backup)

## 1. Virtual Machines (VMs)
- **Data**: OS disks, data disks, configuration.  
- **How**: Snapshot‑based backups taken at scheduled intervals.  
- **Consistency**: App‑consistent (VSS for Windows, scripts for Linux) or crash‑consistent.  

## 2. Files & Folders
- **Data**: Individual files and directories from Windows/Linux systems.  
- **How**: Azure Backup Agent or MARS agent captures incremental changes.  
- **Consistency**: File‑level consistency with minimal impact on workloads.  

## 3. Databases
- **Data**: SQL Server, SAP HANA, and other supported workloads.  
- **How**: Workload‑aware backups using application‑specific extensions.  
- **Consistency**: Transaction‑consistent backups ensure no data corruption.  

## 4. On‑Premises Workloads
- **Data**: Physical servers, Hyper‑V, VMware workloads.  
- **How**: Backed up via Azure Backup Server (MABS) or System Center DPM integrated with Recovery Services vault.  
- **Consistency**: Application‑aware snapshots for enterprise workloads.  

## 5. Recovery Services Vault
- **Data Storage**: All backup data is securely stored in the vault.  
- **How**: Encrypted in transit and at rest (AES‑256).  
- **Redundancy**: LRS (local copies) or GRS (geo‑replicated).  

---

# 🧠 Mental Model
Think of Azure Backup as a **“multi‑layer safety net”**:  
- VM snapshots catch infrastructure failures.  
- File/folder backups catch user errors.  
- Database backups catch transaction integrity.  
- Vault ensures everything is stored securely and redundantly.
