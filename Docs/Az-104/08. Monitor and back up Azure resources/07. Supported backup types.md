# 📂 Supported Backup Types in Azure Backup

## 1. Full Backup
- Captures the **entire dataset** (VM, disk, file, or database).  
- Provides a complete restore point.  
- Typically used for the **first backup** or periodic compliance requirements.  
- **Cost/Impact**: Larger storage + longer backup time.

## 2. Differential Backup
- Captures **only changes since the last full backup**.  
- Reduces storage and time compared to full backups.  
- Commonly used for **daily backups** in enterprise workloads.  

## 3. Multiple Backups per Day
- Azure Backup supports **multiple recovery points in a single day**.  
- Useful for workloads with frequent changes (e.g., financial transactions).  
- Policies can be configured for **hourly snapshots**.  

## 4. Selective Disk Backup
- Allows backing up **specific disks** of a VM instead of all disks.  
- Optimizes cost and performance by excluding non‑critical disks.  
- Example: Backup only OS + data disks, skip temporary/cache disks.  

## 5. Transaction Log Backup
- For **SQL Server and SAP HANA databases**.  
- Captures **transaction logs** to enable point‑in‑time recovery.  
- Ensures minimal data loss by replaying logs up to the failure point.  

---

# 🧠 Mental Model
Think of backup types as **layers of protection**:  
- **Full** = complete safety net.  
- **Differential** = incremental safety net since last full.  
- **Multiple per day** = frequent checkpoints.  
- **Selective disk** = targeted safety net.  
- **Transaction log** = fine‑grained rewind for databases.  

---

# 📌 Revision Summary
- **Full** → entire dataset, baseline restore point  
- **Differential** → changes since last full backup  
- **Multiple per day** → frequent recovery points  
- **Selective disk** → cost‑optimized, disk‑specific backups  
- **Transaction log** → point‑in‑time recovery for DBs
