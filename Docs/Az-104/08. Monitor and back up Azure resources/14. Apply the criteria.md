# 📌 Applying Decision Criteria – Azure Backup vs Azure Site Recovery

| Criteria | Azure Backup | Azure Site Recovery (ASR) |
| --- | --- | --- |
| **Azure Workloads** | Best for **VMs, files, folders, SQL, SAP HANA** needing restore points. Provides **granular recovery** (files, disks, databases). | Best for **VMs and workloads** needing **failover orchestration** across regions. Provides **business continuity** during outages. |
| **Compliance** | Supports **long‑term retention** via **Archive tier**. Ideal for workloads with **regulatory requirements** (finance, healthcare). | Not designed for compliance storage. Focuses on **availability and failover**, not retention. |
| **Operational Recoveries** | Perfect for **day‑to‑day restores** (accidental deletion, corruption, rollback). Multiple recovery points per day. | Used for **disaster scenarios** (regional outage, datacenter failure). Provides **planned/unplanned failover**. |

---

# 🧠 Mental Model
- **Azure Backup** = *“time machine vault”* → rewind workloads for compliance and operational recovery.  
- **ASR** = *“mirror city”* → switch operations to a secondary site during disasters.  

---

# 📌 Summary
- Use **Azure Backup** when:  
  - You need restore points for Azure workloads.  
  - Compliance requires long‑term retention.  
  - Operational recoveries (files, disks, DBs) are frequent.  

- Use **ASR** when:  
  - You need disaster recovery with failover orchestration.  
  - Business continuity is critical during regional outages.  
  - RTO/RPO targets demand replication across regions.
