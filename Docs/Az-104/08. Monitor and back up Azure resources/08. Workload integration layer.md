# 🔌 Workload Integration Layer – Backup Extension

## 1. What is it?
A lightweight agent/extension installed on Azure VMs or workloads that enables **application‑aware backups** by integrating directly with the workload.

## 2. Why do we need it?
- Ensures **app‑consistent backups** (not just crash‑consistent).  
- Coordinates with workload processes (SQL, SAP HANA, etc.) to capture transaction‑safe snapshots.  
- Provides granular restore options (files, disks, databases).  

## 3. How it Works
- **Installed automatically** when backup is enabled for a VM/workload.  
- **Communicates with Azure Backup service** to trigger snapshot operations.  
- Uses **VSS (Volume Shadow Copy Service)** for Windows workloads.  
- For Linux workloads, supports **pre/post scripts** to ensure application consistency.  
- Captures metadata and transaction logs for supported databases.  

## 4. Supported Workloads
- **Azure VMs** (Windows/Linux).  
- **SQL Server** databases.  
- **SAP HANA** databases.  
- Other workloads integrated via **Backup Extension APIs**.  

## 5. Security & Reliability
- Extension runs in the VM context but controlled by Azure Backup policies.  
- Encrypted communication with Recovery Services vault.  
- Logs and monitoring available via **Azure Monitor**.  

---

# 🧠 Mental Model
Think of the Backup Extension as a **“translator inside the VM”** — it speaks both the language of the workload (SQL, SAP, OS) and the language of Azure Backup, ensuring snapshots are consistent and reliable.
