# 📊 Data Plane – Access Tiers in Azure Backup

## 1. Snapshot Tier
- **What it is**: Short‑term storage of VM snapshots taken during backup.  
- **Purpose**: Provides fast, near‑instant restore capability.  
- **Use Case**: Quick recovery of recently backed‑up workloads.  
- **Retention**: Typically short‑lived before data moves to vault storage.  

## 2. Vault‑Standard Tier
- **What it is**: Default tier in the Recovery Services vault.  
- **Purpose**: Stores backups with configurable retention policies.  
- **Use Case**: Daily/weekly backups for VMs, files, folders, and databases.  
- **Retention**: Medium to long‑term, depending on policy (days → years).  

## 3. Archive Tier
- **What it is**: Lowest‑cost, long‑term storage option.  
- **Purpose**: Retains data for compliance or historical records.  
- **Use Case**: Rarely accessed backups (e.g., 7‑year financial compliance).  
- **Retention**: Long‑term, optimized for cost savings.  

---

# 🧠 Mental Model
Think of the tiers as **layers of a library**:  
- **Snapshot tier** = reading desk (fast, temporary access).  
- **Vault‑standard tier** = main shelves (regular storage, organized by policy).  
- **Archive tier** = basement archives (cheap, long‑term preservation).  

---

# 📌 Revision Summary
- **Snapshot tier** → short‑term, fast restore  
- **Vault‑standard tier** → default, policy‑driven retention  
- **Archive tier** → low‑cost, long‑term compliance storage  
- Data flows: Snapshot → Vault → Archive (based on retention policies)  
- Exam trap: confusing archive tier with geo‑redundancy (they serve different purposes)
