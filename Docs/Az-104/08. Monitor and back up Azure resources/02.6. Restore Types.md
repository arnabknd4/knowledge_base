# 🔄 Restore Types in Azure Backup

## 1. Full VM Restore
- **Scope**: Entire virtual machine (OS + all disks).  
- **Use Case**: VM corruption, accidental deletion, ransomware attack.  
- **Restore Location**: Original VM or new VM.  
- **Impact**: Longer recovery time, but complete rollback.  

---

## 2. Disk Restore
- **Scope**: Individual disks from VM backup.  
- **Use Case**: Specific disk corruption or targeted recovery.  
- **Restore Location**: Attach restored disk to existing VM or create new VM.  
- **Impact**: Faster than full VM restore, more granular.  

---

## 3. File/Folder Restore
- **Scope**: Granular recovery of files/folders from VM backup.  
- **Use Case**: Accidental file deletion, operational recovery.  
- **Mechanism**: Instant Restore mounts snapshot → recover files directly.  
- **Impact**: Quick, lightweight recovery without full VM rollback.  

---

## 4. Cross‑Region Restore (CRR)
- **Scope**: Restore VM data in paired region (requires GRS/RA‑GRS).  
- **Use Case**: Regional outage, compliance testing, DR scenarios.  
- **Impact**: Ensures business continuity across regions.  

---

## 5. Application‑Aware Restore
- **Scope**: Workload‑aware backups (SQL Server, SAP HANA).  
- **Use Case**: Point‑in‑time restore (PITR) for databases.  
- **Impact**: Transaction‑consistent recovery, minimal data loss.  

---

# 🧠 Mental Model
Think of restore types as **“levels of rewind”**:
- Full VM → rewind the entire system.  
- Disk → rewind a component.  
- File/Folder → rewind just the data.  
- CRR → rewind in another region.  
- App‑aware → rewind transactions with precision.  

---

# 📌 Revision Summary
- **Full VM** → complete rollback.  
- **Disk** → targeted recovery.  
- **File/Folder** → granular operational recovery.  
- **CRR** → regional resilience.  
- **App‑aware** → transaction‑consistent database restore.
