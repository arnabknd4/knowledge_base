# 🔄 Restoring Virtual Machine Data (Azure Backup)

## 1. Restore Options
- **Full VM Restore**  
  - Recreates the entire VM from a backup point.  
  - Useful for **VM corruption or accidental deletion**.  
  - Can restore to the **original location** or a **new VM**.  

- **Disk Restore**  
  - Restores individual disks from a VM backup.  
  - Useful when only a specific disk is corrupted.  
  - Disks can be attached to an existing VM or used to create a new VM.  

- **File/Folder Restore**  
  - Granular recovery of files/folders from a VM backup.  
  - Uses the **Azure Backup agent** or **Instant Restore** capability.  
  - Ideal for **operational recoveries** (accidental file deletion).  

---

## 2. Restore Workflow
1. **Select Recovery Services Vault** → where VM backup is stored.  
2. **Choose Backup Item** → select the VM.  
3. **Pick Restore Point** → daily/hourly snapshots available.  
4. **Select Restore Type** → full VM, disk, or file/folder.  
5. **Restore Location** → original VM or new VM.  
6. **Apply Post‑Restore Configurations** → networking, extensions, RBAC.  

---

## 3. Key Features
- **Instant Restore** → mount backup snapshot as a temporary disk for quick recovery.  
- **Cross‑Region Restore (CRR)** → restore VM data in paired region (if GRS/RA‑GRS enabled).  
- **Soft Delete Protection** → ensures restore even if backup item was deleted (14‑day window).  
- **Security** → encrypted restore traffic, RBAC‑controlled access.  

---

# 🧠 Mental Model
Think of VM restore as **“rewinding the machine to a safe checkpoint”**:  
- Full VM → rewind the entire system.  
- Disk restore → rewind a specific component.  
- File restore → rewind just the data you lost.
