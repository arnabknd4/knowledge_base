# Activity Logs – Routing & Storage Options

## 1. What is it?
Activity logs capture all control‑plane operations (create, update, delete) performed on Azure resources.

## 2. Why do we need it?
Provides governance visibility, audit trails, and security monitoring. Essential for compliance frameworks (ISO, SOC, HIPAA).

## 3. Core Exam Focus
- **Azure Monitor Logs** → Centralized query/analysis with KQL
- **Azure Storage** → Long‑term archival, cost‑effective retention
- **Azure Event Hubs** → Streaming logs to SIEM/third‑party tools
- Common trap: forgetting to configure diagnostic settings → logs not retained

## 4. Real‑World Use Case
A bank routes activity logs to:
- **Azure Monitor Logs** for daily operational dashboards
- **Azure Storage** for 7‑year retention (regulatory compliance)
- **Azure Event Hubs** to forward logs into Splunk SIEM for threat detection

## 5. Interview Lens
- Q: Why use Event Hubs instead of Storage?
  - A: Event Hubs supports real‑time ingestion into SIEM; Storage is archival.
- Q: How do you balance cost vs compliance?
  - A: Use Storage for long‑term retention, Monitor Logs for short‑term analytics.
- Q: What happens if logs aren’t routed?
  - A: You lose audit visibility, impacting compliance and incident response.

## 6. Common Mistakes
- Assuming logs are retained by default (they expire after 90 days if not routed)
- Not setting retention policies in Storage
- Overloading Monitor Logs with unnecessary data → cost spikes
- Forgetting to secure Storage/Event Hub with RBAC

## 7. Mental Model
Think of activity logs like **CCTV footage**:
- Monitor Logs = live control room
- Storage = archive vault
- Event Hubs = streaming feed to external security teams

## 8. Revision Summary
- Activity logs = control‑plane operations
- Route to Monitor Logs for analysis
- Route to Storage for compliance retention
- Route to Event Hubs for SIEM integration
- Default retention = 90 days unless configured
- Secure endpoints with RBAC/Policy
