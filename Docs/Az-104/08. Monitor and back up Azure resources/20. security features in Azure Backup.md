# 🔐 Security Features in Azure Backup

## 1. Role‑Based Access Control (RBAC)
- Restricts backup/restore operations to **authorized users only**.  
- Supports **least privilege principle** with roles like Backup Contributor, Operator, Reader.  
- Ensures compliance with governance policies.  

---

## 2. Encryption
- **In Transit** → Data encrypted using HTTPS.  
- **At Rest** → AES‑256 encryption in Recovery Services vault.  
- **Customer‑Managed Keys (CMK)** → Option to use your own keys for compliance.  

---

## 3. Soft Delete
- Protects against accidental or malicious deletion.  
- Retains backup data for **14 days after deletion**.  
- Allows recovery even if a backup item is deleted.  

---

## 4. No Internet Connectivity Required
- Backup traffic flows through the **Azure backbone network**, not the public internet.  
- Reduces exposure to external threats.  
- Ensures secure communication between workloads and vault.  

---

## 5. Monitoring & Alerts
- Integrated with **Azure Monitor** and **Security Center**.  
- Provides anomaly detection, suspicious activity alerts, and audit logs.  
- Strengthens proactive defense posture.  

---

# 🧠 Mental Model
Think of Azure Backup security as a **“multi‑layer defense system”**:  
- RBAC = guards at the door.  
- Encryption = locks on the vault.  
- No internet = private tunnel.  
- Soft delete = safety net against mistakes.  
- Monitoring = surveillance cameras.
