# ⚡ Availability Sets – Architect‑Level Breakdown

## 1. Definition
An **Availability Set** is a logical grouping of VMs in Azure that ensures workloads remain available during planned or unplanned maintenance events.

---

## 2. Core Concepts
- **Fault Domains (FDs)**  
  - Physical racks with independent power + network.  
  - VMs in different FDs avoid single point of failure.  
  - Default: up to 3 FDs per region.  

- **Update Domains (UDs)**  
  - Logical groups for patching/updates.  
  - Azure updates one UD at a time to avoid downtime.  
  - Default: up to 20 UDs per region.  

---

## 3. How It Works
- When you place VMs in an Availability Set:  
  - Azure distributes them across **multiple FDs** → resilience against hardware failure.  
  - Azure distributes them across **multiple UDs** → resilience against patching/updates.  
- Ensures **99.95% SLA** for VM uptime.  

---

## 4. Use Cases
- **Application Tiers**: Place web servers, app servers, DB servers in the same Availability Set for resilience.  
- **Legacy HA Design**: When Availability Zones are not required or supported.  
- **Cost‑Effective HA**: Provides HA without cross‑zone replication costs.  

---

## 5. Exam & Interview Lens
- **Exam Trap**: Availability Sets ≠ Availability Zones.  
  - Sets = resilience within a datacenter.  
  - Zones = resilience across datacenters in a region.  
- **Interview Q**: *How do you design HA for a 2‑tier app in one region?*  
  - Place VMs in Availability Sets → distributed across FDs/UDs.  
  - Use Load Balancer for traffic distribution.  

---

## 6. Mental Model
Think of Availability Sets as **“spreading eggs across baskets in the same room”**:  
- Fault domains = different baskets.  
- Update domains = baskets updated one at a time.  

---

## 7. Revision Summary
- Availability Sets = VM distribution across **FDs + UDs**.  
- Protects against hardware failures + patching downtime.  
- SLA = 99.95% uptime.  
- Cheaper than zones, but limited to one datacenter.
