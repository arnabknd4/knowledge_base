# Metrics Explorer – Scope, Namespace, and Aggregation

## 1. Scope
Defines the **resource boundary** for metrics collection.
- Can be **Subscription**, **Resource Group**, or **Specific Resource**.
- Example: Scope = VM resource → only metrics from that VM are shown.

## 2. Metric Namespace
Logical grouping of related metrics.
- Example: `VirtualMachine` namespace includes CPU, memory, disk metrics.
- Custom applications can emit their own namespaces.

## 3. Metric
The actual measurement being tracked.
- Examples: `Percentage CPU`, `Available Memory`, `Disk Read Bytes`.

## 4. Aggregation
Determines how raw metric values are summarized over time.
- **Count** → Number of metric samples in the time window.
- **Average (Avg)** → Mean value across samples.
- **Maximum (Max)** → Highest observed value.
- **Minimum (Min)** → Lowest observed value.
- **Sum** → Total of all values in the time window.

## 5. Exam & Interview Lens
- Q: Why use aggregation functions?
  - A: To smooth noisy data and highlight trends (e.g., Avg CPU vs Max CPU).
- Q: What’s the difference between Count and Sum?
  - A: Count = number of samples; Sum = total of metric values.

## 6. Common Mistakes
- Using **Avg** alone → hides spikes (use Max for peak detection).
- Forgetting to adjust **granularity** → misleading results.
- Misinterpreting **Count** as workload volume (it’s sample count, not transactions).

## 7. Mental Model
Think of aggregation like **summarizing exam scores**:
- Avg = class average
- Max = topper’s score
- Min = lowest score
- Sum = total marks of all students
- Count = number of students who took the exam

## 8. Revision Summary
- Scope = boundary (subscription, RG, resource)
- Namespace = logical grouping of metrics
- Metric = actual measurement (CPU, memory, etc.)
- Aggregation = summarization (Count, Avg, Max, Min, Sum)
- Avg smooths, Max/Min show extremes, Sum totals values
- Count = number of samples, not workload volume
