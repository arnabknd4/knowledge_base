# Server Admin

## daemon
- **What is it?**  
  A background Git process that listens for connections.  
- **Why do we need it?**  
  Enables serving repositories over the network.  
- **Real world example**  
  Running `git daemon` to allow anonymous clone access.  
- **Exam perspective**  
  Know it’s used for lightweight Git server setup.  
- **Interview Q&A**  
  Q: What does `git daemon` do?  
  A: It provides a simple TCP server for Git repositories.  
- **Common Mistakes**  
  Assuming it’s secure by default; it’s meant for trusted networks.  
- **Mental Model**  
  Think of it as Git’s “radio tower” broadcasting repos.  
- **Revision summary**  
  `git daemon` = lightweight Git server process.

## update-server-info
- **What is it?**  
  Updates auxiliary info files for dumb transports (HTTP).  
- **Why do we need it?**  
  Ensures clients using basic HTTP can fetch repository data.  
- **Real world example**  
  Running `git update-server-info` when serving repos via static HTTP.  
- **Exam perspective**  
  Know it’s required for “dumb” HTTP transport.  
- **Interview Q&A**  
  Q: When do you use `git update-server-info`?  
  A: When serving repositories over static HTTP without smart Git protocol.  
- **Common Mistakes**  
  Forgetting to run it after updates, breaking HTTP clones.  
- **Mental Model**  
  Think of it as Git’s “index refresh” for static servers.  
- **Revision summary**  
  `git update-server-info` = prepares repo for HTTP serving.
