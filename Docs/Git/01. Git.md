# Git

## 1. What is it?
Git is a distributed version control system used to track changes in source code during software development.

## 2. Why do we need it?
- Enables collaboration across teams
- Maintains history of changes
- Supports branching and merging for parallel development

## 3. Real world example
- Open-source projects on GitHub rely on Git for version control.
- Enterprise teams use Git to manage microservices codebases.

## 4. Exam perspective
- Understand Git commands (`clone`, `commit`, `push`, `pull`, `merge`, `rebase`)
- Know difference between centralized vs distributed VCS
- Be able to explain branching strategies

## 5. Interview Questions and Answers
- Q: What is the difference between `merge` and `rebase`?  
  A: Merge preserves history with a new commit; rebase rewrites history for a cleaner linear timeline.  
- Q: How does Git ensure data integrity?  
  A: Through SHA‑1 hashing of commits and objects.

## 6. Common Mistakes
- Forgetting to commit before switching branches
- Using `git pull` without understanding merge vs rebase
- Committing secrets or large binaries

## 7. Mental Model
Think of Git as a **timeline of snapshots**. Branches are parallel timelines, merges are intersections, and rebases are re‑alignments.

## 8. Revision Summary
- Git = distributed VCS  
- Core commands: `clone`, `commit`, `push`, `pull`, `merge`, `rebase`  
- Branching strategies matter for collaboration  
- Integrity ensured via hashing
