# Subagent Delegation

## 1. What is it?
A design pattern where a primary agent delegates specific tasks to specialized subagents for execution.

## 2. Why do we need it?
Improves modularity, scalability, and reliability by splitting complex workflows into smaller, manageable units handled by dedicated agents.

## 3. Core Exam Focus
- Delegation of tasks from parent agent to subagents
- Specialization of subagents (finance, devops, compliance, etc.)
- Clear communication and context handoff
- Escalation paths back to parent agent
- Common trap: poor context transfer → subagent misinterpretation

## 4. Real‑World Use Case
Customer support workflow:
- Parent agent receives query
- Finance subagent handles billing disputes
- Technical subagent resolves DevOps issues
- Compliance subagent ensures regulatory checks
- Parent agent consolidates responses into a unified output

## 5. Interview Lens
- Q: How do you ensure smooth context handoff between parent and subagents?
- Q: What happens if a subagent fails mid‑task?
- Q: How do you balance workload across multiple subagents?

## 6. Common Mistakes
- Weak context transfer → subagents lack necessary information
- Overloading one subagent with diverse tasks
- Missing fallback when subagent fails
- Poor monitoring of subagent performance

## 7. Mental Model
Think of subagent delegation as a **project manager with specialists**:
- Project manager (parent agent) assigns tasks
- Specialists (subagents) handle their domain
- Results flow back to manager for consolidation

## 8. Revision Summary
- Subagent delegation = parent assigns tasks to specialists
- Benefits: modularity, specialization, reliability
- Risks: poor context transfer, overloaded subagents
- Exam traps: missing fallback, weak monitoring
- Mental model: project manager with specialists analogy
