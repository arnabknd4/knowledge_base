# Event‑Driven Orchestration

## 1. What is it?
A pattern where agents are triggered by specific events or messages instead of a central controller or fixed schedule.

## 2. Why do we need it?
Enables real‑time responsiveness, scalability, and automation by activating agents only when relevant events occur.

## 3. Core Exam Focus
- Event listeners and triggers
- Message queues or pub/sub systems
- Reactive workflows (agents respond to signals)
- Integration with external systems (APIs, webhooks)
- Common trap: missing event filtering → agents triggered unnecessarily

## 4. Real‑World Use Case
Enterprise monitoring system:
- Event trigger: new log anomaly detected
- Security agent investigates anomaly
- Compliance agent checks regulatory impact
- Notification agent alerts stakeholders
- Workflow runs only when event occurs → efficient resource usage

## 5. Interview Lens
- Q: How do you design event filters to avoid false triggers?
- Q: What happens if multiple agents respond to the same event?
- Q: How would you ensure reliability in an event‑driven orchestration pipeline?

## 6. Common Mistakes
- Over‑triggering agents → wasted resources
- Poor event filtering → noise in workflows
- Lack of idempotency → duplicate actions
- Ignoring event ordering → inconsistent results

## 7. Mental Model
Think of event‑driven orchestration as a **fire alarm system**:
- Alarm (event) triggers response
- Firefighters (agents) act only when alarm rings
- No central controller needed, but reliability depends on correct triggers

## 8. Revision Summary
- Event‑driven = agents triggered by events/messages
- Benefits: real‑time, scalable, efficient
- Risks: false triggers, duplicate actions, ordering issues
- Exam traps: weak filtering, missing idempotency
- Mental model: fire alarm analogy
