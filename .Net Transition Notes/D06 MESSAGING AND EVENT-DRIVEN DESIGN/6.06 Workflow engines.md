1 What is it
- A workflow engine runs a multi-step business process in a fixed order. It remembers where the process is, even if a server restarts or a step fails.
- Think of a process like "take payment, reserve stock, send email, wait 3 days for approval". The engine keeps the state of that process for you.
- In Azure you will meet Durable Functions (workflows written as C# code), Logic Apps (workflows built from connectors in a designer), and Temporal (a code-first engine from outside Azure).
- Legacy equivalent: BizTalk orchestrations, Windows Workflow Foundation, or hand-built status columns plus SQL Agent jobs and Windows services that polled the database.

4 Features and core concepts
- Durable Functions: workflows written as normal C# code on top of Azure Functions. The runtime saves progress to storage, so a workflow can pause for days. It matters because long processes survive restarts without you building state tables.
- Orchestrator function: the function that describes the workflow steps. It must be deterministic (no random values, no current time, no direct I/O), because the runtime replays it from history. This is the most common interview trap.
- Activity function: a normal function that does the real work (call an API, write to a database). It matters because all side effects belong here, not in the orchestrator.
- Durable patterns: function chaining (step after step), fan-out/fan-in (run many in parallel, then combine), human interaction (wait for an external event, with a timeout), monitor (poll until a condition is met). Know these four by name.
- Logic Apps: low-code workflows with triggers and ready-made connectors (Office 365, SAP, Service Bus, SQL, and so on). Consumption plan is pay per run; Standard plan runs on a dedicated hosting plan (verify current plan details). It matters when integration speed beats custom code.
- Temporal awareness: an open-source, code-first engine where workflows are durable code and workers run on your own infrastructure or Temporal Cloud. Know it exists and that it solves the same problem as Durable Functions across languages.
- Azure Functions triggers and bindings: a trigger is what starts a function (HTTP, timer, queue, Service Bus, blob, Event Grid). A binding is declarative input or output to another service, so you write less plumbing code. Durable Functions are started by a client function that is itself triggered this way.
- Code worth remembering: in an orchestrator, call activities with await context.CallActivityAsync("SendEmail", input). Use context.CurrentUtcDateTime, never DateTime.UtcNow.

6 Real-world use case
- Situation: an order process must charge the card, reserve inventory, then create a shipment. Any step can fail, and the shipment step may take hours.
- Choice: a Durable Functions orchestrator calls three activities in sequence. On failure it runs compensating activities (refund, release stock). This is a saga with orchestration.
- Trade-off: you get reliable long-running state and easy retries. You pay with replay complexity, a storage dependency, and harder debugging.
- Choose Logic Apps instead when the flow mostly connects SaaS systems and non-developers will maintain it.
- When NOT to use any of these: a simple queue plus one worker is enough for short single-step jobs. Also avoid them for high-throughput low-latency paths, because each step adds storage round trips.

11 Revision summary
- Workflow engine means durable state plus ordered steps plus retries.
- Durable Functions: orchestrator (deterministic) plus activities (side effects).
- Four patterns: chaining, fan-out/fan-in, human interaction with timeout, monitor.
- Logic Apps is low-code with connectors; Durable Functions is code-first.
- Temporal is the code-first alternative outside Azure.
- Trigger starts a function; binding connects input or output declaratively.
- Use context.CurrentUtcDateTime, not DateTime.UtcNow, inside orchestrators.
- Sagas with compensating actions are the typical use case.
