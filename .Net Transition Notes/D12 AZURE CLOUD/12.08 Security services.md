12.08 Security services

1 What is it
- Azure security services are the managed tools that protect secrets, network traffic, data and the overall posture of your subscriptions.
- Key Vault stores secrets, keys and certificates. Defender for Cloud scores and monitors your setup. NSG, WAF, Firewall and DDoS Protection filter traffic. Sentinel collects security events.
- Legacy equivalent: connection strings and certificates in Web.config, Windows Firewall and IIS rules, and an on-premises security team checking servers by hand.

2 Why needed
- Secrets in config files or repos leak, and a leaked key gives full access.
- Without layered network filtering, one open port exposes the whole app.
- Without posture checks, misconfigurations such as public storage go unnoticed.

3 Before you read
- Managed identity: an Azure-issued identity for an app, with no password to store.
- Azure RBAC: permissions given by role, at a scope.
- VNet and subnet basics.
- Encryption: symmetric versus asymmetric keys.

4 Features and core concepts
- Key Vault: a managed store for secrets (strings), keys (cryptographic keys) and certificates. It keeps secrets out of code and gives one place for rotation and audit. Tiers are Standard and Premium (HSM-backed keys).
- RBAC vs access policies: RBAC uses standard Azure roles such as Key Vault Secrets User. Access policies are the older per-vault model. Use RBAC, because it gives one permission model, per-secret scope and PIM support.
- Soft delete and purge protection: soft delete keeps a deleted vault or object recoverable for a retention period of 7 to 90 days (verify). Purge protection blocks permanent deletion until that period ends, and once enabled it cannot be turned off.
- App Service references: an app setting holds a pointer instead of the secret. The app's managed identity reads the value at runtime. Format: @Microsoft.KeyVault(SecretUri=https://myvault.vault.azure.net/secrets/mysecret/)
- Managed HSM: a single-tenant, dedicated hardware-backed key store for strict compliance. Awareness level only.
- Defender for Cloud plans: the free tier gives posture checks and recommendations. Paid plans protect specific resource types, such as servers, App Service, storage, SQL, containers and Key Vault (verify current plan names).
- NSG: filters traffic at subnet or NIC level by IP, port and protocol. WAF (on Application Gateway or Front Door) blocks web attacks such as SQL injection and XSS. Azure Firewall is a central managed firewall with FQDN and threat-intel rules. They work together in layers.
- DDoS: basic protection is always on. DDoS Protection (network or IP tiers, verify) adds tuning, telemetry and cost protection for public IPs.
- Encryption: at rest is on by default (storage and SQL use platform-managed keys). In transit means TLS (use 1.2 or higher). Customer-managed keys keep the key in your Key Vault, so you control rotation and revocation.
- Sentinel: a cloud SIEM (security event collector and alerting) built on Log Analytics. Awareness only.
- Security baselines: the Microsoft cloud security benchmark gives per-service hardening guidance. Defender for Cloud assesses against it.
- Secure score: a percentage showing how many recommended controls you have met.

5 Core focus (exam and interview)
- Most asked: RBAC versus access policies, and how an app reads a secret with no password (managed identity).
- Soft delete is always on for new vaults. Purge protection is optional and irreversible.
- NSG filters at layers 3 and 4. WAF works at layer 7. Firewall is central and stateful.
- Customer-managed keys sit in Key Vault or Managed HSM, and the service needs access to the key.
- Defender for Cloud free tier recommends only. Paid plans detect threats.

6 Real-world use case
- Situation: a migrated .NET API on App Service uses SQL and Storage, and the connection string sat in Web.config.
- Choice: store secrets in Key Vault with RBAC, grant the app's managed identity the Secrets User role, and use App Service references. Put Front Door with WAF in front, and enable Defender for the paid plans that fit.
- Trade-off: extra services add cost and setup, and Key Vault adds a runtime dependency.
- Do not use: Managed HSM or Premium tier for ordinary app secrets, or Firewall for a tiny single-app setup where NSG plus WAF is enough.

7 Interview lens
- Q: Why RBAC over access policies? A: One model across Azure, finer scope, PIM and audit. Access policies are legacy.
- Q: How does the app get a secret without credentials? A: Managed identity with a Key Vault role, using a reference or the SDK.
- Q: NSG versus WAF versus Firewall? A: NSG filters ports. WAF inspects web requests. Firewall controls outbound and central traffic.
- Q: What does purge protection do? A: It blocks permanent deletion during retention, so a mistake or attacker cannot destroy keys.

8 Common mistakes
- Granting Key Vault Administrator to apps. Fix: use Secrets User.
- Public vault endpoint left open. Fix: private endpoint or firewall rules.
- Customer-managed key vault without purge protection, so deleting the key makes data unreadable. Fix: enable it.
- Ignoring secure score recommendations. Fix: review weekly.

9 Mental model
- Castle layers: DDoS and Front Door/WAF at the gate, Firewall and NSG as inner walls, Key Vault as the locked room, Defender and Sentinel as guards watching.

10 Mini lab (30 minutes)
- Create a resource group and a Key Vault with RBAC: az keyvault create -n kv<unique> -g rg-lab --enable-rbac-authorization true
- Give yourself the Key Vault Secrets Officer role at the vault scope.
- Set a secret: az keyvault secret set --vault-name kv<unique> -n demo --value hello
- Create a web app, enable its system-assigned identity, grant it Key Vault Secrets User, and set an app setting to the @Microsoft.KeyVault(...) reference.
- Expected result: the setting shows a green "Key Vault Reference" status.
- Open Defender for Cloud and note your secure score.
- Clean-up: az group delete -n rg-lab. Purge the soft-deleted vault if it is not purge-protected.

11 Revision summary
- Key Vault holds secrets, keys and certificates.
- Prefer RBAC over access policies.
- Purge protection is irreversible.
- App Service references use the managed identity.
- NSG is layer 4, WAF is layer 7, Firewall is central.
- Encryption at rest is default, and customer-managed keys add control.
- Secure score is a percentage of recommendations met.
