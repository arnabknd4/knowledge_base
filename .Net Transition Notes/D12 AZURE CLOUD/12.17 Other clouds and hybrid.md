1 What is it
- A set of ideas for running systems outside a single cloud, or partly on your own hardware. Four parts: mapping services between AWS, GCP and Azure; Azure Arc; Azure Local; multi-cloud strategy and edge.
- Service mapping means knowing that a service in one cloud has a close cousin in another (example: Azure Blob Storage, AWS S3, GCP Cloud Storage).
- Azure Arc is a way to project servers, Kubernetes clusters and databases that live outside Azure into Azure, so you manage them from one place.
- Azure Local (verify) is Microsoft's hybrid platform that runs Azure-style services on hardware in your own data center or site.
- Multi-cloud means using more than one public cloud on purpose.
- Edge means running compute close to where data is produced (factory, store, branch office) instead of in a distant region.
- Legacy equivalent: an on-premises IIS and SQL Server estate with a VPN to a hosting provider, plus a mix of vendor tools to manage it.

4 Features and core concepts
- AWS and GCP service mapping: each major cloud service has a rough equivalent elsewhere. Why it matters: interviews, client conversations and migrations need you to translate quickly.
  - Compute: Azure VMs, AWS EC2, GCP Compute Engine
  - Containers: AKS, EKS, GKE
  - Serverless functions: Azure Functions, AWS Lambda, GCP Cloud Functions
  - Object storage: Blob Storage, S3, Cloud Storage
  - Relational database: Azure SQL, Amazon RDS, Cloud SQL
  - Messaging: Service Bus, SQS and SNS, Pub/Sub
  - Identity: Entra ID, AWS IAM and IAM Identity Center, Cloud IAM
  - Equivalent does not mean identical. Limits, pricing and behaviour differ. Check each provider's docs (verify).
- Azure Arc: an agent or connector registers a non-Azure resource in Azure Resource Manager. Why it matters: one control plane for Azure Policy, RBAC, tags, monitoring and Defender across on-premises, other clouds and edge.
  - Arc-enabled servers: Windows and Linux machines outside Azure
  - Arc-enabled Kubernetes: any CNCF-conformant cluster
  - Arc-enabled data services and SQL Server: run or manage them outside Azure (verify current scope)
  - Arc does not move the workload. It manages it where it sits.
  - Example command to connect a server: azcmagent connect (verify parameters)
- Azure Local (verify): Microsoft's hybrid infrastructure (previously Azure Stack HCI, verify naming) running on validated hardware in your site and managed through Azure. Why it matters: for data residency, low latency, or disconnected or limited-connectivity needs where public cloud is not allowed or practical. It runs VMs and Arc-enabled AKS on your own hardware.
- Multi-cloud strategy: using two or more clouds deliberately. Why it matters: reasons include regulation, acquisitions, avoiding a single point of provider failure, or best-of-breed services.
  - Costs: more skills, more tooling, lowest-common-denominator design, higher egress charges, more security surface.
  - Portable layers that help: Kubernetes, Terraform, OpenTelemetry, containers, open databases.
  - Most multi-cloud estates are accidental, not designed. Say this in interviews.
- Edge: processing at the site where data is created. Why it matters: lower latency, less bandwidth, works through network loss.
  - Typical pattern: local processing, buffered sync to cloud, central policy and monitoring
  - Azure options: Azure Local, Arc-enabled Kubernetes at the site, IoT services (verify names)

6 Real-world use case
- Situation: a Kolkata-based client has 40 Windows servers in a data center plus a small AWS footprint from an acquired company. Audit asks for one view of patching, policy and security.
- Choice: connect the servers and the EKS cluster with Azure Arc. Apply Azure Policy and Defender for Cloud from Azure. Send logs to one Log Analytics workspace.
- Trade-off: you gain central governance without moving workloads. You pay for Arc-enabled services where charged (verify pricing), and you now depend on agent connectivity and Azure control-plane access.
- When not to use it: if you are migrating everything to Azure within months (use Azure Migrate instead), or if the machines are fully air-gapped with no allowed outbound path. Also avoid multi-cloud itself when one cloud meets the need, because the operating cost is real.

11 Revision summary
- Service mapping gives similar, not identical, equivalents. Always verify limits and pricing.
- Azure Arc projects non-Azure resources into Azure for governance. It does not move them.
- Arc covers servers, Kubernetes and data services (verify current list).
- Azure Local (verify) runs Azure-style infrastructure on your own hardware, for residency and latency needs.
- Multi-cloud is a deliberate use of multiple clouds. Most real cases are accidental.
- Portable building blocks: Kubernetes, Terraform, containers, OpenTelemetry.
- Edge means compute near the data source, with buffered sync to cloud.
- Cost of multi-cloud: skills, tooling, egress and security surface.
