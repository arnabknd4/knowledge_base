1 What is it

- Compute means the Azure services that run your code. They sit on a scale from full control (virtual machines) to no server management (Functions).
- VM: a virtual machine, a full operating system you manage. App Service: managed hosting for web apps and APIs. Functions: small pieces of code that run when an event happens. Container Apps: managed containers without managing Kubernetes. AKS: Azure Kubernetes Service, managed Kubernetes for large container platforms.
- Legacy equivalent: a VM is your IIS server. App Service is IIS without the server patching. Functions resemble a Windows Service or scheduled task, but event-driven.

2 Why needed

- Your code needs somewhere to run. Each service trades control against operations work.
- Without a good choice you pay for idle servers, patch machines by hand, or fight a platform that is too complex for the team.

4 Features and core concepts

- VM sizes: families (general purpose, compute, memory optimized). Pick by CPU to memory ratio. Wrong size means waste or slowness.
- Disks: OS disk, data disks, and a temporary disk that loses data on restart. Types: Standard HDD, Standard SSD, Premium SSD, Ultra (verify). Keep data off the temp disk.
- Availability zones: separate datacenters in one region. Spread VMs across zones to survive a datacenter failure.
- Scale sets (VMSS): a group of identical VMs that autoscale. Gives elasticity without hand-built VMs.
- Images: the template a VM starts from (marketplace or custom image). Custom images give repeatable builds.
- App Service plan: the set of VMs that hosts your apps. The tier (Basic, Standard, Premium, Isolated) decides features and price. Many apps can share one plan.
- Slots: staging copies of an app, swapped into production. Gives zero-downtime releases. Needs Standard tier or above (verify).
- Scaling: scale up changes the tier. Scale out adds instances, manually or by rule.
- VNet integration: lets the app call private resources in your VNet (outbound only). Private Endpoint is for inbound.
- Custom domains and TLS: bind your own hostname and certificate. App Service managed certificates are free for basic cases (verify).
- Functions hosting plans: Consumption (pay per execution, scales to zero), Flex Consumption (verify), Premium (pre-warmed, VNet), Dedicated (runs on an App Service plan). Plan choice drives cold start and timeout.
- Triggers and bindings: a trigger starts the function (HTTP, timer, queue). Bindings read or write data without SDK code. Each function has exactly one trigger.
- Container Apps: serverless containers with revisions, scale by KEDA rules, built-in ingress. Good middle ground.
- AKS: you get Kubernetes with Azure running the control plane. You still manage nodes and upgrades. Covered in D08.
- Choosing compute: ask about control needed, operations load, scaling pattern, cost, team skill.
- Cost levers: reservations (1 or 3 year commitment on specific resources), savings plans (hourly spend commitment across compute), spot (cheap, evictable VMs), hybrid benefit (reuse Windows or SQL licences). Commitments save money only if usage is steady.

5 Core focus (exam and interview)

- Availability set vs zone: zones protect against datacenter failure and carry the higher SLA (verify numbers).
- Slots need Standard or above. Scale up vs out.
- Consumption plan: scales to zero but has cold starts and a default timeout (verify).
- Spot VMs can be evicted at short notice. Never use them for stateful or critical work.
- Temp disk is not persistent.
- Reservation vs savings plan: reservation is specific, savings plan is flexible.

6 Real-world use case

- Situation: an IIS-hosted MVC app moves to Azure with a nightly export job.
- Choice: web app on App Service (Standard, two instances, staging slot, VNet integration to Azure SQL). The export becomes a timer-triggered Function.
- Trade-off: less control than VMs, but no patching and easy slot swaps.
- Do not use: App Service for apps needing Windows services, custom drivers or unsupported installers (use VMs). Do not use Functions for long-running jobs on the Consumption plan.

7 Interview lens

- When App Service over AKS? Answer: when you have few web apps and a small team. AKS adds operations load you must justify.
- How do you deploy with no downtime? Answer: deploy to a staging slot, warm it, run smoke tests, then swap.
- Consumption vs Premium Functions? Answer: Consumption is cheapest and scales to zero but has cold starts. Premium pre-warms and supports VNet.
- How to cut VM cost? Answer: right-size, reservations or savings plan for steady load, spot for interruptible work, hybrid benefit for licences.

8 Common mistakes

- Data on the temp disk is lost after restart. Use data disks.
- One VM in one zone looks fine until a zone fails. Spread across zones.
- Testing in production because slots were not used. Use slots.
- Everything on one App Service plan, so one noisy app slows others. Split by load.
- Buying reservations for workloads that later move to containers. Commit only to steady workloads.

9 Mental model

- A ladder of control: VM -> App Service -> Container Apps -> AKS -> Functions sits at the other end (least control, least work).
- More control means more operations work. Choose the lowest rung that meets your needs.

10 Mini lab

- Time: about 30 minutes. Use the Azure free tier and Cloud Shell.
- Step 1: az group create -n rg-lab-compute -l centralindia
- Step 2: az appservice plan create -g rg-lab-compute -n plan-lab --sku S1
- Step 3: az webapp create -g rg-lab-compute -p plan-lab -n <unique-name> --runtime "dotnet:8" (verify runtime string)
- Step 4: az webapp deployment slot create -g rg-lab-compute -n <unique-name> --slot staging
- Step 5: az webapp deployment slot swap -g rg-lab-compute -n <unique-name> --slot staging
- Expected: the app URL responds, the staging slot has its own URL, and the swap completes without error.
- Note: S1 is paid (verify cost). Delete soon after.
- Clean-up: az group delete -n rg-lab-compute --yes --no-wait

11 Revision summary

- VM = full control, you patch. App Service = managed web hosting. Functions = event-driven code. Container Apps = serverless containers. AKS = managed Kubernetes.
- Temp disk is not persistent.
- Zones protect against datacenter failure.
- Slots need Standard or above and give zero-downtime swaps.
- VNet integration is outbound. Private Endpoint is inbound.
- Consumption Functions scale to zero but have cold starts.
- Reservation is specific, savings plan is flexible, spot can be evicted.
- Hybrid benefit reuses existing Windows or SQL licences.
