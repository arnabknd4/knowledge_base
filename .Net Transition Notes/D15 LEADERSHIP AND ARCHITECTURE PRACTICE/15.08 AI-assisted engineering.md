15.08 AI-assisted engineering

1 What is it
- Using AI coding assistants and chat models as a helper inside normal software work: writing code, reviewing, writing tests and documentation.
- The engineer stays responsible for every line that ships. The AI is a fast, fallible junior teammate.
- Legacy equivalent: Code snippets copied from Stack Overflow or old team wikis, and Visual Studio IntelliSense or ReSharper suggestions. Now the tool writes whole blocks, so checking matters more.

4 Features and core concepts
- Using coding assistants safely: treat output as untrusted code. Read it, run it, test it. It matters because it can look correct and still be wrong or insecure.
- Prompt patterns for review, tests and documentation: give context, the task, constraints and the output format. For review, ask for risks and missing cases. For tests, ask for edge cases and failure paths. For docs, ask for a draft you then correct.
- Data privacy rules: never paste secrets, client code or personal data into tools your client has not approved. It matters because client contracts and the India DPDP Act (verify) can make this a breach.
- Checking for hallucinations: AI can invent APIs, packages, versions and limits. Confirm every package, method and setting against official docs. Check that a suggested NuGet package really exists before installing it.
- AI in the SDLC: usable in requirements, design drafts, coding, test generation, code review, incident summaries. It matters because the gain comes from small steps with a human gate, not from automating everything.
- RAG and agent architecture awareness: RAG (retrieval-augmented generation) fetches your own documents and feeds them to the model, so answers rest on your data. An agent is a model that calls tools in a loop. Know the parts: model, retrieval store, tools, guardrails, logging.
- Azure OpenAI and Foundry awareness (verify): Microsoft's hosted model services with enterprise controls. Names and features change often, so check Microsoft Learn.

6 Real-world use case
- Situation: your team migrates a legacy MVC app to modern .NET and needs unit tests for old, untested classes.
- Choice: use an assistant to draft test cases on non-sensitive code. A senior engineer reviews each test, and CI must pass before merge.
- Trade-off: you save hours of typing, but you spend review time and risk tests that only mirror the current bugs.
- When NOT to use it: code with secrets or client data on an unapproved tool, security-critical logic such as authentication or cryptography without expert review, and any area where nobody on the team can judge the output.
