1 What is it

Go, also called Golang, is a compiled programming language designed for building efficient software, network services, command-line tools, and infrastructure tooling.

DevOps engineers encounter Go because important cloud-native tools, including Kubernetes and Terraform, are written primarily in Go. You do not need to become an expert Go developer to work with these tools, but understanding basic Go syntax helps you read source code, investigate errors, and build small utilities.

A command-line interface (CLI) is a program operated through terminal commands. A small Go CLI might validate configuration, inspect files, call an API, or automate a deployment task.

Legacy equivalent: Shell scripts and compiled system utilities used to automate infrastructure and operating-system tasks.

2 Why needed

* Tool awareness: Understand why many infrastructure tools use Go.
* Troubleshooting: Read source code and error paths when investigating tool behavior.
* Extensibility: Build small utilities when shell scripting becomes difficult to maintain.
* Portability: Go can compile programs for different operating systems and processor architectures.
* Concurrency: Go provides goroutines and channels for coordinating concurrent work.
* Ecosystem understanding: Recognize how Go contributes to cloud-native infrastructure and DevOps tooling.

For this syllabus topic, the goal is awareness rather than advanced application development.

3 Before you read

* Understand the difference between source code and a compiled executable.
* Have access to a terminal; installing Go is needed for the mini lab.

4 Features and core concepts

* Compiled language: Go source code is compiled into an executable program. This can simplify distribution because the target machine usually does not need a Go interpreter to run the compiled binary.
* Static typing: Variables and expressions have defined types. The compiler catches many type errors before the program runs.
* Simple syntax: Go deliberately keeps its language features relatively compact. This can make code easier to read across teams.
* Packages: Packages group related functions, types, and other declarations. They provide a structure for organizing and reusing code.
* Modules: A Go module defines a project’s dependency and version-management boundary, typically using a `go.mod` file.
* Error handling: Go commonly returns errors as explicit values. Callers check and handle errors rather than relying exclusively on exceptions.
* Structs: A struct groups related fields into a single data type. It is often used to represent configuration, API responses, or other records.
* Interfaces: An interface describes behavior through a set of method requirements. Interfaces allow code to work with different implementations without depending on their concrete types.
* Goroutines: Goroutines are lightweight concurrent execution units managed by the Go runtime. They help programs perform multiple activities concurrently.
* Channels: Channels allow goroutines to communicate and coordinate by passing values. They are useful for certain concurrent workflows but are not necessary for every concurrency problem.
* CLI programs: A Go program can read command-line arguments, process input, print output, and return an exit status. These are the core building blocks of small operational tools.
* Cross-compilation: Go supports building programs for different operating systems and processor architectures, subject to target-specific constraints. The resulting executable must match the intended deployment environment.
* Cloud-native tooling: Kubernetes and Terraform are prominent examples of infrastructure tools written primarily in Go. Their language choice does not mean that operating or configuring them requires extensive Go knowledge.

6 Real-world use case

A DevOps team needs a small utility that reads a configuration file, validates required settings, and exits with a clear status code before a deployment begins.

A Go CLI can perform validation, print actionable error messages, and return a non-zero exit code when the configuration is invalid. The deployment pipeline can stop if the validation program fails.

Trade-off: A compiled Go utility can be easy to distribute and run, but developing it introduces a build process and programming-language maintenance. For a short, straightforward task, an existing CLI command or shell script may be simpler. Choose Go when the utility benefits from stronger structure, portability, or more substantial logic.

7 Interview lens

* Why is Go common in DevOps tooling?

  Go supports compiled executables, relatively simple syntax, and concurrency features. These properties are useful for infrastructure tools that need to run across environments.

* What is the purpose of `go.mod`?

  It defines a Go module and records module information, including dependency requirements. It helps manage the project’s dependency graph and versions.

* How does Go commonly handle errors?

  Functions often return an error value alongside a result. Callers inspect the error and decide whether to continue, recover, or terminate.

* What is a goroutine?

  A goroutine is a lightweight execution unit managed by the Go runtime. It allows code to execute concurrently with other goroutines.

8 Common mistakes

* Assuming every DevOps engineer must become an advanced Go developer.
* Confusing compilation with interpretation.
* Ignoring returned errors and continuing with invalid results.
* Forgetting that a compiled binary must match the target operating system and architecture.
* Adding concurrency when a simple sequential program would be easier to understand.
* Assuming interfaces and structs are interchangeable concepts.
* Changing a tool's source code before checking whether configuration or an existing extension point can solve the problem.
* Treating a third-party Go dependency as trustworthy without reviewing its origin and version.

9 Mental model

Think of Go as a language for building operational tools.

* Source code describes the program.
* The compiler turns the source into an executable.
* Packages organize the implementation.
* Modules manage the project and its dependencies.
* Structs represent grouped data.
* Interfaces describe behavior.
* Error values communicate failures.
* Goroutines and channels support concurrency.
* A CLI connects the program to scripts, terminals, and automation pipelines.

As a DevOps engineer, aim to read simple Go code, understand how the program is built, and recognize where errors and configuration are handled.

10 Mini lab

Goal: Write, compile, and run a minimal Go CLI program.

Requirements: Go installed on your machine. Check installation using `go version`.

Steps:

* Create a directory named `go-cli-lab` and enter it.
* Initialize a Go module with `go mod init example.com/go-cli-lab`.
* Create a file named `main.go`.
* Add the following program:

```go
package main

import (
	"fmt"
	"os"
)

func main() {
	if len(os.Args) < 2 {
		fmt.Fprintln(os.Stderr, "Usage: go-cli-lab <name>")
		os.Exit(1)
	}
	fmt.Printf("Hello, %s!\n", os.Args[1])
}
```

* Run the program with `go run . DevOps`.
* Run it without an argument using `go run .` and observe the usage message and failure status.
* Build the executable with `go build -o go-cli-lab`.
* Run the compiled program with `./go-cli-lab Engineer` on Linux or macOS. On Windows, run `.\go-cli-lab.exe Engineer` if the executable was built with that name.
* Inspect `main.go` and identify the package, imports, `main` function, argument handling, and exit code.

Expected result: The program prints a greeting when given an argument. Without an argument, it prints usage information to standard error and exits unsuccessfully.

Clean-up: Leave the lab directory and delete it when finished. Remove any generated executable if you want to keep the source files.
