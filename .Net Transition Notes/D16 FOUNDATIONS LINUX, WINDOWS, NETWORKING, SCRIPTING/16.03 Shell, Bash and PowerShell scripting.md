1 What is it

Shell, Bash, and PowerShell scripting are ways to automate operating-system and cloud tasks by writing commands into reusable scripts.

A shell is a command interpreter that lets you run programs and work with files, processes, and system settings. Bash is a common shell on Linux. PowerShell is a command-line shell and scripting language available on Windows, Linux, and macOS.

A script is a saved sequence of commands that performs a task. Instead of manually repeating the same steps, you write the steps once and run them when needed.

Shell scripting is especially useful for Linux administration, deployment pipelines, log processing, and automation. PowerShell is widely used for Windows administration and Azure automation. Both can be used to manage files, call APIs, start processes, and coordinate other tools.

Legacy equivalent: Manually running commands in a terminal or using older Windows batch files.

2 Why needed

* Repeatability: Run the same process consistently across machines and environments.
* Speed: Automate repetitive operations such as checking services, processing logs, and deploying applications.
* Reliability: Validate inputs and check command results instead of assuming every operation succeeded.
* Integration: Combine operating-system commands, HTTP requests, JSON processing, and cloud tools.
* Troubleshooting: Collect diagnostic information automatically when an application or server fails.
* Infrastructure automation: Use scripts to support provisioning, configuration, deployment, and maintenance.

Scripts can also cause widespread damage if they run with excessive permissions or contain unsafe assumptions. Test them in a non-production environment before using them on important systems.

4 Features and core concepts

* Variables and quoting: Variables store values. Quoting controls how text is interpreted. Correct quoting prevents spaces and special characters from being handled unexpectedly.
* Conditionals and loops: `if` statements make decisions, while loops repeat actions. They allow scripts to handle different conditions and process lists.
* Functions: Named blocks of reusable logic. Functions reduce duplication and make scripts easier to test.
* Exit codes: Numeric results returned by commands. Conventionally, zero means success and a non-zero value indicates failure.
* Pipes and redirection: A pipe sends one command’s output to another command. Redirection writes output to a file or changes where input comes from.
* `set -euo pipefail`: A commonly used Bash safety setting. It helps detect certain command failures, unset variables, and pipeline failures, but it is not a substitute for explicit error handling.
* Argument parsing: Reads values supplied when a script starts. This lets one script work with different filenames, environments, or options.
* `trap`: Runs specified handling code when selected signals or shell exit events occur. It can support cleanup, such as removing temporary files.
* Idempotency: A script is idempotent when rerunning it produces the same intended end state rather than repeatedly creating changes. This is important for deployment and configuration automation.
* `jq` and `curl`: `curl` transfers data to or from URLs; `jq` processes JSON. Together, they are useful for API automation.
* ShellCheck: A static analysis tool that identifies common problems in shell scripts.
* PowerShell objects and pipeline: PowerShell typically passes structured objects between commands rather than only plain text. This makes filtering and manipulating command results more reliable.
* Modules: Packages of reusable PowerShell commands and related functionality.
* Az module: A collection of PowerShell modules used to manage Azure resources and services. Specific command behavior and authentication options can change (verify).

5 Core focus (exam and interview)

* Explain the difference between Bash and PowerShell. Bash is common in Linux automation and frequently processes text streams. PowerShell works with structured objects and is useful for Windows and Azure administration.
* Know how to assign variables, use conditions, loop through items, and define functions.
* Understand exit codes and why a script should check whether important operations succeeded.
* Explain pipes and redirection, including the difference between sending output to another command and saving it to a file.
* Know the purpose and limitations of `set -euo pipefail`.
* Explain idempotency and why rerunning a deployment script should not cause duplicate or destructive changes.
* Understand how `curl` and `jq` can be combined to call an API and inspect its JSON response.
* Know how PowerShell’s object pipeline differs from text-oriented shell pipelines.
* Explain why scripts should validate inputs, avoid exposing secrets, log useful errors, and use the minimum required permissions.

6 Real-world use case

A deployment team needs to check an application health endpoint after deploying a new release.

A Bash script can call the endpoint with `curl`, inspect the response, and return a failure code if the check does not pass. A PowerShell script can perform a similar check using its HTTP and object-processing capabilities.

The deployment pipeline can use the script’s exit code to decide whether to continue or stop.

Trade-off: Scripts are fast to create and easy to integrate with automation tools, but complex scripts can become difficult to maintain. Use functions, meaningful error messages, input validation, and tests. For large workflows involving complex dependencies or extensive business logic, a dedicated application or configuration-management tool may be more appropriate.

7 Interview lens

* Why should scripts check exit codes?

  Exit codes communicate whether commands succeeded. Checking them prevents later steps from proceeding as if a failed operation had worked.

* What is the purpose of quoting variables in Bash?

  Quoting helps preserve spaces and prevents unintended word splitting and wildcard expansion. Use double quotes around most variable expansions unless intentional splitting or expansion is required.

* What is idempotency?

  Idempotency means repeated execution produces the same intended state. It reduces duplicate changes and makes automation safer to retry.

* How does PowerShell’s pipeline differ from Bash’s pipeline?

  PowerShell generally passes structured objects between commands. Bash pipelines usually pass streams of text, so text parsing and quoting require particular care.

8 Common mistakes

* Forgetting to quote Bash variables containing paths or user-supplied values.
* Assuming a command succeeded without checking its result.
* Using `set -e` as if it handled every possible error automatically.
* Writing scripts that make destructive changes without validating arguments.
* Hardcoding passwords, tokens, or other secrets into scripts.
* Assuming API responses always contain valid JSON or the expected fields.
* Ignoring cleanup when scripts fail halfway through.
* Repeating resource-creation steps without checking whether the desired resource already exists.
* Treating PowerShell output as plain text when commands actually return structured objects.
* Running scripts with administrator or root privileges when lower privileges would suffice.

9 Mental model

Think of a script as a small automated operator.

* Inputs tell it what to work on.
* Variables store information.
* Conditions decide what should happen.
* Loops repeat work.
* Functions organize reusable steps.
* Pipes connect operations.
* Exit codes report outcomes.
* Error handling controls what happens when something fails.

A reliable script does not merely execute commands. It checks assumptions, handles failures, protects secrets, and leaves the system in a predictable state.

10 Mini lab

Goal: Write a Bash script that checks a website endpoint and reports whether the request succeeded.

Requirements: A Bash-compatible terminal and `curl`. Use a public endpoint or a local test endpoint you control.

Steps:

* Check that Bash is available by running `bash --version`.
* Check that `curl` is installed by running `curl --version`.
* Create a file named `health-check.sh`.
* Add the following script:

```bash
#!/usr/bin/env bash
set -euo pipefail
url="${1:?Usage: ./health-check.sh URL}"
if curl --fail --silent --show-error "$url" -o /dev/null; then
  echo "Health check passed"
else
  echo "Health check failed" >&2
  exit 1
fi
```

* Save the file.
* Make it executable with `chmod +x health-check.sh`.
* Run it with an endpoint you are permitted to access, for example `./health-check.sh https://example.com`.
* Check the exit code immediately after execution with `echo $?`.
* Test a deliberately invalid hostname to observe how a failed request is reported.
* Inspect the script and identify its input validation, variable, conditional, quoting, and exit-code behavior.

Expected result: A successful request prints `Health check passed` and returns exit code zero. A failed request reports an error and returns a non-zero exit code.

Clean-up: Remove the lab script with `rm health-check.sh` when finished.

11 Revision summary

* Bash and PowerShell automate command-line tasks through reusable scripts.
* Variables, conditionals, loops, and functions provide basic scripting structure.
* Quoting is essential for safely handling spaces and special characters.
* Exit codes help automation detect failures and decide whether to continue.
* Pipes connect commands; redirection changes where input or output goes.
* `curl` handles URL transfers, while `jq` processes JSON data.
* Idempotency makes scripts safer to rerun.
* PowerShell pipelines generally pass structured objects, while Bash pipelines commonly pass text.
