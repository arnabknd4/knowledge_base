1 What is it

Python for automation means using Python scripts to perform repetitive operational tasks, work with files and APIs, run system commands, and manage cloud resources.

Python is a general-purpose programming language. It is useful for automation because it has readable syntax, a large ecosystem of libraries, and built-in support for handling files, structured data, and processes.

A Python automation script might read a configuration file, call an API, process the response, log the result, and return an error if an operation fails.

The syllabus focuses on virtual environments and pip, files, JSON and YAML, HTTP requests, subprocesses, argument parsing, logging, exceptions, Azure SDK and CLI scripting, and basic tests.

Legacy equivalent: Manually running commands and processing files by hand, or using simple shell scripts for repetitive tasks.

2 Why needed

* Repeatability: Perform the same operation consistently without manually repeating each step.
* File processing: Read and update configuration files, reports, and deployment data.
* API integration: Communicate with web services and cloud platforms.
* Operational control: Run external commands such as Azure CLI commands from a Python script.
* Troubleshooting: Record events and errors through logging and exception handling.
* Reusability: Turn a frequently performed task into a script with configurable arguments.
* Testing: Check that automation behaves as expected before relying on it in production.

Python does not automatically make an operation safe. Scripts still need validation, permission controls, error handling, and testing.

3 Before you read

* Know basic Python syntax, variables, conditions, loops, and functions.

* Know the purpose of HTTP requests and JSON data.
* Have Python installed and access to a terminal.

4 Features and core concepts

* Virtual environments (`venv`): A virtual environment isolates a project's Python packages from other projects. This helps prevent dependency conflicts and makes the project's environment easier to reproduce.
* pip: Python's package installer. It installs libraries that a script needs. Pinning dependencies and tracking them in a requirements file can help make installations more consistent.
* Files: Python can read, write, and update files. Use context managers such as `with open(...)` so files are closed properly, including when errors occur.
* JSON: JavaScript Object Notation is a structured data format commonly used by APIs. Python's `json` module can convert JSON text into Python objects and serialize Python data back into JSON.
* YAML: YAML is a human-readable data format frequently used for configuration. A third-party library such as PyYAML can parse YAML. Treat untrusted YAML carefully and use safe parsing functions.
* `requests`: A popular third-party Python library for making HTTP requests. It can call APIs, send headers, and process responses. Set timeouts and check HTTP status codes rather than assuming every request succeeds.
* `subprocess`: Python's standard-library module for launching external programs. It is useful for invoking command-line tools, but commands and arguments should be handled carefully to avoid command injection.
* `argparse`: A standard-library module for defining command-line arguments and options. It allows a script to accept inputs such as a filename, environment, or resource identifier.
* Logging: Python's `logging` module records operational messages at levels such as DEBUG, INFO, WARNING, ERROR, and CRITICAL. Good logs help diagnose failures without requiring the script to be run interactively.
* Exceptions: Exceptions represent errors or unusual conditions during execution. Use `try` and `except` to handle expected failure cases, and avoid silently swallowing errors.
* Azure CLI scripting: The Azure command-line interface (Azure CLI) provides commands for managing Azure resources. Python can invoke it with `subprocess` or use its output as part of an automation workflow.
* Azure SDK: The Azure software development kits provide Python libraries for interacting with Azure services directly. SDK authentication, permissions, and package choices depend on the service and environment (verify).
* Basic tests: Tests check whether individual functions and scripts produce expected results. They help detect regressions when automation changes.

6 Real-world use case

A team needs a daily report of selected Azure resources.

A Python script could accept the target environment as a command-line argument, authenticate using an approved Azure identity, retrieve resource information through the Azure SDK or Azure CLI, convert the results into structured data, and write a JSON report. Logging would record the run, while exceptions would help identify authentication or network failures.

The script should validate its inputs, use appropriate permissions, and avoid writing credentials or access tokens to logs.

Trade-off: Python automation can combine many operations in one maintainable workflow, but it introduces runtime and dependency management. For simple one-line tasks, a shell command may be sufficient. For substantial automation, use version control, tests, structured logs, and a controlled execution environment.

7 Interview lens

* Why use a Python virtual environment?

  It isolates project dependencies so different projects can use different package versions without interfering with one another.

* What is the difference between JSON and YAML?

  Both represent structured data. JSON has a strict data syntax and is common in APIs; YAML is often chosen for human-edited configuration because it supports a more compact presentation.

* Why should HTTP requests have timeouts?

  Without a timeout, a script may wait too long for a server that is slow or unreachable. Timeouts help automation fail or recover in a controlled way.

* When would you use the Azure SDK instead of Azure CLI?

  The SDK is useful when Python code needs direct access to Azure service APIs and structured results. Azure CLI is convenient when an existing workflow already relies on CLI commands; the better choice depends on the task and environment.

8 Common mistakes

* Installing packages globally when a project virtual environment should be used.
* Forgetting to record dependencies needed to reproduce the environment.
* Assuming an HTTP request succeeded without checking the status.
* Omitting timeouts from network calls.
* Parsing JSON or YAML without handling invalid input.
* Building shell command strings from untrusted input.
* Catching every exception and then continuing as if nothing went wrong.
* Logging secrets, credentials, tokens, or sensitive configuration.
* Writing scripts that depend on interactive prompts when they need to run unattended.
* Testing only the successful path and ignoring failure cases.

9 Mental model

Think of an automation script as a controlled workflow:

* Arguments define what the script should do.
* Files and configuration provide input.
* Python functions perform the processing.
* Requests or Azure tools communicate with external services.
* Exceptions handle failures.
* Logging records what happened.
* Tests check that important behavior remains correct.

A good automation script should be predictable, observable, configurable, and safe to run repeatedly.

10 Mini lab

Goal: Create a Python script that accepts a URL, requests it, logs the result, and handles failures.

Requirements: Python and terminal access. Internet access is needed for the example URL.

Steps:

* Create a directory named `python-automation-lab`.
* Enter the directory and create a virtual environment with `python -m venv .venv`.
* Activate it. On Linux or macOS, run `source .venv/bin/activate`; on Windows PowerShell, run `.\.venv\Scripts\Activate.ps1`.
* Install the HTTP library with `python -m pip install requests`.
* Create a file named `check_url.py` with the following content:

```python
import argparse
import logging
import requests

logging.basicConfig(level=logging.INFO)
parser = argparse.ArgumentParser()
parser.add_argument("url")
args = parser.parse_args()

try:
    response = requests.get(args.url, timeout=10)
    response.raise_for_status()
    logging.info("Request succeeded: HTTP %s", response.status_code)
except requests.RequestException as exc:
    logging.error("Request failed: %s", exc)
    raise SystemExit(1)
```

* Run it with `python check_url.py https://example.com`.
* Test an invalid URL or unreachable hostname and observe the error message and non-zero exit status.
* Review how `argparse`, logging, the timeout, and exception handling work.
* Optionally, run `python -m pip freeze` to inspect the installed packages.

Expected result: A successful request logs its HTTP status. A failed request produces an error log and exits with a non-zero status.

Clean-up: Deactivate the virtual environment with `deactivate`, then remove the lab directory when finished. On Windows, close any terminal session that is using files in that directory before removing it.

11 Revision summary

* `venv` isolates project dependencies; pip installs Python packages.
* Python's file handling supports reading and writing operational data.
* JSON is common for API data; YAML is widely used for configuration.
* `requests` supports HTTP calls; use timeouts and check response status.
* `subprocess` runs external commands and should be used carefully with untrusted input.
* `argparse` provides reusable command-line inputs.
* Logging and exceptions improve observability and failure handling.
* Azure CLI and Azure SDK are two approaches to Azure automation; choose based on the workflow and requirements.
