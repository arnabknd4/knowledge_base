16.01 Linux essentials

1 What is it

Linux essentials are the core skills needed to operate, troubleshoot, and maintain Linux systems. They include understanding files and directories, managing users and permissions, controlling processes and services, installing packages, inspecting logs, managing disks, and using command-line tools.

Linux is widely used for servers, cloud workloads, containers, automation, and infrastructure operations. Administrators often use a terminal to inspect system state and solve problems without a graphical interface.

* Filesystem hierarchy: The standard organization of files and directories in Linux.
* Permissions and ownership: Rules controlling who can read, write, or execute files.
* Process: A running instance of a program.
* Service: A background capability managed by the operating system, often through systemd.
* Shell: A command interpreter that lets you run programs and combine commands.
* Package manager: A tool for installing, updating, and removing software.
* Mount: Connecting a filesystem to a directory so its contents become accessible.
* Log: A record of system or application events.

Legacy equivalent: Windows Server administration using NTFS permissions, users and groups, Services, Event Viewer, Task Scheduler, disk management, and command-line tools.

2 Why needed

Linux knowledge helps you diagnose failures, understand server behavior, automate routine work, and manage infrastructure reliably.

It is useful for:

* Finding configuration files and logs.
* Diagnosing permission errors and failed commands.
* Checking whether services are running.
* Investigating CPU, memory, disk, and network problems.
* Installing and updating software safely.
* Connecting to remote systems over SSH.
* Writing scripts for repeatable administrative tasks.
* Managing storage and understanding where filesystems are mounted.

The key skill is not memorizing every command. It is learning how to inspect the system, form a hypothesis, test it, and verify the result.

3 Before you read

* Understand basic computer concepts such as files, directories, programs, and memory.
* Know how to open a terminal and enter commands.
* Understand the difference between an ordinary user and an administrator.
* Know that commands can read information or change system state.

4 Features and core concepts

* Filesystem hierarchy

  * Plain meaning: Linux organizes files under one root directory, written as `/`. Directories such as `/etc`, `/var`, `/home`, and `/usr` have common purposes.
  * Why it matters: Knowing the layout helps you locate configuration, logs, user files, and installed software.
  * Common paths:

    * `/etc`: System and application configuration.
    * `/var/log`: Many system and application logs.
    * `/home`: Home directories for ordinary users.
    * `/tmp`: Temporary files.
    * `/usr`: Many installed programs, libraries, and shared files.
    * `/dev`: Device interfaces exposed as files.
    * `/proc`: Virtual filesystem exposing process and kernel information.
    * `/root`: Home directory of the root user.

* Permissions and ownership

  * Plain meaning: Each file has an owner, a group, and permission bits for the owner, group, and others.
  * Why it matters: Permissions protect files and prevent unauthorized access or modification.
  * Read (`r`): Read file contents or list directory entries, subject to directory permissions.
  * Write (`w`): Modify a file or change directory entries, subject to other restrictions.
  * Execute (`x`): Run an executable file or traverse a directory.
  * `chmod` changes permission bits. `chown` changes ownership. `umask` influences default permissions for newly created files.

* Users, groups, and sudo

  * Plain meaning: Users represent identities. Groups help assign shared access. `sudo` allows authorized users to run commands with elevated privileges.
  * Why it matters: Administrative access should be limited to tasks that need it.
  * Use `whoami` to see the current user and `id` to inspect user and group IDs.
  * Avoid running every command as root. Elevated privileges increase the impact of mistakes.

* Processes and signals

  * Plain meaning: Processes are running programs. Signals notify processes of events, including requests to terminate.
  * Why it matters: A process may consume excessive resources, hang, or stop unexpectedly.
  * `ps` lists processes. `top` provides a changing view of system activity. `kill` sends a signal to a process.
  * Prefer normal termination before forceful termination. Forcing a process to stop can cause data loss or leave work incomplete.

* systemd and journalctl

  * Plain meaning: On many modern Linux distributions, systemd manages services and other system activities. `systemctl` controls and inspects services, while `journalctl` reads logs stored in the systemd journal.
  * Why it matters: A service can fail even when the server itself is running.
  * Memorize:

    * `systemctl status ssh`
    * `journalctl -u ssh`
  * Service names vary by distribution. Some systems use `sshd` instead of `ssh`.

* Package managers

  * Plain meaning: Package managers install, update, and remove software while tracking package dependencies.
  * Why it matters: Managed packages are generally easier to update and maintain than manually copied binaries.
  * Debian and Ubuntu commonly use `apt`. RHEL-family distributions commonly use `dnf`. Other systems may use different tools.
  * Package names and available versions depend on the distribution and configured repositories.

* Cron and timers

  * Plain meaning: Cron schedules commands to run at specified times. systemd timers provide another way to schedule tasks.
  * Why it matters: Backups, maintenance jobs, and periodic scripts often need to run without manual intervention.
  * Scheduled jobs need logging, correct permissions, and a suitable execution environment. A script that works in an interactive terminal may fail when scheduled.

* Disks, LVM, and mounts

  * Plain meaning: Disks provide storage. Filesystems organize data on storage. Mounting makes a filesystem accessible at a directory. Logical Volume Manager (LVM) adds a flexible layer for managing storage volumes.
  * Why it matters: Full disks, incorrect mounts, or storage configuration errors can interrupt applications.
  * `df -h` shows filesystem capacity. `du -sh` estimates directory usage. `lsblk` displays block devices.
  * Be careful: formatting, repartitioning, and changing mounts can destroy data or prevent a system from booting.

* SSH

  * Plain meaning: Secure Shell provides encrypted remote access to systems. SSH keys can authenticate users without relying on password authentication for every connection.
  * Why it matters: Administrators need secure access to remote servers.
  * SSH configuration can define hosts, usernames, identity files, and connection options. Tunnels can forward traffic through an SSH connection.
  * Protect private keys and verify host identity. Do not expose SSH unnecessarily to untrusted networks.

* Logs and resource tools

  * Plain meaning: Logs record events. Resource tools show CPU, memory, disk, file, and network activity.
  * Why it matters: Troubleshooting requires evidence, not guesses.
  * `free` inspects memory, `vmstat` reports memory and system activity, `iostat` reports storage I/O when available, `ss` shows socket information, and `lsof` lists open files.
  * `df` reports filesystem space; `du` helps identify which directories consume space. These commands answer different questions.

* Text tools

  * Plain meaning: `grep` searches text, `sed` transforms text, `awk` processes structured lines, `find` locates files, `xargs` builds command arguments, and `tail` displays the end of a file.
  * Why it matters: Logs and configuration files can be large. Text tools help isolate relevant information quickly.
  * Example: `grep -i error /var/log/syslog` searches for lines containing “error” on systems using that log file. The path and log format vary by distribution.

* Environment variables

  * Plain meaning: Environment variables pass configuration information to programs. `PATH` lists directories searched for executable commands.
  * Why it matters: Scripts and applications often depend on environment settings.
  * `printenv` displays environment variables. `export NAME=value` sets a variable for the current shell and its child processes.

* tar

  * Plain meaning: `tar` groups files and directories into an archive and can extract them later. Compression may be added using supported options.
  * Why it matters: Archives are useful for packaging files, moving data, and preparing backups.
  * Inspect archive contents before extracting untrusted files, especially when extracting into sensitive directories.

* SELinux awareness

  * Plain meaning: Security-Enhanced Linux provides mandatory access controls that can restrict actions beyond ordinary file permissions.
  * Why it matters: An application can be denied access even when standard ownership and permissions appear correct.
  * When investigating a denial, check relevant logs and security contexts rather than immediately disabling SELinux. Exact commands and behavior depend on the distribution and configuration.

5 Core focus

For exams and interviews, focus on troubleshooting and explaining what commands tell you.

* Filesystem: Explain the purpose of `/etc`, `/var/log`, `/home`, and `/tmp`.
* Permissions: Interpret a permission string such as `rwxr-x---` and explain ownership.
* Users: Distinguish ordinary user access from root privileges and `sudo`.
* Processes: Find a process, inspect resource use, and terminate it safely.
* Services: Check service status and use logs to investigate failure.
* Packages: Identify the package manager appropriate for the distribution.
* Storage: Distinguish device discovery, filesystem capacity, directory usage, and mounting.
* SSH: Explain key-based authentication and basic client configuration.
* Logs: Filter log entries and correlate them with a failure.
* Resource diagnosis: Distinguish CPU pressure, memory pressure, disk capacity, disk I/O, and network socket issues.
* Shell tools: Combine commands to search and process text.
* Scheduling: Explain how cron jobs and systemd timers differ at a basic level.
* Security: Explain why disabling SELinux or using root for everything is a poor default.

6 Real-world use case

A Linux application server stops responding to requests. The application team reports that it worked earlier in the day.

A disciplined investigation could look like this:

* Check service status with `systemctl status <service>`.
* Inspect recent service logs using `journalctl -u <service>`.
* Check disk capacity using `df -h`.
* Check memory using `free -h`.
* Inspect active processes using `top` or `ps`.
* Inspect listening sockets using `ss -lntp`, subject to the permissions needed to show process details.
* Review relevant application logs and recent configuration or deployment changes.
* Apply a targeted fix only after the evidence supports it, then verify that the service and application behave as expected.

Trade-off: Restarting the service may restore availability quickly, but it can erase useful transient evidence or temporarily worsen an incident. If the service is handling critical work, assess the impact before restarting it. A full disk, for example, will not necessarily be fixed by restarting an application.

When not to use this approach: If there is an active security incident or risk of evidence loss, follow the organization's incident-response procedure before making changes. For production storage operations, do not modify partitions or filesystems without confirming the device, backups, and recovery plan.

7 Interview lens

* Q: How would you troubleshoot a Linux service that is not starting?

  * A: Check its status using `systemctl`, then inspect its logs using `journalctl`.
  * Verify configuration, permissions, dependencies, available disk space, and recent changes before attempting a fix.

* Q: What is the difference between `df` and `du`?

  * A: `df` reports space usage for mounted filesystems.
  * `du` estimates the space consumed by files and directories, helping locate large directories.

* Q: What is the difference between `chmod` and `chown`?

  * A: `chmod` changes permission bits; `chown` changes file ownership.
  * Use the one that matches the problem instead of changing both without understanding the access failure.

* Q: How would you investigate a server with high resource usage?

  * A: Use tools such as `top`, `free`, `vmstat`, `iostat`, and `ss` to identify the affected resource.
  * Correlate the results with logs and application behavior before deciding whether to stop a process or change configuration.

8 Common mistakes

* Assuming every Linux distribution uses the same package manager or log paths.
* Using `sudo` or root for routine tasks that do not require elevated access.
* Changing permissions recursively without understanding the impact.
* Forcefully killing a process before attempting normal termination.
* Confusing filesystem capacity from `df` with directory usage from `du`.
* Restarting a failing service without examining its logs.
* Assuming a process is healthy merely because it exists.
* Editing system configuration without keeping a backup or knowing how to revert the change.
* Running destructive disk commands without identifying the correct device.
* Treating every access denial as a standard Unix permission problem and ignoring SELinux.
* Assuming scheduled jobs inherit the same environment as an interactive shell.
* Copying SSH private keys into shared directories or exposing them in logs.

9 Mental model

Think of Linux as a building with controlled rooms and operating systems:

* The filesystem is the building layout.
* Users and groups are identities.
* Permissions are the rules governing who can enter or change each room.
* Processes are activities currently running inside the building.
* Services are ongoing facilities that the building depends on.
* systemd is one of the systems responsible for managing those facilities.
* Logs are the activity records used to investigate problems.
* Resource tools are the meters showing how much CPU, memory, storage, and network capacity is being used.
* SSH is a secure entrance for remote administrators.
* Shell scripts are repeatable instructions for performing operational tasks.

When troubleshooting, observe first, identify the relevant layer, make the smallest justified change, and verify the result.

10 Mini lab

Goal: Practice filesystem navigation, permissions, process inspection, text filtering, and basic system inspection without modifying system services.

Time: 20–40 minutes.

Tools: A Linux machine, a virtual machine, or Windows Subsystem for Linux. The lab uses ordinary shell commands and should not require administrator privileges.

Steps:

* Open a terminal and identify your user and current directory:
  `whoami`
  `pwd`

* Create a temporary practice directory and enter it:
  `mkdir -p ~/linux-essentials-lab`
  `cd ~/linux-essentials-lab`

* Create a small text file, inspect it, and search its contents:
  `printf 'INFO service started\nERROR disk check failed\n' > app.log`
  `cat app.log`
  `grep -i error app.log`

* Create a script and inspect its permissions:
  `printf '#!/bin/sh\necho Lab complete\n' > check.sh`
  `chmod u+x check.sh`
  `ls -l check.sh`

* Run the script and inspect its result:
  `./check.sh`
  Expected output: `Lab complete`

* Inspect basic system information:
  `df -h`
  `free -h`
  `ps`

* If systemd is available, inspect a service without changing it. Use a service name that exists on your system:
  `systemctl status cron`
  If the service is absent or has another name, inspect a known service or skip this step. The command may return a non-zero status if the selected service does not exist.

* Inspect available block devices:
  `lsblk`
  If the command is not installed, note that it may need to be installed through your distribution's package manager. Do not install anything solely to complete this step.

Expected result:

* You can identify the current user and working directory.
* You can create and read a file and search for a matching log entry.
* You can explain why a script needs execute permission to run directly.
* You can inspect disk capacity, memory, and running processes.
* You understand that service-management tools depend on the system's init setup and available service names.

Cleanup:

* Leave the practice directory if you are currently inside it:
  `cd ~`
* Remove only the lab directory and its contents when you are certain you created nothing else there:
  `rm -r ~/linux-essentials-lab`

Do not use `rm -r` on directories outside the lab. No production service, system configuration, or disk layout needs to be changed for this exercise.

11 Revision summary

* Linux organizes files under a single root directory, `/`.
* Ownership and permissions control access to files and directories.
* Users, groups, and `sudo` provide identity and privilege management.
* Processes are running programs; services are managed background capabilities.
* `systemctl` inspects services and `journalctl` reads the systemd journal.
* `df` reports filesystem capacity, while `du` estimates directory usage.
* SSH provides encrypted remote access, and private keys must be protected.
* Resource tools, logs, and text-processing commands help turn troubleshooting into an evidence-based process.
