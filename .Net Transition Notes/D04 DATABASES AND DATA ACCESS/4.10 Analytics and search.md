4.10 Analytics and search
Tags: P4, O (SHORT note: sections 1, 4, 6, 11)

1 What is it
- Analytics and search is the set of data systems built for reading, summarizing and finding data at scale, as opposed to the systems that record day-to-day transactions.
- OLTP (online transaction processing) handles many small reads and writes, like placing an order. OLAP (online analytical processing) handles fewer, heavier queries that scan and summarize lots of rows, like sales by region per quarter.
- Search engines index text so that queries like "red running shoes" return ranked results fast.
Legacy equivalent: SQL Server reporting queries, SSIS packages and SSRS reports against the same production database, plus LIKE '%term%' or SQL Full-Text Search for text lookups.

4 Features and core concepts
- OLTP vs OLAP: OLTP is row-oriented, normalized, optimized for fast small writes. OLAP is read-heavy, often column-oriented, optimized for scans and aggregates. Why it matters: running heavy reports on the OLTP database slows the live application, so they are separated.
- Star schema: one central fact table (events, like sales) surrounded by dimension tables (who, what, when, where). Plain meaning: a layout designed for easy grouping and filtering. Why it matters: queries become simple joins, and BI tools expect this shape.
- ETL vs ELT: ETL (extract, transform, load) cleans data before loading it into the warehouse. ELT loads raw data first and transforms it inside the warehouse. Why it matters: ELT suits cloud warehouses with cheap storage and strong compute, and keeps raw data for reprocessing.
- Azure Data Factory (awareness): a managed service to build data pipelines that copy and orchestrate data between sources. Legacy comparison: SSIS in the cloud. Why it matters: it is the usual moving-data tool in Azure.
- Synapse and Fabric (awareness) (verify): Azure's analytics platforms. Synapse bundles warehouse, Spark and pipelines. Fabric is Microsoft's newer unified analytics product built around OneLake. Why it matters: Microsoft's direction and naming have been shifting, so confirm current positioning before an interview or exam.
- Data lake: cheap storage (in Azure, ADLS Gen2 on top of Blob storage) holding raw files in any format, such as CSV, JSON and Parquet. Why it matters: you keep everything first and decide structure later.
- Elasticsearch basics: a distributed search engine. Data is stored as JSON documents, and an inverted index maps each word to the documents containing it. Why it matters: it gives fast full-text search, relevance ranking, filters and facets that SQL handles poorly.
- Azure AI Search basics (verify name and features): the managed Azure search service. You define an index, load documents (often via indexers from SQL, Blob or Cosmos DB), and query with text, filters and ranking. Newer versions also support vector search (verify). Why it matters: it is the Azure-native answer when you do not want to run Elasticsearch yourself.
- Change data capture (CDC): a way to read inserts, updates and deletes from a database's log or change tables and stream them elsewhere. SQL Server has CDC and Change Tracking built in. Why it matters: it keeps the warehouse or search index in sync without polling or full reloads.
- Memorize this: search index and warehouse are copies of the source of truth, so they are eventually consistent and can be rebuilt.

6 Real-world use case
- Situation: an order management app on Azure SQL slows down every month-end because finance runs large reports on it, and customers complain that product search by name is poor.
- Choice made: use CDC from Azure SQL, with Data Factory (or an event stream) to land changes in a data lake, transform into a star schema in a warehouse (Synapse or Fabric (verify)), and point Power BI at it. Separately, push product data into Azure AI Search via an indexer for typo-tolerant, ranked search.
- Trade-off: more services to run and pay for, data is minutes to hours behind, and pipelines and index rebuilds need monitoring and ownership.
- When NOT to use it: small data volumes where a read replica or a few indexed views solve the problem, or when users need real-time, transactionally exact numbers. For simple search on a few thousand rows, SQL Full-Text Search is enough.

11 Revision summary
- OLTP records transactions; OLAP analyzes them; keep them on separate systems.
- Star schema = fact table plus dimension tables.
- ETL transforms before loading; ELT loads first, transforms in the warehouse.
- Data lake holds raw files cheaply; ADLS Gen2 is the Azure form.
- Data Factory moves and orchestrates data; Synapse and Fabric are analytics platforms (verify current direction).
- Elasticsearch and Azure AI Search use inverted indexes for full-text search.
- CDC streams row changes from a source database to keep copies in sync.
- Search indexes and warehouses are derived copies, not the source of truth.
