2.04 Angular core (primary framework) [P2 R L]

1 What is it
- Angular is a TypeScript framework from Google for building single-page applications (SPAs). A SPA loads one HTML page and then updates the screen in the browser without full page reloads.
- You build the UI from components (a class plus an HTML template). Angular provides routing, forms, an HTTP client, dependency injection and a build tool in one package.
- Legacy equivalent: ASP.NET MVC views with Razor, jQuery and TypeScript, where the server rendered pages and jQuery patched the DOM. In Angular the browser owns rendering and the .NET API only returns JSON.

2 Why needed
- Large UIs written with jQuery become tangled: DOM updates are scattered, state is hidden in the page, and nothing is easy to test.
- Angular gives structure (components, services, modules of routes), so ten developers can work on one front end without stepping on each other.
- Without it, you rebuild routing, form validation, HTTP handling and state management yourself, differently in every project.
- It is the primary framework for this plan because many enterprise and Azure-based client projects in India use Angular with a .NET back end.

4 Features and core concepts

Components and templates
- Plain meaning: a component is a TypeScript class tied to an HTML template and CSS. The template shows data with {{ }} and binds events with ( ) and properties with [ ].
- Why it matters: every screen is a tree of components, so reuse and testing become simple.

Standalone components
- Plain meaning: a component that declares its own imports and needs no NgModule. This is the default in current Angular (verify version).
- Why it matters: less boilerplate, easier lazy loading. Older projects still use NgModules, so know both.

Change detection (default, OnPush, signals)
- Plain meaning: change detection is how Angular finds out what changed and updates the DOM. Default mode checks every component after each event. OnPush checks a component only when its inputs change by reference, an event fires inside it, or an observable emits through the async pipe. Signals are reactive values that tell Angular exactly which parts of the screen to refresh.
- Why it matters: this is the main performance lever. Mutating an object in an OnPush component is a classic bug because nothing updates.

DI in Angular
- Plain meaning: Angular creates services and hands them to components through the constructor or the inject() function. Services are usually providedIn: 'root' (one shared instance).
- Why it matters: it is how you share data and call APIs without global variables, and how you mock in tests.

Routing (lazy loading, guards, resolvers)
- Plain meaning: the router maps URLs to components. Lazy loading downloads a feature's code only when the user goes there. Guards decide whether navigation is allowed. Resolvers fetch data before the route opens.
- Why it matters: lazy loading cuts the first load size. Guards only control the UI. Real security stays on the API (see 2.05).

Forms (template-driven vs reactive, validation)
- Plain meaning: template-driven forms are defined mostly in HTML and suit small forms. Reactive forms are defined in TypeScript (FormGroup, FormControl) and suit complex, testable forms. Validators check input rules.
- Why it matters: reactive forms are the standard for enterprise screens with dynamic rules.

HttpClient and interceptors
- Plain meaning: HttpClient calls your API and returns observables. An interceptor is a function that sees every request or response, like middleware in ASP.NET Core.
- Why it matters: one place to add the bearer token, correlation ID, global error handling and retry.

RxJS (map, switchMap, mergeMap, debounceTime, takeUntil, async pipe)
- Plain meaning: RxJS handles streams of values over time (an observable). map transforms values. switchMap cancels the previous inner call when a new value arrives (use for search). mergeMap runs inner calls in parallel. debounceTime waits for a pause in input. takeUntil stops a stream, usually on component destroy. The async pipe subscribes in the template and unsubscribes for you.
- Why it matters: it is the most failed interview area. Forgotten subscriptions cause memory leaks and duplicate calls.

State (signals, services, NgRx awareness)
- Plain meaning: state is data the screens share. Start with signals or a service holding a BehaviorSubject. NgRx is a Redux-style store with actions, reducers and effects.
- Why it matters: use NgRx only when many screens share complex state and you need traceability. Otherwise it is overkill.

Testing (unit, Playwright end-to-end)
- Plain meaning: unit tests check a component or service with TestBed (Jasmine and Karma or Jest, verify current default). Playwright drives a real browser through full user flows.
- Why it matters: end-to-end tests catch integration bugs that unit tests miss, but they are slower. Keep few.

Angular CLI and builds
- Plain meaning: the ng command creates, serves, tests and builds the app. Production builds do ahead-of-time compilation, tree shaking and minification.
- Memorize: ng new app, ng generate component x, ng serve, ng build, ng test.

Performance (lazy load, trackBy, bundle analysis)
- Plain meaning: trackBy (or track in the new @for syntax) lets Angular reuse DOM rows when a list changes. Bundle analysis shows which libraries make the download large.
- Why it matters: slow lists and huge bundles are the usual complaints.

SSR awareness
- Plain meaning: server-side rendering produces the first HTML on the server so pages show faster and are indexable. Hydration then makes it interactive.
- Why it matters: needed for public, SEO-sensitive sites. Most internal apps do not need it.

5 Core focus (exam and interview)
- Most asked: OnPush vs default, switchMap vs mergeMap, reactive vs template-driven forms, lazy loading, interceptors, unsubscribing.
- Defaults to remember: default change detection checks the whole tree. providedIn root gives one instance. Observables are lazy until subscribed. HttpClient completes after one response.
- Guards and hidden buttons are not security. The API must enforce authorization.
- Version names and new syntax (@if, @for, signals, zoneless) change often (verify).

6 Real-world use case
- Situation: a legacy MVC claims portal has slow page reloads and jQuery spaghetti. The team builds a new Angular front end over an ASP.NET Core API.
- Choice: standalone components, lazy-loaded feature routes, reactive forms, one HttpClient interceptor that adds the Entra ID token (MSAL) and a correlation ID, OnPush on large grids, signals for local state.
- Trade-off: you now run two codebases, two build pipelines and need CORS or a shared domain. The team needs RxJS skills.
- When NOT to use it: a small internal admin tool or mostly static pages. Razor Pages or Blazor are simpler. NgRx is wrong for simple CRUD screens.

7 Interview lens
- Q: When do you use OnPush? A: On components with stable inputs and big templates. It cuts checks, but you must pass new object references or use signals and the async pipe.
- Q: switchMap vs mergeMap? A: switchMap cancels the old inner request when a new value arrives, so use it for search and navigation. mergeMap runs all in parallel, so use it when every call must finish.
- Q: How do you avoid memory leaks? A: Prefer the async pipe, use takeUntil with a destroy signal (or takeUntilDestroyed), and never leave manual subscriptions open.
- Q: Does a route guard secure an app? A: No. It only stops navigation in the browser. The API must validate tokens and permissions on every call.

8 Common mistakes
- Nested subscribes inside subscribes: causes race conditions and leaks. Fix with switchMap or combineLatest.
- Mutating arrays or objects in OnPush components: screen does not update. Fix by creating new references or using signals.
- No trackBy on large lists: the whole list re-renders and scrolling lags. Fix by tracking on a stable id.
- Putting API calls inside components: hard to test and reuse. Fix by moving them to services.
- Loading all features eagerly: slow first load. Fix with lazy routes and a bundle analysis.
- Storing tokens carelessly in localStorage: XSS exposure. See 2.05 for the safer options.

9 Mental model
- Angular is a small factory line in the browser:
- URL -> Router -> Component tree -> Template shows data.
- User event -> Component -> Service (DI) -> HttpClient (interceptors) -> API.
- Response -> Observable or signal -> change detection -> DOM update.
- Think of RxJS as pipes carrying data, and change detection as the worker who repaints only what the pipe delivered.

10 Mini lab (about 40 minutes)
- Tools: Node LTS (verify) and any editor. No Azure needed.
- Step 1: run npm install -g @angular/cli, then ng new lab-app (choose standalone defaults, no SSR).
- Step 2: run ng generate service api and call https://jsonplaceholder.typicode.com/users with HttpClient (add provideHttpClient in app.config.ts).
- Step 3: create a component with a reactive form holding one search input. Use valueChanges with debounceTime(300), then switchMap to call the API with a query. Show results with the async pipe and @for with track.
- Step 4: add an HttpClient interceptor that logs each request URL to the console.
- Step 5: add a lazy route: { path: 'users', loadComponent: () => import('./users.component').then(m => m.UsersComponent) }.
- Step 6: set the list component to ChangeDetectionStrategy.OnPush and confirm it still updates through the async pipe.
- Expected result: typing pauses 300 ms before one request fires, older requests are cancelled in the Network tab, the interceptor logs each call, and the users chunk loads only when you open /users.
- Clean-up: stop ng serve with Ctrl+C and delete the lab-app folder.

11 Revision summary
- Component = class + template + CSS; standalone is the current default (verify).
- OnPush checks on input reference change, internal events, or async pipe emission.
- switchMap cancels the previous call; mergeMap runs in parallel; debounceTime waits for a pause.
- Prefer the async pipe; otherwise unsubscribe with takeUntil.
- Interceptors are the HttpClient middleware: tokens, correlation ID, errors.
- Lazy loading shrinks the first bundle; guards are UI only, not security.
- Reactive forms for complex screens; NgRx only for large shared state.
- Use trackBy (track) on lists; run bundle analysis before tuning.
