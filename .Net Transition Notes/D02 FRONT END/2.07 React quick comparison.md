1 What is it
- React is a JavaScript library for building user interfaces from small reusable pieces called components. Each component takes inputs and returns the screen markup for them. When data changes, React updates only the parts of the page that need it.
- This note is a quick comparison against Angular, which is your primary framework. Aim for working knowledge, not depth.
- Legacy equivalent: Razor partial views and jQuery UI widgets, except that the data and the markup live together and the page redraws itself when the data changes.

4 Features and core concepts
- Components: a function that returns markup (JSX, which is HTML-like syntax inside JavaScript). Why it matters: it is the unit of reuse, like an Angular component without the class and decorator.
- Hooks: special functions (names start with "use") that give a function component memory and side effects. Why it matters: they replace Angular's class fields, lifecycle methods and injected services.
- useState: stores a value inside a component and re-renders when you set it. Why it matters: it is the basic form of state, like an Angular signal. Example: const [count, setCount] = useState(0);
- useEffect: runs code after render, such as an API call or subscription, and re-runs when listed dependencies change. Why it matters: it is the Angular equivalent of ngOnInit plus ngOnChanges plus ngOnDestroy. A missing or wrong dependency list causes stale data or loops.
- useMemo: caches the result of an expensive calculation until its dependencies change. Why it matters: avoids repeated heavy work on every render.
- useCallback: caches a function so its identity stays the same between renders. Why it matters: stops child components re-rendering needlessly when the function is passed down as a prop.
- Context: shares a value with all components below it without passing it through every level. Why it matters: it works like Angular's DI for things such as the current user or theme. It is not meant for fast-changing data.
- Router: maps URLs to components (React Router is the common choice). Why it matters: React has no built-in router, so you pick one. Angular ships its router in the box.
- React Query: a library that fetches, caches and refreshes server data. Why it matters: it removes most hand-written loading and error code. Roughly what HttpClient plus RxJS plus a cache would give you.
- Redux Toolkit: a library for one shared store with predictable updates. Why it matters: it is used for large shared client state, like NgRx in Angular.
- Next.js: a framework on top of React that adds routing, server rendering and API routes. Why it matters: most production React jobs use it, much like Angular Universal for SSR. Awareness only for now.
- Comparison to keep in mind:
  - Angular is a full framework (router, forms, HTTP, DI included). React is a library, so you assemble the stack yourself.
  - Angular uses TypeScript, templates and RxJS. React uses JSX, plain functions and hooks.
  - Data flows one way in React: props down, events up.

6 Real-world use case
- Situation: your team runs an Angular admin portal. A client asks for a public marketing and product-search site that needs good SEO and fast first load.
- Choice made: build the public site with Next.js (React) and keep the admin portal in Angular. Both call the same ASP.NET Core APIs, and sign-in uses Entra ID.
- Trade-off: you get strong SEO and a large React ecosystem, but the team now maintains two front-end stacks and two skill sets.
- When NOT to use it: if the whole team already knows Angular and the product is an internal app with no SEO need, adding React adds cost for no gain. Use Angular.

11 Revision summary
- React is a library and Angular is a framework: React needs you to choose router, forms and HTTP tools.
- Components are functions returning JSX, and data flows one way (props down, events up).
- useState holds local state and useEffect handles side effects after render.
- useMemo caches values and useCallback caches functions, both used only for measured performance problems.
- Context shares values down the tree, similar to DI, but is not for fast-changing data.
- React Query manages server data, while Redux Toolkit manages large shared client state.
- Next.js adds routing and server rendering, which is why most production React work uses it.
- Wrong dependency lists in useEffect are the most common hook bug.
