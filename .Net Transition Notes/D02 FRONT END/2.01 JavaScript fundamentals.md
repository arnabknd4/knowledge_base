2.01 JavaScript fundamentals

1 What is it
- JavaScript is the language browsers run. It is single-threaded, dynamically typed, and driven by an event loop.
- Scope, closures, prototypes, modules and async behaviour decide how front-end code actually behaves.
- Legacy equivalent: jQuery-era script files in MVC views, with global variables, $.ajax callbacks and script tag ordering.

2 Why needed
- Angular, TypeScript and MSAL all sit on these rules. Without them you cannot debug a stale closure, a lost this, or a promise that never resolves.
- As a lead you review front-end pull requests and need to spot these bugs quickly.
- Without module and same-origin knowledge you cannot reason about CORS or token storage.

4 Features and core concepts
- Scope: var is function-scoped and hoisted. let and const are block-scoped and sit in a temporal dead zone before declaration. Why it matters: it explains the classic loop-with-var bug.
- Closures: a function remembers variables from where it was created. Why it matters: it is behind callbacks, event handlers, memoization and stale values in Angular and React code.
- this: set by how a function is called, not where it is written. Arrow functions take this from the enclosing scope. Why it matters: lost this in callbacks is a common bug. Fix with arrow functions or bind.
- Prototypes: objects inherit through a prototype chain. class is syntax over this. Why it matters: it explains instanceof, inheritance and why methods are shared.
- ES modules: import and export are static, strict mode by default, and loaded once. Replaces script tags and CommonJS require. Why it matters: it enables tree shaking and bundler optimisation.
- Event loop: one call stack, plus a macrotask queue (setTimeout, I/O) and a microtask queue (promises). Microtasks run to completion before the next macrotask. Why it matters: it explains ordering puzzles and why heavy loops freeze the UI.
- Promises and async: a promise is pending, fulfilled or rejected. async/await is syntax over promises. Promise.all fails fast. Promise.allSettled waits for all. Why it matters: unhandled rejections and missing await are common production bugs.
- fetch: returns a promise that resolves even on HTTP 404 or 500. Check response.ok yourself. It does not send cookies cross-origin unless credentials is set. Why it matters: different from $.ajax, which errored on non-2xx.
- Destructuring: pull values from arrays and objects, with defaults. Why it matters: used everywhere in modern code.
- Immutability: use spread and non-mutating methods instead of changing objects in place. Object.freeze is shallow. Why it matters: change detection (OnPush, signals, NgRx) depends on new references.
- Array methods: map, filter, reduce, find, some, every, flatMap. toSorted and toReversed are newer non-mutating versions (verify browser support). Why it matters: sort mutates the original array, which is a common bug.
- Error handling: try/catch with async/await, catch on promise chains, a global handler for unhandled rejection. Why it matters: a missing catch fails silently in the UI.
- Cookies, localStorage, sessionStorage: cookies go to the server on each request and can be HttpOnly. localStorage persists and is readable by any script. sessionStorage lasts for the tab. Why it matters: token storage choices decide XSS exposure.
- Same-origin policy: origin is scheme, host and port. The browser blocks cross-origin reads unless the server allows them through CORS. Why it matters: CORS is enforced by the browser, not the server.
- Memorize:
  - const copy = { ...obj, name: "x" };
  - const res = await fetch(url); if (!res.ok) throw new Error(res.status);

5 Core focus (exam and interview)
- Most asked: closures, this binding, event loop order, promise vs async/await, == vs ===, var vs let vs const.
- Order rule: synchronous code, then microtasks (promises), then macrotasks (setTimeout).
- == coerces types. === does not. Use ===.
- typeof null is "object". NaN !== NaN.
- localStorage is about 5 MB per origin (verify). Cookies are about 4 KB each.
- CORS preflight is an OPTIONS request sent before some cross-origin calls.

6 Real-world use case
- Situation: an Angular app on Azure Static Web Apps calls an ASP.NET Core API on App Service. Users report random 401 errors and a duplicate-save bug.
- Findings: the token was cached in a closure and went stale after refresh. A double click fired two async saves.
- Choice: read the token fresh through the auth library on each call, and disable the button while the request is pending.
- Trade-off: more calls into the auth layer, slightly more code.
- When not to: do not hand-roll token logic when MSAL already handles it.

7 Interview lens
- Q: What is a closure and a real risk? A: A function that keeps access to variables of its outer scope. Risk is stale values and memory held longer than expected.
- Q: Explain the event loop. A: One stack runs code. When it empties, all microtasks run, then one macrotask. Promise callbacks are microtasks.
- Q: Does fetch reject on a 500? A: No. It rejects only on network failure. You must check response.ok.
- Q: Why is localStorage risky for tokens? A: Any injected script can read it. HttpOnly cookies or in-memory storage reduce that.

8 Common mistakes
- Forgetting await: the code continues with a pending promise. Fix with await and lint rule no-floating-promises.
- Mutating state: UI does not refresh under OnPush. Fix with new object references.
- Using forEach with async callbacks: it does not wait. Fix with for...of or Promise.all with map.
- Treating CORS as a server security feature: it only protects browsers. Fix by still authorising on the API.
- Using var in loops with callbacks: wrong captured value. Fix with let.

9 Mental model
- One worker, one desk.
- Stack = what the worker is doing now.
- Microtask tray = urgent notes, cleared fully before anything else.
- Macrotask queue = the in-tray, taken one item at a time.
- Closure = a backpack a function carries from where it was born.

11 Revision summary
- var is function-scoped. let and const are block-scoped.
- this depends on the call site. Arrow functions inherit it.
- Microtasks run before the next macrotask.
- fetch does not reject on HTTP errors. Check response.ok.
- sort mutates. Spread first or use toSorted (verify support).
- Origin is scheme, host and port. CORS is browser-enforced.
- localStorage is readable by any script on the origin.
