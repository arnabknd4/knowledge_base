1 What is it
- Creational patterns are standard ways to control how objects get created, so calling code does not depend on concrete classes or construction details.
- Factory Method: one method decides which concrete type to return. Abstract Factory: one object creates a whole family of related objects. Builder: assembles a complex object step by step. Singleton: exactly one instance exists. Prototype: new objects are made by cloning an existing one.
- Legacy equivalent: static helper classes, "new" scattered through MVC controllers, and static singletons with private constructors in .NET Framework apps.

4 Features and core concepts
- Factory Method: a method returns an interface and hides which class is built. It matters because adding a new type changes one place, not every caller. Example: a PaymentProcessorFactory.Create(provider) returning IPaymentProcessor.
- Abstract Factory: an interface that creates several related objects that must match. It matters when a family has to stay consistent, for example a SqlServer family (connection, command) vs a Postgres family. In .NET, DbProviderFactory is the classic example.
- Builder: constructs an object in steps and ends with Build(). It matters when there are many optional parts and constructors would explode. Examples: WebApplication.CreateBuilder, HostBuilder, StringBuilder, SqlConnectionStringBuilder.
- Singleton (DI-managed): one instance for the whole app, but the container owns it, not a static field. It matters because static singletons are hard to test and hide dependencies. Code to memorize: builder.Services.AddSingleton<IClock, SystemClock>();
- Prototype: copy an existing object instead of building from scratch. It matters when creation is expensive or you need a safe copy. In modern C#, a record with the "with" expression gives a shallow clone: var b = a with { Name = "x" };
- IHttpClientFactory: a factory that creates HttpClient instances and manages the handler pool behind them. It matters because new HttpClient() per call causes socket exhaustion, and one static client ignores DNS changes. Gap vs old code: the factory is the fix for both.
- ILoggerFactory: creates ILogger instances per category. It matters because the category (usually the class name) drives filtering and log levels. Normally you inject ILogger<T> and the factory works behind the scenes.

5 Core focus (exam and interview)
- Most asked: Factory Method vs Abstract Factory, Singleton thread safety, and why DI replaced hand-written singletons.
- Singleton lifetime in DI is per container, not per static class. Captive dependency risk: a singleton must not hold a scoped service.
- Factory vs DI: if the type is known at startup, DI is enough. Use a factory only when the type is chosen at runtime.
- Keyed services (.NET 8 and later, verify) are the built-in answer to many "choose by name" factories.
- Builder usually ends in a Build() call and often returns an immutable result.
- Prototype in C#: ICloneable is discouraged because it does not say deep or shallow. Prefer records or an explicit copy method.

6 Real-world use case
- Situation: an Azure-hosted order API must support three payment gateways, picked per tenant at runtime.
- Choice: register each gateway with a keyed service or a small IPaymentProcessorFactory that resolves by tenant setting. Outbound calls use typed HttpClients from IHttpClientFactory, with Polly resilience handlers (verify).
- Trade-off: the factory adds one more abstraction and a lookup. You gain a single place to add gateway number four.
- When NOT to use: when only one implementation exists and none is planned. Plain constructor injection is simpler. Also avoid static singletons, and avoid Abstract Factory when there is no real "family" of objects.

11 Revision summary
- Factory Method picks one type. Abstract Factory builds a matching family.
- Builder builds step by step: WebApplication.CreateBuilder is the daily example.
- Singleton in .NET means AddSingleton, not a static field.
- Prototype means clone. Records with "with" give a shallow copy.
- IHttpClientFactory prevents socket exhaustion and stale DNS.
- ILoggerFactory creates category-based loggers. Inject ILogger<T>.
- Do not hold scoped services inside a singleton.
- A factory is justified only when the type is decided at runtime.
