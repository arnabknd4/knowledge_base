# 10.04 Behavioral patterns

## 1 What is it

- Behavioral patterns describe how objects talk to each other and share work.
- They focus on who is responsible for what, and how behavior can change without rewriting callers.
- Covered here: Strategy, Observer, Command, Chain of Responsibility, Template Method, State, Mediator, Iterator, Visitor, Memento.
- Legacy equivalent: switch statements on type codes, event handlers in WebForms and MVC, and base-class overrides in .NET Framework code.

## 2 Why needed

- Without them, behavior sits in large if/else or switch blocks that grow with every new rule.
- Adding a new case means editing old, tested code, which risks regressions.
- Tight links between objects make unit testing hard and slow down change.

## 4 Features and core concepts

- Strategy: swap an algorithm behind an interface. Why it matters: replaces switch blocks and enables DI-based selection. Modern .NET: register many implementations of one interface, resolve with keyed services (.NET 8) or an IEnumerable of the interface.
- Observer: a subject notifies subscribers of changes. Why it matters: decouples the publisher from listeners. Modern .NET: C# events, IObservable and IObserver, and in-process or broker-based messaging. Gap to watch: events keep subscribers alive, so they leak memory if you never unsubscribe.
- Command: wrap a request as an object with an Execute method. Why it matters: enables queuing, logging, undo and retry. Modern .NET: message and request classes sent through a queue or handler.
- Chain of Responsibility: pass a request along handlers, each can act or pass on. Why it matters: lets you add or reorder steps without touching others. Modern .NET: ASP.NET Core middleware, DelegatingHandler in HttpClient, pipeline behaviors.
- Template Method: a base class fixes the algorithm steps, subclasses fill in some. Why it matters: shares a workflow while allowing variation. Modern .NET: BackgroundService.ExecuteAsync. Prefer composition (Strategy) when inheritance gets deep.
- State: an object changes behavior when its internal state changes. Why it matters: removes large state-flag conditionals. Use for order, payment and workflow lifecycles.
- Mediator: one object coordinates communication between others. Why it matters: reduces many-to-many dependencies. Modern .NET: MediatR style request dispatching. Licensing changed for MediatR recently (verify), so check the license before adopting or consider alternatives such as Wolverine or a hand-rolled dispatcher.
- Iterator: sequential access without exposing the structure. Modern .NET: IEnumerable, yield return, IAsyncEnumerable. Know that LINQ deferred execution is an iterator under the hood.
- Visitor (awareness): add operations to a class hierarchy without changing it. Rarely needed in business code. Modern C# pattern matching and switch expressions often replace it.
- Memento: capture and restore an object's state. Why it matters: undo and snapshots. Awareness level only.
- One snippet worth memorizing (Strategy via keyed DI):

```
builder.Services.AddKeyedScoped<IDiscount, FestivalDiscount>("festival");
public Checkout([FromKeyedServices("festival")] IDiscount d) { ... }
```

## 5 Core focus (exam and interview)

- Most asked: Strategy vs State, Strategy vs Template Method, Observer vs events vs pub/sub, Mediator vs direct calls, where middleware is Chain of Responsibility.
- Strategy: caller picks the behavior. State: the object changes its own behavior.
- Template Method uses inheritance. Strategy uses composition.
- Observer in-process is synchronous by default and failure in one handler can break the rest.
- Mediator hides dependencies but can become a hidden god object.
- Interviewers expect you to name the .NET framework example for each pattern.

## 6 Real-world use case

- Situation: an order service in a Kolkata e-commerce client has a 400-line method with a switch on payment type and another on discount type.
- Choice: Strategy for payment gateways and discounts, resolved through DI. State for the order lifecycle (placed, paid, shipped, cancelled). A middleware-style chain for validation steps.
- Trade-off: more classes and indirection, harder to read for juniors at first.
- When NOT to use: with two stable cases, a plain if is clearer. Do not use Mediator for a small app, and do not add patterns before a second variation exists.

## 7 Interview lens

- Q: Difference between Strategy and State?
  A: Strategy is chosen by the client and does not change itself. State changes internally as the object moves between states.
- Q: Where do you see Chain of Responsibility in ASP.NET Core?
  A: Middleware pipeline, each component calls next or short-circuits. HttpClient DelegatingHandlers work the same way.
- Q: Why can C# events cause memory leaks?
  A: The publisher holds a reference to each subscriber. Unsubscribe, or use weak references or scoped lifetimes.
- Q: When would you avoid Mediator?
  A: In small apps or when it hides the call flow and turns into a god object. Direct service calls are simpler and easier to trace.

## 8 Common mistakes

- Pattern overuse: dozens of one-method classes for a single case. Fix: introduce a pattern only at the second or third variation.
- Strategy chosen with a switch inside a factory that grows forever. Fix: register implementations in DI and resolve by key.
- Event subscribers never unsubscribed. Shows up as growing memory over days. Fix: unsubscribe or dispose.
- Mediator handlers calling other handlers in cycles. Shows up as hard-to-debug flows. Fix: keep handlers independent, publish events instead.
- Deep Template Method inheritance. Shows up as fragile base class changes. Fix: switch to composition.

## 9 Mental model

```
Strategy   : one slot, swap the plug
State      : the plug changes itself
Observer   : one speaker, many listeners
Command    : a request written on paper, can be queued
Chain      : conveyor belt with stations
Mediator   : air traffic control tower
Template   : recipe with fill-in steps
```

## 11 Revision summary

- Strategy swaps algorithms, State changes behavior with internal state.
- Middleware and DelegatingHandler are Chain of Responsibility.
- Command turns a request into an object for queue, log, undo and retry.
- C# events are Observer, so unsubscribe to avoid leaks.
- IEnumerable and yield return are Iterator.
- Mediator licensing for MediatR changed (verify).
- Prefer composition over Template Method inheritance.
- Visitor and Memento are awareness topics only.
