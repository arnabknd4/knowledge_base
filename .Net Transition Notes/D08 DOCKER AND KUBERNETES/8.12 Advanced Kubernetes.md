1 What is it

- Advanced Kubernetes is the set of features that control who can do what in a cluster, what pods are allowed to do, how the cluster is extended, and how services talk to each other.
- It covers RBAC (permissions), Pod Security Standards (pod safety rules), admission controllers (gatekeepers on every request), operators and CRDs (custom resource types plus the code that manages them), service mesh (a network layer for service-to-service traffic), Dapr (a runtime of ready-made distributed building blocks), multi-cluster (running more than one cluster), and the CKA and CKAD exams.
- Legacy equivalent: IIS and Windows permissions plus Group Policy and WCF/ESB-style plumbing, where access and traffic rules were set outside the application.

4 Features and core concepts

- RBAC details. Plain meaning: Roles list allowed verbs on resources inside one namespace. ClusterRoles do the same cluster-wide. RoleBindings and ClusterRoleBindings attach them to users, groups or service accounts. Why it matters: least privilege and a common exam task.
- Memorize: kubectl auth can-i list pods --as=system:serviceaccount:dev:app
- Pod Security Standards. Plain meaning: three built-in profiles, Privileged, Baseline and Restricted, applied per namespace through Pod Security Admission labels (enforce, audit, warn). Why it matters: blocks root containers and host access by default. These replaced PodSecurityPolicy, which was removed.
- Admission controllers. Plain meaning: code that runs after authentication and authorization and before an object is saved. Mutating ones change the request, validating ones accept or reject it. Why it matters: this is how policy engines such as Azure Policy for AKS (Gatekeeper/OPA) or Kyverno enforce rules like "no latest tag".
- Operators and CRDs. Plain meaning: a CRD adds a new resource type to the API. An operator is a controller that watches that type and keeps the real system matching it. Why it matters: it packages operations knowledge, for example a database operator that handles backup and failover.
- Service mesh (Istio, Linkerd). Plain meaning: small proxies beside each pod handle mTLS, retries, timeouts, traffic splitting and metrics without code changes. Why it matters: consistent security and observability across many services. Cost: extra latency, memory and operational complexity. Istio is feature-rich and heavier, Linkerd is lighter. AKS offers an Istio-based add-on (verify).
- Dapr. Plain meaning: a sidecar or runtime exposing building blocks (state, pub/sub, service invocation, bindings, secrets) over HTTP or gRPC. Why it matters: cloud-neutral code for messaging and state. It overlaps with a mesh in service invocation, so do not stack both without a reason.
- Multi-cluster. Plain meaning: several clusters for regions, isolation or blast-radius control. Why it matters: DR and compliance, but it adds routing, config sync and cost. Tools: Azure Fleet Manager (verify), GitOps, a global load balancer such as Front Door.
- CKA and CKAD skills. Plain meaning: CKA tests cluster administration, CKAD tests application workloads. Both are hands-on, in a terminal, time-limited. Why it matters: practice speed with kubectl, YAML and docs. Check the current curriculum and passing score on the CNCF page (verify).

6 Real-world use case

- Situation: a Kolkata-based team runs 15 microservices on AKS for a client and an audit asks for encrypted internal traffic and no privileged pods.
- Choice: apply the Restricted Pod Security Standard to production namespaces, add Azure Policy for AKS to block untagged or latest images, scope RBAC per team namespace using Entra groups, and use a mesh add-on for mTLS between services.
- Trade-off: stricter rules break some existing manifests, so roll out in warn and audit mode first. The mesh adds proxies, CPU and memory overhead, and one more thing to upgrade.
- When NOT to use: skip the mesh when you have fewer than about five services or only need TLS at the ingress. Skip operators and custom CRDs for simple apps, and skip multi-cluster until one cluster cannot meet an availability, compliance or scale need.

11 Revision summary

- RBAC is additive only: there are no deny rules. Role is namespaced, ClusterRole is cluster-wide.
- Pod Security Standards profiles: Privileged, Baseline, Restricted. Modes: enforce, audit, warn.
- Admission order: authn, authz, mutating admission, schema validation, validating admission, then save to etcd.
- CRD adds the type, operator adds the behavior.
- A mesh adds mTLS, retries, traffic splitting and telemetry through sidecars, at a cost in overhead.
- Dapr gives building blocks (state, pub/sub, invocation); do not duplicate it with a mesh without reason.
- Multi-cluster is for DR, isolation and compliance, not a default.
- CKA is admin and troubleshooting, CKAD is app workloads; both are practical exams.
