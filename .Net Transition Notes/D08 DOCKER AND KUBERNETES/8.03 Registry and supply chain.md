1 What is it
- A container registry stores and distributes container images. Azure Container Registry (ACR) is Azure's private, managed registry.
- Supply chain means everything that goes into an image: base image, packages, your code. Securing it means knowing what is inside and proving where it came from.
- Registry: a server that stores images by name and tag. You push from CI and pull from AKS, App Service or Container Apps.
- Legacy equivalent: a NuGet feed or a file share holding signed release builds, plus a patching policy for the servers they ran on.

2 Why needed
- Nodes and pipelines need one trusted place to pull images from. Public registries can be rate limited, change without notice or be tampered with.
- Without scanning, a vulnerable base image goes to production unnoticed.
- Without a tagging rule, nobody knows which build is running. A mutable tag like latest can point to different code tomorrow.
- Without retention, old images pile up and the bill grows.

3 Before you read
- An image is built from read-only layers. A tag is a movable label. A digest is a fixed hash of the image content.
- Dockerfile and multi-stage build basics (topic 8.01).
- Managed identity: an Azure-issued identity for a resource, so no password is stored.
- A CI pipeline can run build, scan and push steps.

4 Features and core concepts
- ACR SKUs: Basic, Standard, Premium (verify limits and prices on the pricing page). Premium adds geo-replication, private link and more. Why it matters: features and storage limits depend on the SKU.
- ACR Tasks: build images inside ACR, with triggers on source commit or base image update. Why it matters: no build agent needed, and base image updates can rebuild your images automatically.
- Geo-replication: one registry with copies in several regions (Premium). Why it matters: faster pulls and survival of a regional outage.
- Private link: the registry gets a private IP in your VNet. Why it matters: image traffic stays off the public internet.
- Managed identity pull: the cluster or app pulls using its own identity with the AcrPull role. Why it matters: no admin user and no stored password.
- Tagging strategy: tag with semantic version plus git SHA, for example 1.4.2 and 1.4.2-a1b2c3d. Avoid latest. Why it matters: you can trace a running container to an exact commit. Deploy by digest for strictest safety.
- Vulnerability scanning: scan images for known CVEs in OS packages and libraries (Defender for Cloud, Trivy; verify current Defender plan name). Why it matters: finds known flaws before release. Fail the pipeline on high severity.
- Image signing: attach a signature (Notation, Cosign; verify tooling support in ACR) so a consumer can verify who built the image. Why it matters: stops a swapped or forged image.
- SBOM: a software bill of materials, a list of every component in the image. Why it matters: when a new CVE appears, you can find affected images fast.
- Base image patching: rebuild regularly on a patched base. Why it matters: a scan of an old image keeps failing until you rebuild.
- Retention policies: auto-delete untagged manifests after N days (Premium feature, verify). Why it matters: cost control and a tidy registry.
- Commands to memorize:
- az acr create -n myacr -g rg1 --sku Standard
- az acr build -r myacr -t api:1.0.0 .
- az aks update -n aks1 -g rg1 --attach-acr myacr

5 Core focus (exam and interview)
- Most asked: managed identity pull with AcrPull role versus admin user (disable admin user).
- Most asked: which SKU gives geo-replication and private link (Premium).
- Tags are mutable, digests are immutable. Latest is a trap.
- Scan in the pipeline and keep scanning stored images, because new CVEs appear after the push.
- Registry names are globally unique and lowercase.
- Deleting a tag does not free layers still used by other images until cleanup runs.

6 Real-world use case
- Situation: a legacy .NET Framework API moves to .NET 8 in containers on AKS (verify the current LTS). Three teams push images.
- Choice: one Premium ACR with private endpoint, AKS pulling through managed identity, admin user disabled. The pipeline builds, runs Trivy, pushes with version plus SHA tag, and signs. ACR Task rebuilds on base image updates. A retention rule removes untagged images after 7 days.
- Trade-off: Premium costs more than Standard, and private link adds DNS setup work. You gain security and regional pull speed.
- When not to use it: a small single-app team with no compliance need can use Standard with public access plus firewall rules. Skip signing until a policy requires it.

7 Interview lens
- Q: Why not use the latest tag?
- A: It is mutable, so a pod restart can pull different code. Use version plus git SHA, or a digest.
- Q: How does AKS pull from ACR without a password?
- A: The kubelet managed identity gets the AcrPull role on the registry. The attach-acr option sets this up.
- Q: Scan passed at build time. Are we safe?
- A: No. New CVEs are published later. Rescan stored images and rebuild on patched bases.
- Q: What does an SBOM give you?
- A: A list of components per image. When a library CVE is announced, you query SBOMs to find affected images.

8 Common mistakes
- Admin user left enabled: shared password leaks in a pipeline log. Fix: disable it, use identities.
- Deploying latest: rollback is impossible because nobody knows what ran. Fix: immutable version and SHA tags.
- Scanning only at build: old images carry new CVEs. Fix: scheduled rescans and base image rebuilds.
- Using an unpinned public base image: build changes silently. Fix: pin version or digest, mirror to your ACR.
- No retention: storage grows. Fix: retention policy and cleanup tasks.
- Private link without private DNS zone: pulls fail with name resolution errors. Fix: link the privatelink DNS zone to the VNet.

9 Mental model
- Think of ACR as a locked warehouse with a receipt for every box.
- CI builds the box, scanner inspects it, signer seals it, registry stores it.
- The cluster's identity is the badge that opens the door.
- Source code -> build -> scan -> sign -> push (tag + digest) -> pull by identity -> run

10 Mini lab (30 minutes, Azure free tier)
- Create a resource group and a Basic ACR: az group create -n lab-rg -l centralindia, then az acr create -n <uniquename> -g lab-rg --sku Basic.
- Create a small Dockerfile for any hello-world .NET app, or use a one-line nginx image.
- Build in the cloud: az acr build -r <uniquename> -t hello:1.0.0 . Expected result: build log ends with the pushed image.
- Run az acr repository show-tags -n <uniquename> --repository hello. Expected result: 1.0.0.
- Run a second build with tag 1.0.1, then list tags and manifests with az acr manifest list-metadata. Note the different digests.
- Install Trivy locally and scan: trivy image <uniquename>.azurecr.io/hello:1.0.0 after az acr login. Expected result: a CVE table.
- Clean up: az group delete -n lab-rg --yes --no-wait.

11 Revision summary
- ACR SKUs: Basic, Standard, Premium. Geo-replication and private link need Premium (verify).
- Pull with managed identity and the AcrPull role. Disable the admin user.
- Tags move, digests do not. Avoid latest.
- Tag format: semver plus git SHA.
- Scan in CI and rescan stored images. Rebuild on patched base images.
- SBOM lists components. Signature proves origin.
- Retention policy removes untagged images.
- ACR Tasks can rebuild on base image updates.
