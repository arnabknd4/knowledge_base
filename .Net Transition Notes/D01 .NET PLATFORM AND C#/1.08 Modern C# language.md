# 1.08 Modern C# language
1 What is it

- Modern C# is the set of language features added from C# 9 to roughly C# 13 (verify the current version). They remove boilerplate and make code safer.
- Records are classes or structs with built-in value-based equality. Pattern matching tests the shape of data. Nullable reference types make the compiler warn about possible nulls.
- Legacy equivalent: hand-written POCO classes with Equals and GetHashCode overrides, if-else chains with casts, and null checks written by hand in .NET Framework 4.x code.

2 Why needed

- Legacy C# needs many lines for simple data carriers, and null reference errors show up only at runtime.
- Without these features, DTOs are mutable by accident, switch logic is long, and the compiler cannot warn about nulls.
- Modern ASP.NET Core, EF Core and minimal APIs assume these features. Interviewers expect you to read and write them.

3 Before you read

- Class vs struct: a class is a reference type (copied by reference), a struct is a value type (copied by value).
- Equality: == and Equals can compare by reference or by value.
- Null: a reference that points to no object. Using it throws NullReferenceException.
- Interface and generics basics from your .NET Framework work.

4 Features and core concepts

- Records: a type with value equality, a ToString and a non-destructive copy (with). Why: DTOs and messages compare by content, not by identity.
  - public record OrderDto(int Id, string Customer);
  - var b = a with { Customer = "X" };
- Record struct: the same idea as a value type. Why: avoids heap allocation for small data.
- init and required: init lets a property be set only during object creation. required forces the caller to set it. Why: immutable objects without constructors with ten parameters.
  - public required string Name { get; init; }
- Pattern matching: test a value against a shape (type, property, range, list). Why: replaces cast-and-if chains.
  - if (o is Order { Total: > 1000 } big) { ... }
- Switch expressions: a switch that returns a value. Why: short, and the compiler checks all cases are handled.
  - var tax = region switch { "IN" => 0.18m, "US" => 0.07m, _ => 0m };
- Nullable reference types (NRT): the compiler tracks whether a reference can be null. string means non-null, string? means maybe null. Why: finds null bugs at build time. Enable with <Nullable>enable</Nullable> in csproj. It gives warnings only, not runtime enforcement.
- Primary constructors: parameters placed right after the type name, usable across the class body. Why: removes the field-and-assign code for DI.
  - public class OrderService(IRepo repo, ILogger<OrderService> log) { ... }
  - Parameters are captured, not readonly. For records they become properties; for classes they do not.
- Collection expressions: one syntax for creating arrays, lists and spans. Why: uniform and lets the compiler pick an efficient form.
  - List<int> xs = [1, 2, 3]; int[] all = [..xs, 4];
- Tuples and deconstruction: a lightweight group of values returned together, then split into variables. Why: return two or three values without a new class.
  - var (min, max) = GetRange();
- Generics and constraints: type parameters with rules (where T : class, new(), struct, notnull, an interface). Why: reusable, type-safe code with no boxing.
- Delegates, events, lambdas: a delegate is a typed method reference (Func, Action, Predicate). A lambda is an inline method. An event is a delegate with restricted invocation. Why: callbacks, LINQ and middleware all use them. Events held by long-lived objects leak memory if never unsubscribed.
- LINQ: query methods over collections. Deferred execution means the query runs when you enumerate it, not when you write it. IEnumerable runs in memory. IQueryable builds an expression tree that EF Core translates to SQL. Why: calling a non-translatable method too early pulls the whole table into memory.
- Exception best practices: throw specific exceptions, use throw; not throw ex; to keep the stack trace, do not use exceptions for normal flow, catch only what you can handle, use finally or using for cleanup. Why: keeps diagnostics and performance intact.

5 Core focus (exam and interview)

- Asked most: record vs class, init vs set, IEnumerable vs IQueryable, deferred execution, NRT meaning, throw vs throw ex.
- Records: reference type by default, value equality, with-expression copies shallowly.
- NRT is a compile-time feature only. It does not stop nulls at runtime.
- Primary constructor parameters in classes are not properties.
- ToList() or foreach forces execution. Enumerating twice runs the query twice.
- Latest language version depends on the SDK and target framework (verify).

6 Real-world use case

- Situation: you migrate an MVC order API to ASP.NET Core. Old DTOs are mutable classes with hand-written equality, and null errors show up in production.
- Choice: request and response models become records with required and init. Services use primary constructors for DI. NRT is enabled project by project. Region and status logic moves to switch expressions.
- Trade-off: NRT on a large legacy code base gives hundreds of warnings. Enable per file or project and fix in stages. Record with-copies are shallow, so a mutable list inside is still shared.
- Do not use: records for EF Core entities that need identity and change tracking. Do not use primary constructors when you need readonly fields. Do not use tuples across public API boundaries; use a named type.

7 Interview lens

- Q: Record vs class? A: Records give value-based equality, ToString and with-copies by default. Classes compare by reference. Use records for DTOs and messages, classes for entities with identity.
- Q: IEnumerable vs IQueryable? A: IEnumerable filters in memory after loading data. IQueryable translates the query to SQL so the database filters. Calling AsEnumerable() or ToList() too early loads everything.
- Q: Does NRT prevent NullReferenceException? A: No. It gives compile-time warnings only. Runtime nulls from JSON, reflection or the null-forgiving operator still happen.
- Q: Why throw; instead of throw ex;? A: throw; keeps the original stack trace. throw ex; resets it to the current line and hides where the error started.

8 Common mistakes

- Enabling NRT and silencing warnings with the ! operator everywhere. In production the nulls still appear. Fix: model nullability properly, validate at boundaries.
- Using a record as an EF entity. Equality by value breaks change tracking and identity. Fix: classes for entities, records for DTOs.
- Enumerating a LINQ query many times. The database is hit repeatedly. Fix: materialize once with ToList() when you need the data more than once.
- Calling a custom method inside an IQueryable where clause. EF cannot translate it, so it fails or runs client-side. Fix: use translatable expressions or project first.
- Subscribing to events and never unsubscribing. Memory grows. Fix: unsubscribe or use weak patterns.
- catch (Exception) with an empty body. Failures vanish. Fix: log or rethrow.

9 Mental model

- C# 9+ features = less ceremony, more compiler help.
- Data shape: record (value equality) + init/required (set once).
- Decisions: pattern matching + switch expression (compiler checks all cases).
- Safety: NRT warns about null at build time, not at runtime.
- Queries: IEnumerable = in memory, IQueryable = database. Execution is deferred until you enumerate.

10 Mini lab

- Time: about 30 minutes. Tools: .NET SDK (current LTS, verify) and a terminal.
- Steps:
  - dotnet new console -n ModernCs && cd ModernCs
  - Confirm <Nullable>enable</Nullable> in the csproj.
  - Create record Order(int Id, string Customer, decimal Total). Make two with the same values and print a == b. Expect True.
  - Use var b = a with { Total = 500 }; print both. Expect a unchanged.
  - Declare string name = null; and read the build warning. Change it to string? and handle null.
  - Write a switch expression that maps Total to "Small", "Medium", "Large" with relational patterns.
  - Build a List<Order> with a collection expression. Run a LINQ Where, store it without ToList(), change the list, then enumerate. Expect the new data to appear (deferred execution).
- Expected result: record equality is True, the null warning appears, and the LINQ result reflects the later change.
- Clean-up: cd .. and delete the ModernCs folder.

11 Revision summary

- Records have value equality and with-copies; use them for DTOs, not EF entities.
- init sets once at creation; required forces callers to set it.
- Pattern matching and switch expressions replace cast-and-if chains with compiler-checked cases.
- NRT is compile-time only; ? marks nullable, ! silences warnings.
- Primary constructor parameters in classes are captured, not properties.
- LINQ is deferred; IEnumerable is in memory, IQueryable becomes SQL.
- Use throw; to keep the stack trace; avoid empty catch blocks.
- Events on long-lived objects leak memory if never unsubscribed.
