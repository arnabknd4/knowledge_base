1 What is it

- Advanced .NET is the set of features that go below everyday application code: code that writes code at build time, tools that inspect and enforce code rules, and ways to inspect or call things at runtime.
- Source generators run during compilation and add new C# files to your project. Roslyn analyzers are checks that run inside the compiler and the editor and report warnings or errors. Reflection reads type information while the program runs. Expression trees represent code as data that can be inspected. Native AOT compiles an app ahead of time into a machine-code executable with no JIT. P/Invoke calls native (non-.NET) libraries. Minimal API tuning means trimming overhead in minimal APIs. .NET Aspire is a stack for composing and observing distributed apps locally and in the cloud (verify).
- Legacy equivalent: T4 templates and CodeDOM for code generation, FxCop and StyleCop for analyzers, System.Reflection and Expression<T> in EF6 and AutoMapper, DllImport for native calls, and NGEN for pre-compilation.

4 Features and core concepts

- Source generators: a compiler plug-in that reads your code and emits extra C# at build time. Why it matters: it removes runtime reflection, so startup is faster and the app is trim and AOT safe. System.Text.Json source generation and the LoggerMessage generator use it.
- Roslyn analyzers: compiler plug-ins that flag rule violations with squiggles and build warnings, often with an automatic code fix. Why it matters: you can enforce team standards in CI instead of in code review. Severity is set in .editorconfig.
- Reflection and attributes: reflection reads types, members and attributes at runtime. An attribute is metadata attached to code, such as [Authorize]. Why it matters: frameworks use it for DI, model binding and serializers. Cost: it is slow, and the trimmer cannot see what it touches.
- Expression trees: code held as a tree of objects, such as Expression<Func<T,bool>>. Why it matters: it is how EF Core turns a LINQ lambda into SQL. Compile() turns the tree into a delegate.
- Native AOT: the app is compiled to native code at publish time. Why it matters: fast startup and a small memory footprint, good for serverless and containers. Limits: no runtime code generation, reflection is restricted, and not every library is compatible. Setting: PublishAot in the csproj.
- P/Invoke: [DllImport] or [LibraryImport] declares a native function you can call from C#. Why it matters: it reaches OS APIs and C libraries. Risks: manual memory handling, platform-specific code, and crashes that managed code cannot catch. LibraryImport is source-generated and preferred in new code.
- Minimal API tuning: reduce per-request cost in minimal APIs. Items: the Request Delegate Generator for AOT, typed results, avoiding extra allocations, trimming unused services, response caching, and the slim host builder (verify names for your .NET version).
- .NET Aspire (verify): an opinionated app host that defines services and dependencies in C#, wires up telemetry and service discovery, and shows a dashboard. Why it matters: it makes local multi-service development reproducible. Naming and packaging have changed across versions (verify).
- One setting to remember: <PublishAot>true</PublishAot> in the csproj, then dotnet publish -c Release.

6 Real-world use case

- Situation: a Kolkata team runs a Container Apps API where cold start and memory use drive cost. The service uses heavy reflection for JSON and mapping.
- Choice: move JSON to System.Text.Json source generation, replace the reflection-based mapper with generated mapping, add an analyzer rule banning new reflection calls, and publish with Native AOT.
- Result: much faster startup and a smaller image, which helps scale-to-zero and KEDA scaling.
- Trade-off: some NuGet libraries are not AOT-compatible, debugging is harder, and build time grows. Generated code is harder to read.
- When NOT to use it: a long-running monolith on a large App Service plan where startup time does not matter, or an app that depends on dynamic plug-in loading, heavy reflection libraries or runtime code generation. Also avoid writing your own source generator when a library already provides one.

11 Revision summary

- Source generators emit C# at build time and replace runtime reflection.
- Analyzers enforce rules in the editor and in CI, configured through .editorconfig.
- Reflection is flexible but slow, and it is hostile to trimming and AOT.
- Expression trees are code as data; EF Core uses them to build SQL.
- Native AOT gives fast startup and low memory, but it restricts reflection and dynamic code.
- P/Invoke calls native code; prefer LibraryImport and treat it as unsafe and platform-specific.
- Aspire composes and observes distributed apps; its names and versions change often (verify).
