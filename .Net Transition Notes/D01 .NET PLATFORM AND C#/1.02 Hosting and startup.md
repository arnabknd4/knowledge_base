1.02 Hosting and startup [P1 R L]. FULL note, new-topic depth, with mini lab.

1 What is it
- Hosting is how an ASP.NET Core app starts, wires itself up and runs as a process. Startup is the code in Program.cs that builds the app and runs it.
- The host is the object that owns the app's lifetime: configuration, logging, dependency injection (DI, the built-in object supplier) and background services.
- Kestrel is the built-in cross-platform web server. It listens on a port and passes HTTP requests to your pipeline.
- Legacy equivalent: Global.asax plus Web.config plus IIS hosting System.Web in-process. In .NET Framework, IIS owned the process. In modern .NET, your app owns the process and IIS is optional.

2 Why needed
- The app must start the same way on a laptop, in a container and on Linux. IIS-only hosting cannot do that.
- Without a clear host model, you cannot control startup order, shutdown behaviour or which server faces the internet.
- Wrong proxy or port settings give wrong client IPs, broken HTTPS redirects and dropped requests during deployments.

4 Features and core concepts
- Program.cs: the single entry file. It builds the app, adds services, sets up the pipeline, then calls Run. It replaces Global.asax and Startup.cs. It matters because all startup logic is now in one readable place.
- WebApplicationBuilder: the object from WebApplication.CreateBuilder(args). It holds configuration, logging and the service collection before the app is built. It matters because you register services here, once, before Build.
- Generic host: the underlying host (IHost) that runs any long-lived app, web or not. Web apps and worker services share it. It matters because the same lifetime, logging and DI model works for APIs and background workers.
- Kestrel: the managed HTTP server inside your process. It is fast and runs on Windows, Linux and macOS. It matters because it removes the need for IIS to run the app.
- Reverse proxy (IIS, Nginx, YARP): a server in front of Kestrel that receives public traffic and forwards it. IIS and Nginx handle TLS, buffering and process restarts. YARP (Yet Another Reverse Proxy) is a .NET library for building a proxy or gateway. It matters because Kestrel is usually not exposed directly to the internet in production, and YARP is the tool for strangler-style migration (see 1.12).
- Environments: a named mode such as Development, Staging or Production, read from ASPNETCORE_ENVIRONMENT (or DOTNET_ENVIRONMENT for non-web hosts). It matters because it switches settings and behaviour, such as detailed error pages only in Development.
- launchSettings.json: a local-only file holding run profiles (ports, environment variables). It is not used in deployment. It matters because people wrongly expect these values to exist in production.
- Forwarded headers: X-Forwarded-For, X-Forwarded-Proto and X-Forwarded-Host, which a proxy adds to carry the original client details. The ForwardedHeaders middleware reads them. It matters because without it the app sees the proxy's IP and thinks the request was HTTP.
- Ports and URLs: set by ASPNETCORE_URLS, the --urls argument or Kestrel configuration. Container images in recent .NET listen on port 8080, not 80 (verify). It matters because a wrong port is the top reason a container starts but is unreachable.
- Hosted lifetime and graceful shutdown: on SIGTERM or Ctrl+C the host stops accepting new requests, lets in-flight ones finish, then stops hosted services. The wait is set by HostOptions.ShutdownTimeout (default 30 seconds in recent versions, verify). It matters because Kubernetes and App Service stop apps often, and a short timeout cuts requests off.
- Worth memorizing:
  - var builder = WebApplication.CreateBuilder(args);
  - var app = builder.Build();
  - app.Run();
  - builder.Services.Configure<ForwardedHeadersOptions>(o => o.ForwardedHeaders = ForwardedHeaders.XForwardedFor | ForwardedHeaders.XForwardedProto);

5 Core focus (exam and interview)
- Most asked: why use a reverse proxy in front of Kestrel, and what is the order of builder, services, Build, pipeline, Run.
- In-process vs out-of-process IIS hosting: in-process runs your app inside the IIS worker process (w3wp.exe) and is faster. Out-of-process runs Kestrel as a separate process behind IIS.
- Environment variable precedence beats appsettings values, and the default environment is Production if none is set.
- Services must be registered before Build. Middleware is added after Build.
- Azure App Service for Linux and Container Apps act as the reverse proxy for you. Forwarded headers are still your concern.
- Exact defaults for ports and shutdown timeout change across versions (verify).

6 Real-world use case
- Situation: an IIS-hosted MVC 5 monolith moves to .NET on Azure App Service for Linux, with a YARP gateway in front of old and new parts.
- Choice: Program.cs with WebApplicationBuilder, Kestrel behind the platform's proxy, forwarded headers enabled, a health endpoint, and a 30 to 60 second shutdown timeout for long requests.
- Trade-off: you gain portability and containers, but you now own startup code, proxy settings and shutdown behaviour that IIS used to hide.
- When NOT to use it: do not expose Kestrel directly to the internet when you need TLS offload, WAF or request filtering. Do not add YARP if one app and one platform proxy already do the job.

7 Interview lens
- Q: Why put a reverse proxy in front of Kestrel?
  A: It handles TLS, load balancing, request filtering and process restarts. Kestrel stays simple and can sit on a private port.
- Q: Why does request.IsHttps return false behind a proxy?
  A: The proxy talks HTTP to Kestrel. Enable the forwarded headers middleware so it reads X-Forwarded-Proto.
- Q: What is the generic host?
  A: The IHost base that owns DI, configuration, logging and hosted services. Web apps are a generic host with a web server added.
- Q: What happens on SIGTERM?
  A: The host stops accepting requests, drains in-flight ones, stops hosted services, then exits. It force-stops after the shutdown timeout.

8 Common mistakes
- Relying on launchSettings.json in production. The app starts on the wrong port. Fix: set ASPNETCORE_URLS or Kestrel config in the environment.
- Skipping forwarded headers. Logs show the proxy IP and HTTPS redirect loops appear. Fix: configure the middleware and trust only known proxies.
- Trusting all proxies blindly. Clients can spoof X-Forwarded-For. Fix: set KnownProxies or KnownNetworks.
- Forgetting the environment variable. The app runs as Production on a dev box or the reverse. Fix: set the value explicitly in every deployment.
- Short shutdown timeout. Requests drop on every deployment. Fix: raise HostOptions.ShutdownTimeout and handle cancellation tokens.
- Container port mismatch. Container runs but the service gets no traffic. Fix: align the app's port, EXPOSE and the platform's target port.

9 Mental model
Internet -> [Reverse proxy: IIS / Nginx / Front Door / YARP] -> [Kestrel inside your process] -> middleware pipeline -> your endpoints
The host wraps everything: it starts services, then on stop it drains requests and shuts down in order.

10 Mini lab (30 minutes)
- Run: dotnet new web -n HostLab, then cd HostLab.
- Open Program.cs. Add this line before app.Run(): app.MapGet("/info", (HttpContext c) => $"{app.Environment.EnvironmentName} {c.Request.Scheme} {c.Connection.RemoteIpAddress}");
- Run dotnet run. Browse to the printed URL plus /info. Expected: Development http ::1.
- Stop it. Set the environment: on PowerShell $env:ASPNETCORE_ENVIRONMENT="Production"; on bash export ASPNETCORE_ENVIRONMENT=Production. Run again. Expected: Production.
- Change the port: dotnet run --urls http://localhost:5055. Expected: the app answers on 5055.
- Add a timeout line: builder.Services.Configure<HostOptions>(o => o.ShutdownTimeout = TimeSpan.FromSeconds(10)); then run and press Ctrl+C. Expected: a graceful stop message.
- Optional: test forwarded headers with curl -H "X-Forwarded-Proto: https" and app.UseForwardedHeaders() added first in the pipeline. Expected: Scheme shows https.
- Clean-up: stop the app, delete the HostLab folder, reset the environment variable.

11 Revision summary
- Program.cs with WebApplicationBuilder replaces Global.asax and Startup.cs.
- Register services before Build, add middleware after Build, then Run.
- Kestrel is the built-in server. Production usually puts a reverse proxy in front.
- YARP is a .NET reverse proxy library, used for gateways and strangler migration.
- ASPNETCORE_ENVIRONMENT sets the environment. Default is Production.
- launchSettings.json is local only. Use environment variables elsewhere.
- Forwarded headers fix client IP and scheme behind a proxy. Trust only known proxies.
- Graceful shutdown drains in-flight requests within the shutdown timeout.
