1 What is it
Advanced security covers how an organisation defends itself at scale. It brings together a trust model (zero trust), tools that collect and react to security events (SIEM, SOAR), people who test defences (penetration testers, red and blue teams), and tuning of the web firewall (WAF).
Legacy equivalent: a firewall at the office edge, a yearly audit and a pile of IIS logs nobody reads.

4 Features and core concepts
- Zero trust architecture: never trust a request because of where it comes from. Verify identity, device and context every time, give least privilege, and assume a breach has already happened. Why it matters: the office network perimeter no longer exists with cloud and remote work. On Azure this maps to Entra Conditional Access, private endpoints and managed identities.
- SIEM (security information and event management): a central system that collects logs from many sources and raises alerts by correlating them. Why it matters: one failed login means nothing, but a failed login plus a new country plus a privilege change does. Microsoft Sentinel is the Azure example.
- SOAR (security orchestration, automation and response): automated playbooks that react to alerts, such as disabling an account or isolating a VM. Why it matters: it cuts response time and removes manual toil.
- Penetration testing process: an authorised, simulated attack. Steps: agree scope and rules, gather information, find weaknesses, exploit them safely, report, then retest after fixes. Why it matters: it finds what scanners miss and proves real risk.
- Red and blue teams: the red team attacks like a real adversary. The blue team detects and responds. Why it matters: it tests people and detection, not just software. A joint exercise is often called purple teaming.
- WAF tuning: a WAF (web application firewall) filters HTTP traffic against rules. Tuning means starting in detection mode, finding false positives, adding exclusions, then switching to prevention mode. Why it matters: an untuned WAF either blocks real users or protects nothing. Azure options: Application Gateway WAF, Front Door WAF.

6 Real-world use case
Situation: a .NET API behind Application Gateway serves a customer portal, and logs are scattered across services.
Choice: enable WAF in detection mode and review false positives for two weeks, then switch to prevention. Send WAF, Entra and Activity logs to Sentinel. Add one SOAR playbook that notifies the team and blocks a repeat-offender IP. Commission a yearly pen test.
Trade-off: more alerts, more tuning effort and higher log ingestion cost.
When not to use it: a small internal app with little data does not need a full SIEM, SOAR and red team. Baseline controls (MFA, patching, least privilege) come first.

11 Revision summary
- Zero trust: verify explicitly, least privilege, assume breach.
- SIEM collects and correlates logs. SOAR automates the response.
- Pen test order: scope, recon, find, exploit, report, retest.
- Red team attacks. Blue team defends. Purple team shares findings.
- WAF tuning: detection mode first, fix false positives, then prevention.
- Azure names (verify): Sentinel, Application Gateway WAF, Front Door WAF, Conditional Access.
